# 05: 必填引导：门禁 +「说不清在哪儿」出口 + 常见主诉快捷入口

**What to build:** 新会话的首条输入之前必须先声明部位（输入框是明确的等待态）；「说不清在哪儿 · 直接描述」出口让指不出位置的人照常问诊；五个常见主诉快捷词点一下直接带患者去图上对应区域。

必填的是**这一步动作**，不是"必须点中某个区域"——发烧、乏力、浑身没劲、头晕这类主诉根本指不出位置，没有那个出口这批人会被挡死。

## ⚠️ 遗留偏差：门禁判据的前端半边仍是近似

spec 要求「判据与后端『新主诉判定』同口径，**以服务端状态为准**」。当前 `partStage` 的翻转依据是
**done 事件的 `hasResult`**（服务端下发，这部分达标），但**声明随请求携带的判据**仍在前端用
`!sessionId` 近似"首轮"（`sse.js`）。反例：已出结论的旧会话续聊时，后端会开新会话并**保留**声明
（isFirstTurn 对新会话为真），前端却因 sessionId 存在而不带 `parts` ⇒ 声明静默丢失。
后果有限（那句话里本身含部位词，门槛照样过、prompt 只是少一节），但**方向上与"以后端状态为准"相悖**。
正解是把"这是不是首轮"变成服务端事实：`session` 事件带回会话状态（或 done 事件带回 `nextIsNewTurn`），
前端只消费不推断。**建 A-05 之后的任何门禁强化前，先修这条。**
