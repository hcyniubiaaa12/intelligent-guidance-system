# 提交拆分（对应 `issues/01–06`）

实际落地时按**工单**拆分提交（每张工单一个 worktree / 分支，各自 2–4 个提交，再由集成分支 merge），
而不是最初设想的「01+03+04+05 合成一个 feat 提交」——分张提交让每片的领域层、编排层、前端各自可读可回退。

| 提交 | 工单 | 说明 |
|---|---|---|
| `feat(kb): 术语白名单新增——物理判重、复活与即时刷新` + `feat(admin): 新增术语端点与编排映射` + `feat(admin): 术语白名单页新增入口与弹窗` | 01 | 加词：数据访问 → 错误码 → 领域规则 → 编排与端点 → 页面 |
| `fix(admin): 移除永不生效的追问升级阈值配置` | 02 | 独立提交，无代码依赖 |
| `feat(kb): 术语编辑——另一行判重与来源/启停保持不变` + `feat(admin): 术语编辑端点` + `feat(admin): 术语列表行内编辑复用新增弹窗` | 03 | 改词 |
| `feat(kb): 术语删除——逻辑删除并立即失效` + `feat(admin): 术语列表支持删除` + `test(kb): 删除后同词新增走复活分支` | 04 | 删词 |
| `refactor(kb): 删除术语白名单种子——人工维护入口已成唯一来源` | 05 | 退出种子 |
| `docs: 同步术语维护与参数口径` | 06 | 文档与进度；验证记录写施工日志 |
