# 01: 入库即抽取——术语自动进入白名单候选与 ES

**What to build:**

上传一份文档，系统在切分完成后自动让模型从切片里抽出部位 / 症状术语，**当场落两处**：ES 的 `medical_terms`（参与关键词通道检索）与 MySQL `medical_term`（管理端可见的白名单候选）。管理端刷新术语列表就能看到 `来源 = 模型抽取`、`状态 = 未生效` 的行。抽取失败时文档照常完成、切片照常可检索，页面上只在日志里留一条 WARN。

这一片贯穿全链路，是整条功能唯一能端到端演示的部分：提示词配置 → LLM 调用 → 词面校验 → 白名单合并 → 接进切分入库流水线 → ES 写入侧过滤 → 进度文案。

**已定的规则：**

1. **提示词进 `prompts.yml`**（`prompts.term-extract.*`），由 `common` 的 `PromptProperties` 承载。这与既有 `prompts.split.*` 同构——`kb` 已在读它，不新增依赖边。
2. **抽取器放 `kb`**，不放 `llm`：`llm` 只留"唯一外部出口"的模型客户端，领域提示词与输出协议属于 `kb`。走 `ChatModel.chat()`（一次性返回），不新增客户端接口。
3. **输出协议**：JSON 数组 `[{ "term": "...", "type": "part" | "symptom" }]`。**非法 `type` 降级为 `symptom`、不丢弃该词**——类型错了人可以在管理端改，丢了真实的词更亏。
4. **词面校验与 `MedicalTermService.validateTerm` 同源**：`trim` 后 2–20 字、拒绝内部空白与换行、**拒绝单字**。单字必须挡在入口——信息充足性门槛用子串匹配，一个「头」进来会让几乎全部主诉都被判"含医学术语"。**不要在下游另写一套校验**。
5. **批量 20 片一批**（与入库批次对齐）；**单批失败继续下一批**；**连续失败 3 批熔断**、中止本文档剩余批次。3 是经验阈值，**注释里写清来由**（连续三次同一路径失败几乎可断定不是网络抖动，继续只会白烧调用）。日志带 `docId` + 批序号 + 原因。
6. **抽取异常绝不上抛**：返回值、`ingest_task` 状态、`kb_doc.status` 都不受影响。
7. **执行位置**：切分完成之后、第一批 `indexChunks` 之前。ES **一次写入即带 terms**，不走"先写空再更新"的二次写路径。抽取耗时计入 `split` 阶段。
8. **`mergeExtracted` 与人工新增刻意不同**（新增独立方法，不复用 `add`——`add` 的复活语义是人工路径的契约）：

   | 表内状态 | 处理 |
   |---|---|
   | 活跃行 | **跳过，不动 `enabled`**（人手动停用的词不因又被抽到就复活） |
   | 已删除行 | **跳过，不复活**（"删除"是人的决定） |
   | 不存在 | 插入，`source=llm_extract`，`enabled` 由 `term.manual.review` 决定 |

   判存在按**物理行**判（逻辑删除的行仍占着 `uk_mt_term_type`）；跨批去重后**整份文档只写一次** MySQL；写库后立即 `refresh()`；返回「插入 / 跳过活跃 / 跳过已删除」三个计数供日志。
9. **单字术语在写 ES 时统一过滤**（只此一处实现，种子语料与上传文档自动一致）；**不改 `SeedCorpus`**——语料里的词是给 ES 用的，过滤是写入侧的职责。
10. **回流合成 chunk 不走抽取**：只有一片、文本由管理员定稿，术语在预览时由人决定。注释里写明，别让后来者以为是漏了。
11. **不新建线程池**（抽取就在 async 流水线线程里顺序执行）；**不新增 `ingest_task` 阶段或字段**（旁路进状态机会产生"抽取失败要不要改阶段"的无解问题）。
12. **进度文案**：`split` 阶段由「正在切分」改为「**正在切分与提取术语**」，仍无百分比。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

**验收**

- [ ] 上传新文档 → 页面显示「正在切分与提取术语」，离开页面再回来进度不丢
- [ ] 日志出现批次数 / 抽取词数 / 落库条数 / 跳过原因
- [ ] 管理端术语列表出现 `来源=模型抽取`、`未生效` 的行
- [ ] 抽取失败不阻塞入库：把模型 Key 改错后上传，文档仍完成、切片可检索、只有 WARN
- [ ] ES 文档里 `medical_terms` 不含单字；种子语料的多字词仍在
- [ ] 抽取撞上活跃词（含 `enabled=0` 的）→ `enabled` 保持原值；撞上已删除词 → `deleted` 仍为 1
- [ ] 单测：抽取器（正常 / 非法类型 / 单字 / 非 JSON / 调用异常）、`mergeExtracted` 三态、`splitAndIndex` 在抽取抛异常时正常返回、连续 3 批失败后不再调用、`IngestPipeline` 抽取失败仍 `success`、`SeedDataRunner` 不触发抽取
