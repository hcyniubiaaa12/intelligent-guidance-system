**七条真实验收（逐条）**

1. **进度文案 + 切页保持** ✅ 真跑（UI 自动化：Edge + playwright-core）。上传 → 出现「正在切分与提取术语」→ 切到「术语白名单」1.2s 再回「文档入库」，文案仍在。任务状态由 `ingest_task` 提供，页面切换不影响轮询。
2. **抽取日志** ✅ 真跑。`术语抽取完成：docId=… 已尝试 1 批 失败批次=0 抽到词条 15（跨批去重后）`；`抽取术语合并：插入 7 / 跳过活跃 5 / 跳过已删除 3`——三态在真实库上同时出现。
3. **管理端候选与计数** ✅ 真跑。`source=llm_extract&enabled=false` 返回 7 条（耳部 / 听力下降 / 打喷嚏 / 流涕 / 扁桃体肿大 / 扁桃体 / 吞咽不适）；页面「待确认 N」用同一查询取 total，口径一致。
4. **一键启用 → 患者端生效** ✅ 真跑。批量启用 7 条（返回实际 7）→ 待确认 0；患者端发「流涕」（2 字、含已启用术语）**未命中规则门槛**、直接检索（模型给针对性追问，非模板）；另开新会话发「不舒服」→ 日志 `规则门槛：首条主诉过于笼统（未命中术语且过短）`、模板追问、未调模型/未检索。
5. **断 Key 可复现失败** ✅ 真跑。用命令行 `--llm.deepseek.api-key=sk-invalid-…` 覆盖（**不改 `application-local.yml`**，恢复即重启）→ 上传 → 日志只有 `WARN 单批失败 … HTTP 401`，无 ERROR；文档 `done`、7 片入库、ES 可检索（`medical_terms=[]`）。恢复后再次真实上传，抽取成功（13 词 / 插入 8）。
6. **加分对比（加 / 不加 should）** ✅ 真跑（重建后 14 片小语料，直接对 ES 发同一条查询的两种 bool 形状）：
   - 流涕 3.9225 → 4.6774（+19%）；耳鸣 3.6043 → 4.3592（+21%）；反酸 3.9225 → 4.5633（+16%）；咽痛 6.6676 → 8.1774（+23%）

7. **索引重建后检索正常、标题片仍排除** ✅ 真跑。删 `guide_chunk` → 重启 → `ES 索引已创建`，mapping 为 `text` + `ik_max_word/ik_smart` + `.keyword`；`match(medical_terms, 反酸)` 命中 7 条（重建前 keyword 为 0）；按检索形状查询返回 1 条 `text` 片、无 title 片。

**审查发现与修复**（mattpocock code-review，main..feat/term-extraction，双轴）

- **Standards 轴**：主要发现即本票要做的文档同步（已全部改完）。代码两条：`validateTerm` 与 `normalizeTerm` 同规则两处 → 改为 `validateTerm` 调用 `normalizeTerm`、只保留文案分支；`TermType` javadoc 声称"解析只此一处"被 `TermSource` 证伪 → 改为如实说明两者空值语义不同、同一枚举内只许一份。其余 smell 判定可接受（有明确读者或 spec 定形）。
- **Spec 轴**：保真度高，无 scope creep、无方向性错误。缺一条测试缝：spec 明列 `IngestPipelineTest`「抽取失败任务仍 success」→ 补两例（吞掉后 success / 真抛异常则 failed）。另修 `TermExtractor` 日志「批次数」→「已尝试 N 批」（熔断后数的是尝试批次）。三条「看着不对」判定不修：`mergeExtracted` 枚举/`getCode()` 不一致（`main` 既有模式）、`applyTerms` 透传 `type`（不可达）、`batchNo` 语义（已改措辞）。
