# 健康档案与长期记忆（spec）

Status: resolved

---

## Problem Statement

**健康档案现在同时扮演三个角色，但它三个都演不好。**

1. **它是检索原料**：档案另开「向量 + 关键词」两路召回。但精排 query 仍是主诉串，档案没有排序话语权；落地时的记录已经写明「当前种子语料下演示不出效果差异」。它既证明不了收益，又让本该权威的过敏/手术信息去参与语义相似度竞争——真正危险的档案项（青霉素过敏、近期手术）和普通切片一样排在一堆候选里，没有任何特殊地位。
2. **它是生成背景**：档案整段塞进 prompt，但**没有时间语义**——「近期手术」是一个没有日期的标签，一年后仍然写着「近期」。慢病、长期用药、过敏混在同一张表里，颗粒度粗到无法判断「现在是否还在用/还算不算近期」。
3. **它承担了「记住患者」的职责，但只对填过表单的人生效**：患者说过「我希望你讲慢一点」「我有糖尿病」，下一次会话系统完全不记得。偏好与稳定背景没有任何跨会话载体。

同时缺一个控制面：患者看不到系统到底记住了什么、从哪里记的、怎么删。医疗场景下，「记错了还一直用」比「没记住」更危险。

---

## Solution

**把「患者是谁」拆成两层：档案是患者手写并确认的权威事实，长期记忆是系统自动积累的笔记。**

- **健康档案（安全关键）**：只保留性别、出生年、过敏史、近期用药、近期手术。**退出检索层**，只注入生成提示词；是**硬警报**的唯一来源。即使用户关闭自动记忆，档案仍照常注入。
- **长期记忆（跨会话）**：记录两类东西——**偏好**（希望怎么被回答）与**稳定背景**（慢病、长期健康状况）。由模型从对话中抽取，**不需要确认**，但每条都带患者原话出处，患者可查看、编辑、删除。
- **档案候选（二手信息）**：抽取出的、能落进档案字段的健康事实（过敏/用药/手术）不直接进档案，也不进背景记忆，而是进入「待确认」。**用户接受后才写档案，拒绝后不再重复提议，30 天未处理自动失效。**
- **注入策略**：偏好全量注入；稳定背景按需注入——用 pgvector 按当前 query 向量召回 top-3，未命中即不出现。记忆总量再小也不全量塞，避免 token 膨胀。
- **预警**：档案项与召回内容冲突 → 硬警报；稳定背景与当前话题相关 → 相关提醒（不报「禁忌」）。
- **控制面**：侧栏「健康档案」页内分三段——「您填写的」「我记住的」「待确认」；顶部一个「自动记忆」开关。关闭后停止抽取、停止注入偏好与背景，**档案保留并继续注入**。

## User Stories

### 健康档案：只留真正需要确认的东西

1. 作为患者，我想在健康档案里只填过敏史、近期用药、近期手术，这样我不用面对一张不知道填什么的表单。
2. 作为患者，我想在注册时选填性别与出生年，这样系统不必在档案里再问我一次。
3. 作为患者，我想给用药填开始/结束时间，这样系统知道我现在是否还在吃。
4. 作为患者，我想给手术填发生时间，这样系统知道它是「近期」还是「既往」。
5. 作为患者，我想让超过 12 个月的手术自动不再算「近期手术」，这样档案不会一直撒谎。
6. 作为患者，我想在档案里看到性别与出生年，这样我能确认系统对我的基本判断。
7. 作为老用户，我想在没有出生年时继续看到旧的年龄段，这样我的档案不会因为改版变成空白。
8. 作为患者，我想让档案项在回答里被说出来（相关时），这样我知道系统参考了我的情况。
9. 作为患者，我想让档案项永不参与科室排序，这样它不会因为一句慢病就把我推到某个科。
10. 作为患者，我想在档案与召回内容冲突时看到醒目提示，这样我不会忽略过敏/手术这类风险。
11. 作为患者，我想关闭自动记忆后档案仍然生效，这样我关掉的只是「自动记笔记」，不是我的健康信息。

### 长期记忆：偏好与稳定背景

12. 作为患者，我想说「我希望你讲慢一点、温柔一点」后，下一次会话系统仍然这样回答，这样我不必每次重复。
13. 作为患者，我想说「我有糖尿病」后，系统在相关话题里记得这件事，这样它不会把我当成没有基础病的人。
14. 作为患者，我想让偏好影响表达方式但不改变医学结论，这样「温柔」不会变成「不告诉我风险」。
15. 作为患者，我想让稳定背景只在相关话题出现，这样 prompt 不会被无关的旧事塞满。
16. 作为患者，我想在记忆页看到系统记住了什么、是从我哪句话记的，这样我能判断它有没有记错。
17. 作为患者，我想编辑一条记忆，这样记错时我能改而不是只能删。
18. 作为患者，我想删除一条记忆，这样它以后不再影响回答。
19. 作为患者，我想一键清空所有长期记忆，这样我能重新开始。
20. 作为患者，我想关闭自动记忆，这样系统不再从我的对话里抽新东西。
21. 作为患者，我想在关闭自动记忆后仍然看到旧记忆但不再被注入，这样我知道它们还在、只是不生效。
22. 作为患者，我想让偏好最多 5 条、稳定背景最多 10 条，这样系统不会无限堆东西。
23. 作为患者，我想在偏好满了时由系统合并去重，这样我不用自己整理。
24. 作为患者，我想在稳定背景满了时收到「需要整理」的提示，这样我知道该删哪条。
25. 作为患者，我想让过期的背景（比如已结束的长期用药）不再注入，这样旧信息不会一直生效。

### 档案候选：二手信息要过用户这一关

26. 作为患者，我想在我说「我青霉素过敏」后看到一条待确认的档案候选，这样我能决定要不要写进正式档案。
27. 作为患者，我想在确认前先修改候选的值，这样系统听错字时我能纠正。
28. 作为患者，我想拒绝一条候选后它不再反复出现，这样系统不会一直念叨。
29. 作为患者，我想让候选 30 天未处理自动失效，这样待确认区不会越积越多。
30. 作为患者，我想让候选与已有档案冲突时被标出来，这样我能看到「你说不过敏，但档案里写着过敏」。
31. 作为患者，我想让未确认的候选**永远不出现在回答里**，这样系统不会拿一条我听错的话去给建议。
32. 作为患者，我想让候选只在我接受后才写进档案，这样档案始终是我确认过的事实。

### 预警

33. 作为患者，我想在知识片段提到我过敏的药时看到硬警报，这样我知道这条建议与我的档案冲突。
34. 作为患者，我想在话题涉及我的慢病时看到一句「与您提到的糖尿病相关」，这样我知道系统考虑了我的背景。
35. 作为患者，我想让背景提醒只说「相关」不说「禁忌」，这样系统不会把一句背景当成医学结论。
36. 作为患者，我想让警报最多 3 条、按重要性排序，这样结论卡不会被警告淹没。
37. 作为患者，我想在非结论轮次（追问/资料回答）只听模型口头说明，不弹出结构化警报，这样对话不被反复打断。
38. 作为患者，我想让当前主诉优先于任何长期记忆，这样「我今天胸痛」不会被「他有长期心脏病」轻描淡写。

### 游客、开关与数据

39. 作为游客，我不想有健康档案与长期记忆，这样系统不会在没有账号的情况下保存我的医疗信息。
40. 作为游客，我想在侧栏看到「登录后…」而不是一个空档案入口，这样我知道这是登录后才能用的功能。
41. 作为患者，我想在关闭自动记忆后不再产生新记忆，这样我的对话不会被继续分析。
42. 作为患者，我想在关闭自动记忆后旧记忆仍留在库里，这样我重新打开时它们还在。
43. 作为老用户，我想让旧的慢病标签迁移成稳定背景记忆，这样我填过的信息不会丢。
44. 作为老用户，我想让旧的用药/过敏标签继续留在档案里，这样我不用重新填一遍。
45. 作为患者，我想让历史就诊记录里的档案快照保持原样，这样改档案不会改写过去。

### 系统与运维

46. 作为系统维护者，我想让记忆抽取异步执行、不占用在线导诊线程，这样抽取慢或失败都不影响患者当前这轮回答。
47. 作为系统维护者，我想让抽取失败只记日志、不重试、不阻塞对话，这样模型抖动不会变成用户可见的错误。
48. 作为系统维护者，我想让每会话最多抽取 3 次，这样成本可控。
49. 作为系统维护者，我想让 pgvector 写失败可补偿，这样 MySQL 与向量库不会长期不一致。
50. 作为系统维护者，我想让记忆模块与召回层解耦，这样 rag 仍然不感知用户与会话。
51. 作为答辩演示者，我想能现场演示「说一句偏好 → 下一次会话生效」「说一句慢病 → 相关话题被提到」「说一句过敏 → 待确认 → 接受后进档案」，这样这个功能是可讲清楚的。

## Implementation Decisions

### 1. 概念模型：一层档案、一层记忆、一层候选

| 内容 | 存储 | 写入方 | 确认 | 注入 | 预警 |
|---|---|---|---|---|---|
| 档案 | `user_health_profile` | 用户手填；候选经确认后写入 | 用户确认 | 始终注入 | 硬警报 |
| 偏好 | `user_memory` | 模型抽取 | 免确认，可删 | 始终注入 | 不触发 |
| 稳定背景 | `user_memory` | 模型抽取 | 免确认，可删 | 按需召回 | 相关提醒 |
| 档案候选 | `profile_candidate` | 模型抽取 | 逐条接受/拒绝 | 确认前不注入 | 不触发 |

**同一事实只存一处**：能落进档案字段的健康事实（过敏/近期用药/近期手术）只走候选，不进背景记忆。

### 2. 档案字段与时间语义

- 档案只保留：`gender`、`birth_year`、过敏、近期用药、近期手术。
- `age_range`、`history_tags`、`history_other` 保留列但不再展示、不再注入；`history_*` 在迁移后只作回滚依据。
- 用药与手术从字符串数组升为对象数组，带 `startedOn` / `endedOn` / `occurredOn`，精确到月。
- 手术超过 12 个月在组装时标为「既往」，不再算「近期手术」；用药 `endedOn` 非空表示已停。
- 性别、出生年在注册页采集，选填；老 `age_range` 在出生年缺失时作为只读兜底显示。
- **档案不参与任何检索**：删除档案召回串与两路档案召回；档案只出现在生成 prompt 与快照中。

### 3. 表结构（新增/变更）

```sql
ALTER TABLE user_health_profile
  ADD COLUMN birth_year SMALLINT NULL,
  ADD COLUMN surgery_tags JSON NULL,
  ADD COLUMN surgery_other VARCHAR(512) NULL;

ALTER TABLE user ADD COLUMN memory_enabled TINYINT NOT NULL DEFAULT 1;

CREATE TABLE user_memory (
  id VARCHAR(32) PRIMARY KEY,
  user_id VARCHAR(32) NOT NULL,
  type VARCHAR(32) NOT NULL,            -- preference / background_health / background_other
  mkey VARCHAR(32) NOT NULL,            -- ≤8 字
  mvalue VARCHAR(128) NOT NULL,         -- ≤60 字
  retrieval_text VARCHAR(256),          -- 供 embedding 的扩展文本，不注入
  source_quote VARCHAR(512),            -- 患者原话
  confidence DECIMAL(4,3),
  observed_at DATETIME NOT NULL,
  valid_from DATE,
  valid_to DATE,
  status VARCHAR(32) NOT NULL DEFAULT 'active',
  deleted TINYINT NOT NULL DEFAULT 0,
  created_at DATETIME NOT NULL,
  updated_at DATETIME NOT NULL,
  KEY idx_um_user_type (user_id, type, status)
);

CREATE TABLE user_memory_vec (
  memory_id VARCHAR(32) PRIMARY KEY,
  user_id VARCHAR(32) NOT NULL,
  type VARCHAR(32) NOT NULL,
  embedding vector(1024) NOT NULL,
  updated_at DATETIME NOT NULL,
  KEY idx_umv_user_type (user_id, type)
);

CREATE TABLE user_memory_log (
  id VARCHAR(32) PRIMARY KEY,
  memory_id VARCHAR(32) NOT NULL,
  user_id VARCHAR(32) NOT NULL,
  op VARCHAR(32) NOT NULL,              -- add/update/delete/merge/promote
  old_value VARCHAR(512),
  new_value VARCHAR(512),
  actor VARCHAR(32) NOT NULL,           -- extract/user/migration
  created_at DATETIME NOT NULL,
  KEY idx_uml_memory (memory_id),
  KEY idx_uml_user (user_id)
);

CREATE TABLE profile_candidate (
  id VARCHAR(32) PRIMARY KEY,
  user_id VARCHAR(32) NOT NULL,
  field VARCHAR(32) NOT NULL,           -- allergy/medication/surgery
  value VARCHAR(128) NOT NULL,
  occurred_on VARCHAR(7),               -- YYYY-MM
  source_quote VARCHAR(512),
  confidence DECIMAL(4,3),
  status VARCHAR(32) NOT NULL DEFAULT 'pending',
  deleted TINYINT NOT NULL DEFAULT 0,
  created_at DATETIME NOT NULL,
  updated_at DATETIME NOT NULL,
  KEY idx_pc_user_status (user_id, status)
);
```

- `user_memory_vec` 不建 HNSW：每用户 ≤10 行，按 `(user_id, type)` 过滤后顺序扫描足够。
- 只有 `background_*` 写向量；偏好不向量化。
- `health_tag` 新增 `surgery` 类型；枚举 `HealthTagType` 追加 `SURGERY("surgery","手术史")`。

### 4. 抽取管线

- **触发**：规则预筛（「我 / 喜欢 / 希望 / 有 / 做过 / 吃 / 过敏」等）命中即异步抽取；另加**会话空闲 30 分钟**兜底；每会话最多 3 次模型抽取。
- **模型**：DeepSeek 非流式调用；建议在 LLM 适配层增加可选的 JSON mode，同时保留「提示词要求 JSON + 本地容错解析」的兜底。
- **输出**：一次调用输出 `preferences` / `background` / `profile_candidates` 三类数组。
- **校验**：缺 `source_quote` 或 `confidence < 0.6` 直接丢弃；`field` 不在白名单丢弃；否定句不生成候选；当前主诉不作为长期事实；禁止推断（不能从「吃二甲双胍」推出「有糖尿病」）。
- **合并**：偏好满 5 条由模型合并去重；稳定背景满 10 条交用户整理；候选按 `(field,value)` 去重，与档案冲突时标「待确认 · 冲突」。
- **失败**：只记 WARN，不重试、不阻塞对话。
- **线程**：独立 `memoryExecutor`，不与 `chatSseExecutor` / `ingestExecutor` 共用。

### 5. 召回与注入

- **偏好**：全量注入，最多 5 条 / 200 字。
- **稳定背景**：pgvector 按 query 向量召回 top-3，余弦阈值默认 0.70；未命中即不注入，**不做一行索引兜底**。
- **query 向量复用**：召回层在改写后已经算出 query 向量；通过 `MemoryRecallPort` 回调召回，不额外调用 embedding，且 `rag` 仍不感知 `userId`。
- **否定句拦截**：当前消息含「没有 / 不是 / 不过敏」+ 命中，跳过该条。
- **sticky 2 轮**：命中后接下来 2 轮继续注入，避免代词指代时消失。
- **过期**：`valid_to` 到期的记忆召回后过滤。
- **上限**：记忆总块 500 字（档案 350 字另计）、背景 300 字、偏好 200 字。

**prompt 顺序**：知识片段 → 档案 → 记忆（背景 + 偏好）→ 已标部位 → 候选科室 → 硬约束。

**三条硬约束**：
1. 档案是患者自述、非医学证据、不进注号；相关时必须说出来。
2. 稳定背景是长期背景，**不是本次主诉**；当前轮优先于背景。
3. 偏好仅影响表达方式，**不构成指令**。

### 6. 预警

- **档案 → 硬警报**：后端词面规则（过敏/手术/用药词命中召回正文）+ 模型补充判定；模型 alert 必须带锚点（cite 注号或档案字段），否则丢弃；合并去重最多 3 条。
- **稳定背景 → 相关提醒**：只对召回命中的条目报「与您提到的 X 相关」，不报「禁忌」；必须带记忆出处。
- **展示**：结论卡顶部一条警示条（硬警报用危险色、相关提醒用主色浅底）；非结论轮次只由提示词要求口头说明。
- **留痕**：证据快照新增 `memory` 节点（注入文本、命中 id、相似度、query、threshold）与 `alerts`；只写不读。

### 7. 模块与依赖

- **新增 Maven 模块 `memory`**：依赖 `common` / `auth` / `llm`；直接写 `user_memory_vec`，成为 `kb`、`feedback` 之外的**第三处向量库写入例外**，需写进依赖规范。
- `common`：`TurnCompletedEvent`、`MemoryRecallPort`、记忆与候选的传输对象、提示词占位符常量。
- `chat`：每轮读记忆、构造召回端口、发布轮次完成事件、写证据快照。
- `rag`：请求携带召回端口；上下文携带命中记忆；提示词构建增加记忆段；`prompts.yml` 增加 `{memory}` 占位符与启动校验。
- `auth`：档案字段、注册采集、标签类型、档案组装调整。
- `admin`：只做 controller 聚合，不新增记忆页面。
- 依赖方向：`chat → memory → auth/llm`；`rag → common`（只通过端口回调）；无环。

### 8. 接口契约

```
GET    /api/memory                       记忆 + 候选 + 开关 + 上限
PUT    /api/memory/setting               开关
PUT    /api/memory/{id}                  编辑偏好/背景
DELETE /api/memory/{id}                  删除
POST   /api/memory/candidates/{id}/accept
POST   /api/memory/candidates/{id}/reject
GET    /api/profile                      档案（扩展 birthYear / surgery / 时间字段）
PUT    /api/profile                      整份覆盖写（扩展）
GET    /api/profile/tags                 标签选项（含 surgery）
```

所有接口要求登录；`userId` 只从登录态取，请求体不携带 `userId`。

## Testing Decisions

**什么算好测试**：只测外部可观察的行为——给定输入，断言「读到了什么、注入了什么、写了什么、发了什么事件」，不断言私有方法或 SQL 细节。提示词测试用真实 `prompts.yml`，因为占位符缺失会导致启动失败，那是外部契约。

### 缝一 · 对话轮次边界（扩展现有 `ChatServiceTest`）

最高缝。观察 `handleTurn`：

- 开关开 → 记忆候选随检索请求传入；开关关 → 只传档案，记忆为空；
- 每轮结束发布 `TurnCompletedEvent`，且不阻塞 SSE；
- 证据快照含 `memory` 节点与 `alerts`；
- 抽取/召回失败不影响本轮回复。

### 缝二 · 召回与提示词组装（`RagServiceTest` + 新增 `PromptMemoryBlockTest`）

- 用假 `MemoryRecallPort` 返回命中项，断言 `RagContext` 携带命中记忆；
- 用真实 `prompts.yml` 断言「档案 → 背景 → 偏好」顺序、空记忆整段消失、三条硬约束在场、关闭开关时档案仍在而记忆段不出现。

**先例**：`PromptProfileBlockTest`、`PromptBuilderTest`、`RagServiceTest`。

### 缝三 · 抽取与档案候选（新增 `MemoryExtractorTest`，扩展 `HealthProfileServiceTest`）

- mock 模型返回 JSON，断言原子事实、`source_quote` / 置信度过滤、否定句丢弃、不推断、候选字段映射；
- 候选接受 → 写档案并标 `accepted`；拒绝 → 不写且不再提议；30 天过期；与档案冲突时标记。

**先例**：`TermExtractorTest`（模型返回 JSON + 容错解析）、`HealthProfileServiceTest`（档案写入与校验）。

## Out of Scope

- **L0 就诊摘要**：不做；历史就诊数据已在导诊记录里，未来若要加是纯读派生。
- **管理端记忆内容页**：不做；管理端不看患者记忆，避免隐私面扩大。
- **图记忆、反思摘要、遗忘曲线**：不做。
- **记忆的读时语义检索**：不做；向量只用于背景注入的触发，不参与知识片段排序。
- **游客记忆**：不做。
- **完整的 FHIR 建模**：只借其字段语义，不做资源级建模。
- **药物相互作用检查**：警报只覆盖档案项与召回内容的冲突，不做药理相互作用库。
- **历史证据快照迁移**：不迁移，老结构原样可读。
- **自动重算全部记忆向量**：换 embedding 模型时作为运维任务，不自动化。
- **前端组件测试框架**：不引入。

## Further Notes

**为什么档案必须退出检索**：档案本来就不该决定科室；它作为第四路召回既没有排序话语权，也从未被证明有效。让它回到「生成约束 + 硬警报」的位置，架构上更干净。这是架构偏好，不是修 bug，验收只承诺「没有退步」，不承诺准确率提升。

**为什么稳定背景按需注入而不是全量**：偏好永远相关（怎么说话），背景只在话题相关时才有意义。pgvector 召回解决「同义/近义表述」，但**解决不了「腹痛 vs 糖尿病」这种语义远、临床上相关的情况**——这是本方案已知的限制，靠 `retrieval_text` 扩展和 gold set 校准缓解，不假装解决。

**为什么不做一行索引兜底**：已明确选择严格按需；未命中的背景对本次回答完全不可见。代价是漏召回时模型失明，收益是 prompt 干净、行为可解释。

**两条要防止的未来误改**：

1. **别把档案重新塞回检索层**。档案进检索会重新引入「安全关键信息与普通切片抢排序」的问题，且它本来就没有排序话语权。
2. **别让未确认的候选进 prompt**。候选是二手信息，用户没确认就注入，等于让模型拿一句可能听错的话给医疗建议；确认门是这条链路唯一的安全阀。

**需要同步的基线文档**：`CONTEXT.md`（新增「长期记忆」「稳定背景」「偏好」「档案候选」词条）、`数据库设计.md`、`链路A-导诊对话.md`、`链路C-反馈闭环.md`（证据快照）、`CLAUDE.md`（新增 `memory` 模块与向量写入例外）、`进度.md` 三节。
