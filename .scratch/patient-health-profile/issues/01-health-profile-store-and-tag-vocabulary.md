# 01: 健康档案可填、可存、可读（含慢病标签词表）

**What to build:** 患者在自己的账号下有一份**选填**的健康档案，跨会话、跨设备保存。他可以用下拉框选性别与年龄段，多选既往病史与长期用药，按类别多选过敏史并补填具体药名，还可以在「其他」里用自己的话补充。每一栏都能改、能读回。条数与字数上限在患者打字那一刻就挡住他（并显示还剩多少），后端保存时**再校验一遍**——绝不允许"先存下来再悄悄裁掉"。慢病标签词表落地并预置种子数据，成为患者端选项与后续检索用串共用的一份受控词汇。条数上限与字数上限进受管参数白名单，管理员可调、改完立即生效。

本单据的边界只到"**原料存得下、读得出**"：不改任何检索或生成链路，不实现「档案 → 待注入文本」的组装（那是 02）。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 患者能读到自己那份健康档案（字段：性别、年龄段、既往病史、长期用药、过敏史，以及各自的「其他」自由文本）
- [ ] 患者能整份覆盖写回；改完刷新，读回来的是改后的内容
- [ ] 性别与年龄段是枚举下拉框；年龄段是**区间**（0-3 / 4-6 / 7-14 / 15-44 / 45-59 / ≥60），不是具体岁数
- [ ] 既往病史、长期用药、过敏史都是「多选标签 + 「其他」自由文本」两种填写方式并存
- [ ] 标签类超条数、自由文本超字数时，**前端当场写不进去**并显示剩余额度
- [ ] 后端独立二次校验同样的上限，超限直接拒绝并返回可展示的错误（不信任前端）
- [ ] 未登录访问返回 401；登录用户只能读写自己那一份
- [ ] 慢病标签词表有种子数据（常见慢病 20–30 个起步），支持启用 / 停用，只读侧供患者端选项加载
- [ ] 条数上限与字数上限是**受管参数**，落在既有参数白名单机制里，改完立即生效（不重启）
- [ ] **一个字都不填的患者，导诊链路行为与今天完全一致**（回归保证）
