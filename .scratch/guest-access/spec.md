# 游客访问对话页（spec）

Status: ready-for-agent
Branch: `feat/guest-access`

---

## Problem Statement

**未登录访客连"这个产品长什么样"都看不到。**

`/` 现在要求登录（`router/index.js`），访客一进首页就被送去 `/login?redirect=/`。这条规则对"就诊记录"是必要的——那是个人数据；但对**接诊卡**不是：空状态那一屏是纯前端的行动邀请（说清部位/时间/感觉、人体图、示例句），它不含任何患者数据，也不产生任何后端请求。

结果是一个具体损失：**谁都看不见这个系统是做什么的**。要把这个产品展示给一个人（同学、老师、答辩评委、潜在用户），必须先给他开一个账号。而"先注册再看"在演示场合经常直接劝退。

**同时有一个更隐蔽的问题：两套 401 处理口径已经分叉了。** `utils/sse.js` 与 `api/http.js` 各写了一份"未登录就跳登录"的逻辑，其中 `http.js` 会看当前路由是否 `meta.public`、`sse.js` **不看**。只要哪天把 `/` 设成公开路由，同一页面上两个接口对同一个 401 会做出不同反应——一个安静失败、一个强制跳转。这不是假设，是读代码就能看见的现状。

**第三个问题：草稿跨登录流程会丢。** `draft` / `parts` / `partStage` 都是对话页的局部状态，跳去登录页那一刻组件卸载，游客刚选好的部位与刚写完的主诉全部消失。仓里有一条现成判据——「可编辑文本被静默顶掉属于不可接受的数据丢失」——而这里更糟：**是我们要求他去登录的，不是他改了主意**。

---

## Solution

**未登录也能完整走一遍导诊前的准备，只是发不出去。**

访客打开 `/`：

- 看得到完整的接诊卡、人体图、示例句、快捷词，能点选部位、能在输入框里写字；
- 左栏保留但内容空态化：会话列表显示「登录后查看就诊记录」，用户区显示「未 登 录」+「去登录」；
- 输入区左下角常驻一句「登录后我才能给您导诊 · 去登录」，**取代**免责语的位置（不新增一行）；
- **按发送那一刻**提示登录并把焦点交给「去登录」——按钮本身保持可点，因为"按钮灰着"会让人以为是自己哪里没填对。

点了「去登录」→ 登录 → 回到 `/`，**刚才写的字和选好的部位都还在**，按一次发送就发出去。

已登录用户点「退出登录」后**留在 `/` 的游客态**，而不是被送去登录页——退出登录的语义是"不再以这个身份操作"，不是"这个产品对我关门了"。

**后端一行不动。** 游客路径不发任何 `/api/**` 请求，靠前端"不发请求 + 不渲染依赖登录的块"实现，而不是放宽鉴权把安全边界让给 UI。

## User Stories

### 访客看得到

1. 作为未登录访客，我想直接打开首页看到完整的接诊界面，这样我不必先注册就能理解这个系统在做什么。
2. 作为未登录访客，我想看到「说清这三件事就够了」那三张部件卡与示例句，这样我知道系统期待我描述什么。
3. 作为未登录访客，我想打开人体图并点选部位，这样我能判断这个选部位的过程是否省事。
4. 作为未登录访客，我想点快捷词让图上自动预选，这样我不用在大图上找位置。
5. 作为未登录访客，我想在输入框里写下自己的主诉，这样我能试写一句再决定要不要登录。
6. 作为未登录访客，我想看到左侧栏的原貌（会话目录、开始新咨询、用户区），这样页面不会看起来像加载失败。
7. 作为未登录访客，我想在左栏看到「登录后查看就诊记录」而不是「还没有就诊记录」，这样我不会误以为系统把我的记录弄丢了。
8. 作为未登录访客，我想在用户区看到「未 登 录」和「去登录」，这样我知道当前身份以及下一步该做什么。

### 访客发送时被拦

9. 作为未登录访客，我想按发送时得到一句明确的「登录后我才能给您导诊」，这样我知道卡在哪、而不是猜自己是不是哪里没填对。
10. 作为未登录访客，我想发送按钮保持可点，这样我能主动触发提示，而不是面对一个灰按钮猜原因。
11. 作为未登录访客，我想在点发送后焦点自动落到「去登录」，这样我不用再找一次入口。
12. 作为未登录访客，我想在点了发送之后**不被强行跳转**到登录页，这样我不会被一个惩罚性跳转打断。
13. 作为未登录访客，我想在输入区左下角**常驻**看到「登录后我才能给您导诊 · 去登录」，这样我在写之前就知道需要登录。
14. 作为未登录访客，我想让那句提示取代免责语而不是叠加，这样输入区不会多出一行、布局不变。

### 登录回来不丢东西

15. 作为未登录访客，我想在点「去登录」后，登录成功回来时输入框里那句话还在，这样我不必重写。
16. 作为未登录访客，我想登录回来时已选好的部位与锁定回执还在，这样我不必在人体图上重新点一遍。
17. 作为未登录访客，我想登录回来后按一次发送就能发出，这样登录流程不额外增加操作步数。
18. 作为登录用户，我想登录后发出的第一条消息被当成本次就诊的首条（部位声明被采纳），这样登录流程不影响导诊本身的行为。

### 退出登录

19. 作为已登录用户，我想退出登录后留在首页的游客态，这样我不必再从登录页手动点回首页。
20. 作为已登录用户，我想退出后左栏用户区变成「未 登 录」+「去登录」，这样我能确认自己确实退出了。
21. 作为共用同一台设备的用户，我想退出登录时清掉上一位患者写的主诉草稿，这样下一个人看不到不属于他的内容。

### 边界与安全

22. 作为系统维护者，我想 `/register`（模拟挂号）仍然要求登录，这样游客不会看到一个只有错误提示的空页面。
23. 作为系统维护者，我想 `/admin/**` 的鉴权完全不变，这样管理端不被这次改动波及。
24. 作为系统维护者，我想后端鉴权规则一行不改，这样游客路径不是靠放宽服务端来兜的。
25. 作为系统维护者，我想游客的会话列表请求压根不发，这样"没有记录"与"这里不开放"是两个可区分的状态，而不是同一个空态。
26. 作为系统维护者，我想 401 的处理口径合并成一处，这样同一页面上两个接口不会对同一个 401 做出相反反应。
27. 作为系统维护者，我想「登录过期」仍然会跳登录页，这样过期态不会被这次改动顺手放开。
28. 作为开发调试者，我想 `/preview`（人体图部件预览页）维持现状，这样它不受这次改动影响。

## Implementation Decisions

### 鉴权边界：只在前端放开，后端零改动

后端现状（事实）：`permitAll` 只有 `/api/auth/login`、`/api/auth/register`、`/error` 与 dispatcher 规则；`/api/chat/**`、`/api/records/**`、`/api/profile/**`、`/api/track/**` 全部 `authenticated()`，游客调用一律 401 + 业务码 2000。

**不放宽任何一条。** 就诊记录是个人数据，为一个前端展示态去动服务端鉴权是把安全边界让给 UI。

### 路由

| 路由 | 处理 |
|---|---|
| `/` | 加 `meta.public: true` |
| `/register` | 保持需登录（缺 `recordId` 时它只会渲染错误态，放开没有意义） |
| `/preview` | 维持现状 `public` |
| `/admin/**` | 不动 |

### 401 口径合并为一处

现况是两份实现且行为不一致：`http.js` 的 `redirectToLogin` 检查 `meta.public`，`sse.js` 里的同名函数**不检查**。

抽出 `utils/authRedirect.js`，导出单一入口 `onUnauthorized()`，判据统一为：

- 当前路由 `meta.public` ⇒ **不跳转**，把"需要登录"交回调用方展示；
- 否则 ⇒ 清 user store 与 chat store，跳 `/login?redirect=<当前 fullPath>`。

两个文件都改为调它，**各自不再保留本地副本**。

> 这条判据不分"游客"与"登录过期"：游客在 `canSend` 处就被拦住、发不出请求；能走到 401 的只有"token 过期/失效"。所以"过期 ⇒ 跳登录"的行为原样保留。

### 游客判定：全仓只许一处

`stores/user.js` 增加 `isGuest`（= 未持有 token），**所有分支只读它**。对话页再收一个 `canSend` 作为"按钮能不能按"的唯一判据。

仓库已有两条同型教训（`isFirstTurn` 曾在前后端各算一次、`partStage` 曾用 `!sessionId` 预测后端），这条是同一判据：**同一个值服务多个消费者时，只许有一处算它。**

### 发送闸的位置：点击路径，不是按钮禁用

发送按钮的 `disabled` 条件**保持现状不变**（流式中 / 等待态 / 无内容），**不加入游客判断**。

游客点击发送时，在 `send()` 的入口处拦截，展示"需要登录"提示并把焦点交给「去登录」。理由：按钮灰掉时用户的第一反应是"我是不是哪里没填对"，而真正原因必须在他**试图发送时**告诉他。

**一个刻意保留的语义差别**：`partStage` 门禁（等待态）**仍然禁用按钮**，因为那一条的提示已经写在输入框 placeholder 里（"先在上面选好位置，就能开始说了…"），用户能自己读懂；而"没登录"这条没有任何就地线索，必须靠点击触发。

### 游客草稿：进 chat store，取走即清

`draft` / `parts` / `partStage` 三样在游客态下必须跨登录流程存活，而它们现在是对话页的局部状态。

- 在 chat store 里加一组**独立字段**（`guestDraft`），`reset()` **不碰它**——`reset()` 的语义是"清空这次会话"（开新咨询、挂号成功、登出三处调用），而草稿恰恰是要保住的。
- 读写形状**照搬既有的 `consumeReplay()`**：`consumeGuestDraft()` 取走并清空，对话页在挂载时调它。登录页**完全不知道**这件事——让登录页去管对话页的内部状态是不该有的耦合。
- **清除点显式写**：`consumeGuestDraft()` 那一次 + 登出时清一次（登出根本不经过对话页挂载）。
- 不落 `localStorage`：共用设备上会给下一个人看到上一位患者写的主诉。仓里已有同一条线（换账号不能看到上一位患者的主诉与结论卡）。

### 游客态的左栏

`SideRail` 现在只收三个 props、七个 emit，template 里会话列表与用户区**无条件渲染**，组件内**零** store 依赖——这个契约要保持。

- **新增一个 `isGuest` prop**，父页面算好传下去；组件不自己读 store（否则"谁是游客"又被算了一遍）。
- 游客态：会话列表区显示「登录后查看就诊记录」；用户区显示「未 登 录」+「去登录」（替换昵称与「健康档案」「退出」三个入口）。
- `loadSessions()` 在游客态**直接返回，不发请求**。让请求发出去再靠 401 兜的写法会把"没有记录"和"这里不开放"混成同一个空态——仓里已有判据：**「取不到」与「没有」必须是两个状态**。

### 输入区

- 游客态：输入区左下角那格**换成**「登录后我才能给您导诊 · 去登录」，取代免责语。它承担同一位置、同一角色的说明，**不是新增一行**——医疗产品的免责信息在游客态下仍以"登录后我才能给您导诊"的形式在场。
- 点发送时那句提示高亮一下，焦点交给「去登录」。
- 输入框在游客态**可写**（这是 Q1「闸在发送」的核心：让游客走完准备流程）。

### 登录回来的路径是通的（已核实，不需额外处理）

登录回来时 `partStage` 仍是 `locked`、`parts` 还在、`sessionId` 为空。后端 `isFirstTurn` 的判据是 `askRound==0 && hasResult!=1` ⇒ 这条消息会被当成本次就诊的**首条**，部位声明被采纳。**这条路径不需要任何特殊处理**，但它是"草稿必须保留"这个决定的技术前提，记在这里防止后人误改。

### 文档

- `docs/architecture/链路D-鉴权.md`：补"未登录可访问对话页，导诊与就诊记录要求登录"这条边界。
- `.claude/rules/前端设计方案-患者端.md`：新增游客态视觉（输入区左下角那句、左栏用户区「未 登 录」）。
- `CONTEXT.md`：新增「游客（guest）」词条，**一条、不铺开**——它在本系统里是有语义的状态（能看不能问、能选部位不能发送），不是纯前端实现细节；后面谁再改鉴权边界，词表里没这个词就得从头推一遍。
- `进度.md` 三节 + `进度-施工日志.md`。

## Testing Decisions

**总原则**：只测外部可观察的行为，不测实现细节。这次改动**几乎全在前端**，而后端零改动——所以不新增后端测试，也不引入前端组件测试框架（Vitest + @vue/test-utils 是新依赖，违反"不额外引入"）。

### 缝一 · 前端纯规则自检（既有缝，扩展）

仓里已有 `frontend/scripts/check-*.mjs`，且 pre-commit 硬闸会**逐个跑** `scripts/check-*.mjs`（通配，不写死名单）——新脚本自动受保护，不需要改 hook。

新增 `check-guest-draft.mjs`，钉住草稿状态机的纯规则：

- `consumeGuestDraft()` 返回上一次存入的内容，且**再取一次返回空**（取走即清）；
- `reset()` 之后 `guestDraft` **仍在**（这是"开新咨询/挂号成功不该清草稿"的可执行表达）；
- 登出路径清空 `guestDraft`；
- 空草稿不被当成"有草稿"（避免登录回来后覆写一个空的输入框）。

**先红后绿**：把 `reset()` 里误加 `guestDraft` 清理放进去 → 该条应当变红；改回 → 全绿。

### 缝二 · 真机探针（既有缝，不新增工具）

用户跑，逐条对照：

1. 未登录打开 `/` **不跳转**，接诊卡完整；
2. 左栏显示「登录后查看就诊记录」、用户区显示「未 登 录」+「去登录」，**网络面板无 `/api/records/sessions` 请求**；
3. 点快捷词 → 图打开并预选 → 选部位 → 输入框出现句子；
4. 写一句主诉 → 点发送 → 出现「登录后我才能给您导诊」提示 + 焦点在「去登录」，**未跳转**；
5. 点「去登录」→ 登录 → 回到 `/`，**输入框与锁定回执都还在**；
6. 按一次发送 → 导诊正常跑，且后端日志显示这是**新会话首条**、部位声明被采纳（不出现「部位声明丢弃」）；
7. 已登录状态下退出 → **留在 `/` 的游客态**，草稿已清；
8. 把 token 手动改坏（模拟过期）→ 发一条消息 → **跳登录页**（"过期"与"游客"行为必须不同）。

### 缝三 · 不测的东西，以及为什么

- **`utils/authRedirect.js` 不单写测试**：它只在"当前路由是否 public"上分叉，测它等于测一个 `if`；正确性由缝二的第 4 条与第 8 条覆盖（两条路径行为不同）。
- **`SideRail` 的游客渲染不写组件测试**：纯展示分支，且引出组件测试就要引入新依赖。
- **后端不加测试**：没有后端改动。跑一次 `mvn -pl stats -am test` 只为确认没被误伤。

### 回归

- `npm run check` 现有 161 条（人体图 153 + 请求体 8）必须全绿。**注意**：`check-chat-body.mjs` 钉的是"有声明就带、不看 sessionId"，游客态**不改请求体规则**，这个脚本不该被动到——如果它需要改，说明方案跑偏了。
- `npm run build` 通过。

## Out of Scope

- **后端鉴权规则**：一条不放宽。`/api/chat/**`、`/api/records/**`、`/api/profile/**`、`/api/track/**` 仍要求登录。
- **免注册试用导诊**（真让游客发消息、匿名会话、后续再补登录并迁移数据）：这是完全不同的体量，牵动会话归属、埋点口径、看板分母。本次只做"能看能准备、发不出去"。
- **管理端「健康档案标签」维护页**：已确认不做。
- **`track_event` 查看入口**：独立缺口，不在本次范围。
- **`/register` 对游客开放**：它没有 `recordId` 时无内容可看。
- **前端组件测试框架**：不引入 Vitest / @vue/test-utils。
- **游客草稿的持久化跨浏览器会话**（关标签页再开还在）：不落 localStorage，理由见实现决策。

## Further Notes

**这次改动的形状**：一小块路由配置 + 一个合并的 401 函数 + 三个组件的展示分支 + 一组 store 字段。**没有新模块、没有新表、没有新依赖、后端零改动。**

**为什么值得做**：它把一个"必须先注册才能看"的系统变成"先看得见、再决定". 对答辩与演示是直接收益——评委打开链接就能看到完整界面，不需要先要一个账号。

**两条要防止的未来误改**：

1. **别把游客判断写进发送按钮的 `disabled`**。那会让"按钮灰着、用户不知道为什么"重现，而这正是本次刻意避开的交互。
2. **别把 `guestDraft` 塞进 `reset()`**。`reset()` 的语义是"清空这次会话"，草稿不是会话的一部分；塞进去的后果是"游客点了去登录、回来一看输入框空了"——正是这次要修的那个缺陷。
