# 05: 游客态的对话页——闸在发送，不在按钮

**What to build:**

游客能完整走一遍"导诊前的准备"：选部位、看锁定回执、在输入框里写字。**只有按发送那一刻**才告诉他需要登录。

三处改动：

1. **发送按钮的 `disabled` 条件保持不变**（流式中 / 等待态 / 无内容），**不加入游客判断**。
2. **`send()` 入口拦一道**：游客点击时展示"需要登录"提示，把焦点交给「去登录」，**不跳转**。
3. **输入区左下角那格换成**「登录后我才能给您导诊 · 去登录」。

**已定的规则**

1. **按钮必须可点**。灰按钮会让人的第一反应变成"我是不是哪里没填对"，而真正的原因必须在他**试图发送时**告诉他。
2. **一个刻意保留的不对称**：`partStage` 门禁（等待态）**仍然禁用按钮**，因为那一条的提示已经写在 placeholder 里（"先在上面选好位置，就能开始说了…"），用户能自己读懂；而"没登录"这条没有任何就地线索，必须靠点击触发。
3. **提示是常驻的，不是按需的**。它取代免责语的位置——同位置、同角色，**不新增一行**。医疗产品那条线（免责信息要一直在场）在游客态下以"登录后我才能给您导诊"的形式承担。
4. **点了发送不跳转**。跳转会打断一个刚选完部位、写完一句话的游客——页面突然消失是惩罚性交互。去哪里由他点「去登录」决定。
5. **草稿在游客态要存进 store**（`guestDraft`，见工单 02），挂载时用 `consumeGuestDraft()` 取回。**清除点只有两处**：取走那次、登出那次。**不许写进 `reset()`**。
6. **游客态输入框可写**。"闸在发送"的核心就是让游客走完准备流程；输入框 readonly 等于把闸挪到了输入区，与决定相违。
7. **登录回来后的路径已经核实是通的，不要额外处理**：`partStage` 仍是 `locked`、`parts` 还在、`sessionId` 为空 ⇒ 后端 `isFirstTurn`（`askRound==0 && hasResult!=1`）会把它当新会话首条、采纳声明。**这条不需要代码，但它是"草稿必须保留"的技术前提**。

**验收**

- [ ] 发送按钮的 `disabled` 表达式**与改动前完全一致**（git diff 里这一行不该变）
- [ ] 游客点发送 ⇒ 输入区出现/高亮「登录后我才能给您导诊 · 去登录」+ 焦点在「去登录」，**URL 不变**
- [ ] 游客可打开人体图、选部位、拿到锁定回执、输入框出现句子
- [ ] 游客可自由编辑输入框文字
- [ ] 点「去登录」⇒ 登录 ⇒ 回到 `/`：**输入框文字与锁定回执都还在**
- [ ] 登录后按一次发送 ⇒ 导诊正常跑；后端日志显示**新会话首条 + 部位声明被采纳**（不出现「部位声明丢弃」）
- [ ] 已登录用户界面**完全不变**（回归：等待态门禁、流式中禁用、无内容禁用）
- [ ] 视觉符合 `.claude/rules/前端设计方案-患者端.md` §3.5（输入区是整块书写卡、聚焦态转 `--leaf` 描边）
- [ ] `npm run build` 通过；`npm run check` 全绿

## Comments

**最容易被改坏的两处，已写进 spec 的 Further Notes**：

1. 别把游客判断写进发送按钮的 `disabled`——那会让"按钮灰着、用户不知道为什么"重现。
2. 别把 `guestDraft` 塞进 `reset()`——后果是"游客点了去登录、回来一看输入框空了"，正是本次要修的缺陷。
