# 04: 游客态的左侧栏——保留整栏，内容空态化

**What to build:**

左栏是这套设计最强的识别点之一，游客态**不隐藏、不收窄**，只把内容换成对应的空态：

| 区块 | 游客态 |
|---|---|
| 标识行 + 「＋ 开始新的咨询」 | 原样保留 |
| tab（全部对话 / 挂号历史） | 原样保留 |
| 会话列表区 | 「**登录后查看就诊记录**」（替换「还没有就诊记录」） |
| 底部用户区 | 「**未 登 录**」+「**去登录**」（替换昵称 / 健康档案 / 退出三个入口） |

**实现**

`SideRail` 新增 **`isGuest` prop**（不自己读 store——组件现在零 store 依赖，这个契约要保持）。

`loadSessions()` 在游客态**直接返回，不发请求**。

**已定的规则**

1. **不发请求，而不是发了靠 401 兜**。让请求发出去再安静失败，会把"他确实没看过病"与"这里对他不开放"混成同一个空态。仓里已有判据：**「取不到」与「没有」必须是两个状态**。
2. **整栏保留的理由**：直接砍掉半屏会让人以为页面没加载完；而"这里本来该有什么、只是我还看不到"本身就在说明登录能换来什么。
3. **「去登录」是唯一新增的交互入口**，它跳 `/login?redirect=/`。不做浮层、不复用 `.p-overlay`——为一句提示新开一个浮层不划算。
4. **「健康档案」「退出」在游客态不渲染**：它们都是已登录才成立的动作。健康档案对应的是个人数据；退出对未登录者没有意义。
5. **手机端顶栏也要对齐**：现在它固定渲染「我的就诊」与「退出」，游客态要改成与左栏用户区一致（未登录 + 去登录），否则同一页面上两处对身份的表述会打架。

**验收**

- [x] `SideRail` 新增 `isGuest` prop；组件内仍无 store 引用（grep 确认）
- [x] 游客态左栏：标识行 / 开始新咨询 / tab 都在，列表区显示「登录后查看就诊记录」
- [x] 游客态用户区显示「未 登 录」+「去登录」，无「健康档案」「退出」
- [ ] 点「去登录」⇒ `/login?redirect=/`；登录后回到 `/`（代码路径已通，实际点击归人工）
- [ ] **网络面板确认**：进页面时没有 `GET /api/records/sessions` 请求（归人工）
- [x] 已登录态的渲染**完全不变**（回归：会话列表、归档、用户区三入口）

## Comments

**一个容易做错的地方**：`loadSessions()` 在三处被调用（挂载、归档切换、每轮对话结束由父页 `reload`）。游客态下这三处都该直接返回——只在挂载那处加判断，另外两处会在游客能触发的路径上漏出去（虽然本次游客发不了消息，但归档切换那条仍然可能被点到）。

**实现说明（2026-10-23）**：

改了三处：`components/patient/SideRail.vue`、`views/patient/Chat.vue`、`styles/patient.css`（后两个类 `.p-topbar__who` / `.p-topbar__logout--guest` 是顶栏的共享件，只有 Chat 的顶栏用；放共享层是因为 `.p-topbar` 系列本来就定义在 `patient.css`，不拆成两处实现）。

- **闸在 `loadSessions()` 函数体第一行**（`if (props.isGuest) return`），挂载 / `setArchived` 末尾 / 父页 `reload()` 三处调用自动被同一道闸拦住。没有在调用点分别判断——那正是工单 Comments 警告的漏法。
- **空态优先级**：`v-if="isGuest"` 排在 `v-else-if="!shownDays.length"` 之前。游客的 `shownDays` 本来就是空数组，若沿用原三元会落进「还没有就诊记录」——把"这里对他不开放"说成"他没看过病"。
- **顺手收掉的第二处同源问题**：抬头「我的就诊 · N 次」在游客态不渲染次数（`N` 是 `total` 的默认 0）。写「0 次」等于替游客断言"你从没来过"，与下面「登录后查看就诊记录」自相矛盾——同一条判据（「取不到」≠「没有」）的另一个面。"我的就诊"这个抬头本身保留（整栏保留是工单的一等要求）。
- **「未登录」的视觉**：没有用昵称首字（游客没昵称，随手编一个字更像出错），头像位改画一枚 **锁形 SVG**（14px，`--rail` 底 + `--ink-2` 图标）——中性、说的是"这里要登录"，不是"你是某个人"，且不占用杏色（杏色专属读数与推荐）。身份行是 `<span>` 不是按钮（它不指向任何地方，做成按钮就是个点不动的假控件），12.5px/600/`--ink-2`，与已登录态的昵称同字阶，只是少了 hover 变色。「去登录」复用 `.p-chat__uprof` 的槽位（同一张卡、同一套行高），游客态用上下文覆盖升到 `--leaf-deep`（它是这张卡唯一的动作，不再是"健康档案"那样的副标）。
- **emit `login`**：组件仍零 router / store 依赖，跳转由 `Chat.vue` 的 `goLogin()` 做（`router.push({ path: '/login', query: { redirect: '/' } })`，顺带 `sideOpen = false` 收掉手机覆盖层）。落地判定仍在 `Login.vue` 的角色优先逻辑里，本工单不碰。
- **手机顶栏**：游客态换成「未登录」+「去登录」，与左栏用户区一字不差。「去登录」按钮复用 `.p-topbar__logout` 的形状（同高同圆角）但加 `--guest` 修饰——已登录态那个是「退出」、hover 转危险色，语义不同不能沿用危险色。
- 已登录路径逐个分支核对过：新增的 `v-if="isGuest"` 全部是"游客分支 / `v-else` 原样"，非游客渲染与改动前逐字一致。

**与工单字面的一处偏差**：工单写「未 登 录」，实现里文本是 **「未登录」+ `letter-spacing: .08em`**。仓里既有约定就是"标签放宽靠字距，文字本身不插空格"（`patient.css` 里 `.p-eyebrow` 上方那条注释，理由是复制 / 搜索 / 读屏连贯），已有同类标签（「健康档案」「我的就诊」）也都是这么写的。视觉等价，按既有约定落地。

**归人工（本环境无浏览器）**：网络面板确认无 `GET /api/records/sessions`；点「去登录」→ 登录 → 回到 `/` 的实跑；视觉走查（`--rail` 底、无新增边线）。
