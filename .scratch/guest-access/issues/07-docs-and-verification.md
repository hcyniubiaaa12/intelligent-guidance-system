**第 8 条暴露的缺陷（工单 01 的实现口径在工单 03 落地后失效）**

`utils/authRedirect.js` 的 `onUnauthorized()` 原先第一行是 `if (route.meta.public) return false`。工单 01 合并两份副本时这是对的——当时 `/` 还不是公开路由。工单 03 把 `/` 放开之后，**登录过期**用户在首页发消息被 401 会既不清 token 也不跳登录页：界面维持"已登录"的假象、每次操作都失败、没有出路。

**修法**：判据从「当前路由是否 public」改为「**public 且 `isGuest`**」——游客与过期的分界是手里有没有 token，不是路由。游客本来就走不到 401（工单 05 的发送闸先拦下了），所以这条分支只兜底"公开页对游客发了请求"这种将来才可能有的场景。改的是 `frontend/src/utils/authRedirect.js` 一个判断，**后端仍零改动**。

**为什么单测和工单 01 的验收都没发现**：单测里这是一个 if；工单 01 验收时 `/` 还没公开（它自己的验收清单写的是"把 token 改坏后发一条消息 ⇒ 跳登录页"，当时 `/` 非 public，自然过）。**这个组合直到 01 与 03 同时生效才存在**——跨工单的交互缺陷，正是第 8 条"能同时证伪两个工单"的价值所在。

**探针本身踩过的两个坑（写进 `进度.md`「已知坑」）**：

1. **刷新一下再发消息会验出假绿**：刷新后跳登录页是 `SideRail` 拉会话列表拿 401 触发的，**不是发消息那条路径**。第 8 条必须验"发消息"这个动作本身，所以改成只改 localStorage（store 保持已登录、请求头现取坏 token），不刷新。
2. **在 worktree 里跑探针验到的是共享检出那份代码**：常驻 vite 起在共享检出目录。解法是在 worktree 里另起 `npx vite --port 5174`，探针指过去。

**第 6 条的证据选择**：后端 stdout 不归本会话所有，但日志文件 `backend/admin/logs/guide.log` 可读且确实在写（用 `stat` 确认过请求后增长）。做法是发消息前记下文件大小、之后只读新增段，避免误中历史会话。这比 SSE 帧更硬：`firstTurn` 与「部位声明 腹部」都是后端算的。

### 评审补充（2026-10-23）——探针第 7 条只验了"清草稿"，没验"清列表"

第 7 条（已登录退出 ⇒ 留在 `/` 游客态、草稿已清）的检查项是：URL 仍 `/`、用户卡「未登录」+「去登录」、token 清空、输入框与回执都空。它**没有看左栏的会话列表**——而恰恰是那里漏了：`SideRail` 的 `days` / `archivedDays` 在登出后仍留着上一位患者的全部主诉，归档区「取回」还点得动。探针跑完是绿的，缺陷照样在。

**为什么没覆盖到**：这条探针的断言都落在"输入区 + 用户卡 + 回执"这三块（它们正是工单 05/06 改过的地方），左栏会话列表被当成工单 04 的既有成果、默认正确。但工单 04 验的是**游客首屏挂载**，从没验过"已登录 → 游客"这个 prop 翻转——探针第 7 条恰好是这个翻转的唯一一次真跑，却没查它。

**教训（值得进后续探针的写法）**：验"共用设备上看不到上一位患者的数据"时，断言不能只查被清理动作显式点到的那几个字段，要**查整页所有承载个人数据的位置**——本页是四处：对话正文、输入框草稿、左栏会话列表、归档区。少查一处就等于给那一处发了免检通行证。

**修法**（详见 04 的评审补充）：`SideRail.vue` 加 `watch(() => props.isGuest, …, { immediate: true })` 清零 + 模板把主区与归档区整块包进 `<template v-else>`。第 7 条若要补断言，应加一句"退出后 `.p-chat__list` 内 `.p-i` 数量为 0、归档折叠条不出现"。

**第 3 条：token 失效时点退出会被踢去登录页（首次失败，已修复并复验通过）**

**首次现象**（两次运行一致）：登录 → 把 `localStorage.token` 改成 `bad`（**不刷新**，store 仍认为已登录）→ 点「退出」→ URL 变成 `/login?redirect=/`。本地状态确实清干净了（token 已清），但工单 06 验收第 5 条要的是**留在游客态**，这一条没达成。

根因：`Chat.vue` 的 `onLogout()` 先 `await apiLogout()`。坏 token 让 `POST /api/auth/logout` 返回 401，axios 响应拦截器调 `onUnauthorized()`；此刻 `isGuest` 仍为 false（token 只改在 localStorage，store 里那份没动），于是 `meta.public && isGuest` 不成立 → 走「登录过期」分支 → `router.push('/login?redirect=/')`。

**URL 轨迹实测**（钩 `history.pushState` + 20ms 轮询，共采样 3 秒）：`t=0` 停在 `/` → `t=38ms` 一次 `pushState` 到 `/login?redirect=/` → **之后没有任何跳转**，最终 URL 就是登录页。`finally` 里那句 `if (router.currentRoute.value.path !== '/') router.push('/')` 没有生效——它执行时路由导航尚未确认，`currentRoute.value.path` 仍是 `/`，条件为假。也就是说**兜底那一行在这个时序下兜不住**，这不是"推回去又被弹回来"，而是"压根没往回推"。

**当时的控制台情况**：401 另带一条未捕获 promise rejection——`pageerror: Error: 未登录或登录已过期`，同时一条 `Failed to load resource: 401 (Unauthorized)`。原因是 `try/finally` 没有 `catch`：拦截器 reject 后异常直接冒泡。

**修复**（三处，`frontend/src/`）：

1. `api/http.js` 加 `skipRedirect(config)` 判据（`config.skipAuthRedirect === true`），两处调 `onUnauthorized()` 前跳过；默认行为不变。
2. `api/auth.js` 的 `logout()` 用 `http.post('/auth/logout', null, { skipAuthRedirect: true })`——**请求照发**，只是 401 不再触发跳转。
3. `Chat.vue` 的 `onLogout()` 补 `catch (e) { console.warn(...) }`，吞异常但不吞日志。
