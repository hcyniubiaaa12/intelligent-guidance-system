# 07: 文档同步与真机验收

**What to build:**

把本次改动的口径落进基线文档，并在真实环境把游客路径完整跑一遍。

**文档（四处）**

1. `docs/architecture/链路D-鉴权.md`——补"未登录可访问对话页，导诊与就诊记录要求登录"这条边界，并写明**后端鉴权规则未放宽**（游客路径靠前端不请求实现）。
2. `.claude/rules/前端设计方案-患者端.md`——新增游客态视觉：输入区左下角那句、左栏用户区「未 登 录」、会话列表空态文案。**只写视觉，不写实现**（那份文档只管视觉与布局）。
3. `CONTEXT.md`——新增「游客（guest）」词条，**一条、不铺开**。它在本系统里是有语义的状态（能看不能问、能选部位不能发送），不是纯前端实现细节。
4. `进度.md` 三节 + `进度-施工日志.md`——总览、已知坑（若有）、施工日志三件事（定了什么 / 踩了什么 / 还欠什么）。

**真机探针（八条，需人工跑）**

1. 未登录打开 `/` **不跳转**，接诊卡完整；
2. 左栏显示「登录后查看就诊记录」、用户区「未 登 录」+「去登录」，**网络面板无 `/api/records/sessions` 请求**；
3. 点快捷词 ⇒ 图打开并预选 ⇒ 选部位 ⇒ 输入框出现句子；
4. 写一句主诉 ⇒ 点发送 ⇒ 出现「登录后我才能给您导诊」提示 + 焦点在「去登录」，**URL 不变**；
5. 点「去登录」⇒ 登录 ⇒ 回到 `/`，**输入框与锁定回执都还在**；
6. 按一次发送 ⇒ 导诊正常跑，后端日志显示**新会话首条 + 部位声明被采纳**（不出现「部位声明丢弃」）；
7. 已登录状态退出 ⇒ **留在 `/` 游客态**，草稿已清；
8. 把 token 手动改坏（模拟过期）⇒ 发一条消息 ⇒ **跳登录页**（"过期"与"游客"行为必须不同）。

**已定的规则**

1. **基线文档不得链进 `.scratch/`**（pre-commit 硬闸 ① 会拦）。要引用这次改动就写"游客访问"这个词本身，不写工单路径。
2. **`npm run check` 的 161 条不该需要改**。`check-chat-body.mjs` 钉的是"有声明就带、不看 sessionId"，游客态**不改请求体规则**——如果它需要改，说明方案跑偏了。
3. 新增的 `check-guest-draft.mjs` 自动受闸保护（闸通配 `scripts/check-*.mjs`），**不需要改 hook**。
