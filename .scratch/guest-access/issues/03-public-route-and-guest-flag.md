# 03: 路由放开 `/`，游客判定收成一处

**What to build:**

1. **路由**：`/` 加 `meta.public: true`。`/register` 保持需登录（缺 `recordId` 时它只会渲染错误态）；`/preview` 维持现状；`/admin/**` 不动。
2. **游客判定**：`stores/user.js` 增加 `isGuest`（= 未持有 token）。**所有分支只读它**，不再各处写 `!token` / `!isLogin`。

**已定的规则**

1. **后端一行不动**。`permitAll` 仍然只有 login/register/error；`/api/chat/**`、`/api/records/**`、`/api/profile/**`、`/api/track/**` 继续要求登录。游客路径靠"前端不请求"实现，不是靠放宽服务端。
2. **`isGuest` 与 `isLogin` 不是两个概念**，是同一个事实的两个名字。**不要**同时保留两个可以被分别使用的东西——若仓库里已有 `isLogin`，`isGuest` 应当是它的反面且全仓只读其中一个。选一个作为唯一入口并在注释里写明，避免下一个人两个都看见、各选一个。
3. **`SideRail` 不自己读 store**。它现在零 store 依赖、只收三个 props——这个契约要保持。游客开关通过**新增 prop** 传入（工单 04 用）。
4. **本工单只做路由与判定，不做视觉**。放开之后 Visiter 能进页面，但此时**还看不到任何游客态提示、左栏也还是老样子**——这是刻意的中间态，由 04 / 05 补齐。验收按"能进页面且不发请求"来判。

**验收**

- [ ] `/` 有 `meta.public: true`；`/register`、`/admin/**` 无此标记
- [ ] `stores/user.js` 有唯一的游客判定导出，注释写明它是全仓唯一入口
- [ ] 全仓 grep 游客判断只有一处定义、且没有别处另写 `!token`
- [ ] 未登录直接访问 `/` **不再跳转**，页面正常渲染
- [ ] 未登录访问 `/register` 仍被送去登录页
- [ ] 后端代码零改动（`git diff --stat` 里没有 `backend/`）
- [ ] `npm run build` 通过

**Blocked by:** 01（否则游客一进页面就可能被 401 强制跳转，本工单的验收条件无法成立）

**Status:** ready-for-agent

## Comments

**为什么依赖 01**：`/` 变成 public 之后，`http.js` 会因为 `meta.public` 跳过跳转，但 `sse.js` 的本地副本不会——两个接口对同一个 401 做出相反反应。先把口径合并（01），这条边界才是确定的。

**中间态可接受**：03 做完后游客能进页面但看不到任何提示、左栏照旧显示"还没有就诊记录"（且会发一次会话列表请求）。它是可上线的中间态（不比现状差），但**不是完整功能**——04/05 补齐前不要宣布这条链完成。
