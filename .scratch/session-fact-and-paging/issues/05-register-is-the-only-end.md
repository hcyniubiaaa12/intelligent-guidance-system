# 05: 会话边界改口径——**挂号才结束**，出结论之后仍可继续询问

**What to build:**

把"这次会话什么时候结束"的判据从**出结论**改成**挂号**：

- `ChatSession.continuable()` 由 `status == ONGOING && (has_result == 0)` 改为 **`status == ONGOING`**——挂号置 `CLOSED` 成为**唯一**的结束信号。
- 出结论（`has_result=1`）之后患者再说话 = **同一会话的续聊**，不再被当成"新的一次就诊"。
- 随之：门禁**不再**在出结论时回等待态（患者不必重新声明部位）；`has_result` 从"边界判据"降级为"这张会话已经出过结论"的事实标记。

**为什么改（用户 2026-10-14 定案）**：现状下"出结论"就结束了这次会话，患者想问一句"那我该注意什么"会被系统当成**新的一次就诊**（要求重新在人体图上选部位、后端另开会话、刚才那段原地只读）。用户的原话：「挂号就结束，出结论还可以询问。」

---

## 一、现状（改之前的事实，逐条有据）

| 事实 | 位置 |
|---|---|
| 可续聊 = `status==ONGOING && has_result!=1` | `ChatSession.continuable()` |
| 不可续聊 ⇒ 后端**新建会话**（`created=true`） | `ChatService.resolveSession()` |
| 「首轮」= `askRound==0 && has_result!=1` | `ChatService.isFirstTurn()` |
| 出结论即置 `has_result=1`，并写一条 `guide_record` | `GuideService.saveConclusion()` 尾部 |
| 挂号即置 `status=CLOSED` | `GuideService.confirmRegister()` |
| 前端在 `done.hasResult` 时把门禁摆回等待态（= 要求重新声明） | `Chat.vue` 的 `onDone` |
| 领域规则明文写着"出结论或 closed 后的下一句 = 新会话" | `CONTEXT.md`「会话」词条（第 73 行） |

## 二、要改的（三处 + 一处文档）

1. **`continuable()` 去掉 `has_result!=1`**：`status == ONGOING` 即可续聊。这是本票的唯一"开关"。
2. **门禁不再回等待态**：`Chat.vue` 的 `onDone` 里 `if (hasResult) { parts 清空; partStage='awaiting' }` 整段去掉（回等待态是"新就诊要重新声明"的逻辑，工单 04 之后归**挂号成功**触发）。出结论后继续问走同会话追问轮：`partStage` 保持 `locked`、`partsSubmitted` 已为 `true` ⇒ **不再重复带声明**，后端也照旧丢弃 ✔ 两端一致。
3. **`isFirstTurn` 的 `has_result!=1` 这一半——保留**：首轮仍然是 `askRound==0 && has_result!=1`。理由：会话首条就可能直接出结论（实测「腰疼两天了，还伴着尿频尿急，有糖尿病」一次就 0.82 出结论），此时 `askRound==0 && has_result==1`；若把它也算"首轮"，续问时会**再次采纳**声明——而位置信息早已在上下文里（`resolveParts` 的注释就是这个道理）。保留后它的语义变得自洽：**首轮只算会话的第一条**。
4. **文档同步**：`CONTEXT.md`「会话」词条第 73 行改为「**会话状态为 closed 后的下一句输入 = 新会话**」（出结论不再是边界）；「就诊记录」词条里"会话结束了就不能再往里写字"的口径不变（结束 = 挂号）；`总体架构与链路设计.md` 链路 A 的对齐点若有"出结论即会话结束"的表述一并对齐。

## 三、影响面（我查到的硬事实 —— 这三条是**待你拍**的，别跳过）

### 待定 ①：追问预算与"强制结论"

`forceConclusion = askRound >= askMaxRounds`（`ChatService` 第 255 行）。而患者往往是**把追问预算用完**才拿到结论（`askRound` 已经到上限）。结论之后继续问 ⇒ 每一轮都满足 `forceConclusion` ⇒ **问一句强制出一张卡**。

- **(a)** 已出结论的会话里，后续输入按"自由问答"处理：不涨 `askRound`、不参与 `forceConclusion`，只有模型自己声明 `RECOMMEND` 才出新卡。
- **(b)** 维持现状（每轮都可能强制出卡）。

➡️ 推荐 **(a)**：`forceConclusion` 存在的理由是"别把患者卡在无限追问里"（见 `ruleGate` 的护栏注释），这个目标在**出结论那一刻就已经达成**了；结论之后再强制出卡，只会给同一次就诊堆出一串结论。

### 待定 ②：一条会话多张卡 —— 回放**今天只支持一张**

`RecordService.sessionDetail()` 用的是 `loadLatestRecords(...)` 并返回**单个** `CardVO`（`SessionDetailVO(sessionItem, replay, questions, card)`）。⇒ 改了口径以后，同一会话可以有多条 `guide_record`，而**回放只显示最新那一张**：旧结论"当时见过、回放里消失"（库里还在）。

- **(a)** 回放改多卡：`CardVO` → `List<CardVO>`，前端把它按位置插回消息流（`Chat.vue` 已按 `entries` 渲染多张卡，天然支持；后端 DTO + 组装要改）。
- **(b)** 只显示最新一张，写进文档当"口径"。

➡️ 推荐 **(a)**。理由：(b) 会让**数据与展示不一致**（库里两条、界面一条），而"回放是取证的地方"——审核侧的「证据链回放」也吃这同一个接口，看到的东西必须与当时发生的一致。

### 待定 ③：准确率口径（按记录还是按会话）

准确率分母 = **`actual_dept` 非空且非低置信度且未标「患者挂错」的记录**（`DashboardService` 注释与窗口计数，逐条 `guide_record`）。一条会话两条记录时，患者只可能给**最新那张**挂号（结论卡的「去挂号」只有最新一张 `canRegister`）⇒ 旧那张永远 `actual_dept` 空，被算成"未确认/流失"。

- **(a)** 保持按记录（旧卡视作流失）。
- **(b)** 口径改为"**每条会话只取最后一条结论**进统计"。
- **(c)** 给被取代的旧卡加标记并排除。

➡️ 推荐 **(b)**：与"一次就诊 = 一份结果"一致，且改动集中在统计口径那一处 SQL；**(c)** 要加列与回填，代价最大；(a) 会让"患者流失"这个指标被系统自身的行为污染。

### 不受影响的（已核过，别顺手改）

- **盲区榜 / 根因分布 / 回流**：仍按 `guide_record` 逐条进、逐条挂 ✔ 不变。
- **侧栏与归档**：仍按会话铺开 ✔；侧栏条目的"结论=最新一张"口径不变。
- **`resolveParts` 的丢弃规则**：不变（非首轮一律丢弃，有日志）。
- **工单 01 的判定收口**：不变（`firstTurn` 仍只算一处）。

## Comments

**为什么这次不能只改前端**：`continuable()` 是后端状态机的判据，前端无从替代——前端能做的只是"不要再拿它猜"（工单 01 已经做了）。这条口径改的是**领域模型的边界**，所以它必须动后端，也必须同步 `CONTEXT.md`。

**为什么它比看上去大**：'一次会话 = 一次就诊"这条模型撑着侧栏按会话铺开、归档、准确率分母、回放取证四处。改边界 ⇒ 这四处都要过一遍；本票把查到的四处**逐条列在影响面**里，就是为了不让它们在下游变成惊喜。

**建议的实施顺序**：先落工单 04（纯收尾，不依赖本票），再落本票——本票改完，04 的门禁分支只需把"结论后回等待态"那段删掉即完成对接。
