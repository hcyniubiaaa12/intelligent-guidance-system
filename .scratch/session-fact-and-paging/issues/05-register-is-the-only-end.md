# 05: 会话边界改口径——**挂号才结束**，出结论之后仍可继续询问

**What to build:**

把"这次会话什么时候结束"的判据从**出结论**改成**挂号**：

- `ChatSession.continuable()` 由 `status == ONGOING && (has_result == 0)` 改为 **`status == ONGOING`**——挂号置 `CLOSED` 成为**唯一**的结束信号。
- 出结论（`has_result=1`）之后患者再说话 = **同一会话的续聊**，不再被当成"新的一次就诊"。
- 随之：门禁**不再**在出结论时回等待态（患者不必重新声明部位）；`has_result` 从"边界判据"降级为"这张会话已经出过结论"的事实标记。

**为什么改（用户 2026-10-14 定案）**：现状下"出结论"就结束了这次会话，患者想问一句"那我该注意什么"会被系统当成**新的一次就诊**（要求重新在人体图上选部位、后端另开会话、刚才那段原地只读）。用户的原话：「挂号就结束，出结论还可以询问。」

---

## 一、现状（改之前的事实，逐条有据）

| 事实 | 位置 |
|---|---|
| 可续聊 = `status==ONGOING && has_result!=1` | `ChatSession.continuable()` |
| 不可续聊 ⇒ 后端**新建会话**（`created=true`） | `ChatService.resolveSession()` |
| 「首轮」= `askRound==0 && has_result!=1` | `ChatService.isFirstTurn()` |
| 出结论即置 `has_result=1`，并写一条 `guide_record` | `GuideService.saveConclusion()` 尾部 |
| 挂号即置 `status=CLOSED` | `GuideService.confirmRegister()` |
| 前端在 `done.hasResult` 时把门禁摆回等待态（= 要求重新声明） | `Chat.vue` 的 `onDone` |
| 领域规则明文写着"出结论或 closed 后的下一句 = 新会话" | `CONTEXT.md`「会话」词条（第 73 行） |

## 二、要改的（三处 + 一处文档）

1. **`continuable()` 去掉 `has_result!=1`**：`status == ONGOING` 即可续聊。这是本票的唯一"开关"。
2. **门禁不再回等待态**：`Chat.vue` 的 `onDone` 里 `if (hasResult) { parts 清空; partStage='awaiting' }` 整段去掉（回等待态是"新就诊要重新声明"的逻辑，工单 04 之后归**挂号成功**触发）。出结论后继续问走同会话追问轮：`partStage` 保持 `locked`、`partsSubmitted` 已为 `true` ⇒ **不再重复带声明**，后端也照旧丢弃 ✔ 两端一致。
3. **`isFirstTurn` 的 `has_result!=1` 这一半——保留**：首轮仍然是 `askRound==0 && has_result!=1`。理由：会话首条就可能直接出结论（实测「腰疼两天了，还伴着尿频尿急，有糖尿病」一次就 0.82 出结论），此时 `askRound==0 && has_result==1`；若把它也算"首轮"，续问时会**再次采纳**声明——而位置信息早已在上下文里（`resolveParts` 的注释就是这个道理）。保留后它的语义变得自洽：**首轮只算会话的第一条**。
4. **文档同步**：`CONTEXT.md`「会话」词条第 73 行改为「**会话状态为 closed 后的下一句输入 = 新会话**」（出结论不再是边界）；「就诊记录」词条里"会话结束了就不能再往里写字"的口径不变（结束 = 挂号）；`总体架构与链路设计.md` 链路 A 的对齐点若有"出结论即会话结束"的表述一并对齐。

## 三、影响面（已逐条定案，2026-10-14）

### ① 出卡之后**重置追问预算**（用户 2026-10-14 提议，采纳），**并且**结论后不再强制出卡

**改法（两个动作，互补而非二选一）**：

1. **出卡后 `ask_round` 归零**：`saveConclusion` 出卡时 `session.setAskRound(0)`（同一条 `updateById` 里）。语义重定义为「**距最近一张结论卡，已追问几轮**」。
2. **`forceConclusion` 加 `!hasResult`**：`boolean forceConclusion = !hasResult && askRound >= askMaxRounds;`

**为什么两个都要**（这是本条最容易被漏掉的地方）：

- **只做"不消耗"是不够的**（我最初的方案，已被推翻）：患者**常见**路径是预算用满才拿到结论（`askRound == max`），此时若只是"不涨"，`forceConclusion = askRound >= max` **仍然每轮为真** ⇒ 一句一卡照旧。归零没有这个洞。
- **只做"归零"也不够**：归零后结论后仍保留"问满 max 轮就强制收口"的能力，于是患者补充信息、模型追问到满、**强制产出第二张卡**——而 `Chat.vue:130` 是 `:can-register="i === lastCardIndex"`，**只有最后一张卡能挂号**。一张补充后兜底出的**低置信度卡**会把患者原本要挂的那张（高置信度）卡的入口**挡掉**。这是不可接受的降级，所以`!hasResult` 必须一起加。

**归零带来的真实收益**（不是记账好看而已）：

- 日志与 `ruleGate` 的护栏在结论后恢复可用：不归零时 `askRound` 冻结在 max，`ruleGate` 的"预算用尽则规则让路"在结论后一直生效（无效输入不再拦），语义怪；
- 结论后继续补充时，日志里的"追问轮次 1/3"读起来就是"这张卡之后问了几轮"，而不是 `3/3` 这种被冻结的值。

**三条配套（必须一起写进注释，否则会被后人改坏）**：

- **`isFirstTurn` 的 `has_result!=1` 那一半不许动**：归零之后 `askRound == 0`；若有人把那半句去掉，"出卡后的下一轮"会被判成**首轮** ⇒ 声明被重新采纳、模板追问也回来。本票第 2 节已写明保留它，两处是咬合的。
- **`ask_round` 的语义要全量同步**：`RecordDTO.SessionItem.askRound`（暴露给管理端，患者端不读）的含义跟着改成"距最近一张卡"；`RagRequest.askRound` 目前**传了但 rag 里无人消费**（死字段，注释仍写"达到上限时不允许再追问"）——顺手清掉或改正注释。
- **"结论后不再强制收口"的后果要说清**：患者补充了一堆信息而模型始终不判定 `RECOMMEND` ⇒ 系统只给自然语言回应、**不弹重复卡**；患者仍可挂**上一张**卡 ✔（入口没被挡）。这是刻意选择——盲区榜会少一个信号，但那类信息本就落在 `chat_message` 里、回放看得到。

### ② 一条会话可以有多张卡 —— 回放要改成多卡

`RecordService.sessionDetail()` 用 `loadLatestRecords(...)` + 单个 `CardVO`。改成多卡：`CardVO` → `List<CardVO>`，前端按位置把卡插回消息流（`Chat.vue` 按 `entries` 渲染，天然支持多张）。

**必须改的理由**：不改就会出现**数据与展示不一致**（库里两条、回放一条），而回放是**取证**的地方——审核侧「证据链回放」吃的是同一个接口，看到的必须与当时发生的一致。

### ③ 统计按**患者实际挂号的那张**——现状口径已经就是它，不用改 SQL

看板三个 KPI 的口径核过了：Top-1 / Top-3 命中率的分母 = **`actual_dept` 非空**且非低置信度且未标「患者挂错」的记录；待审核按 `review_task`；盲区榜按低置信度记录。**没有任何"流失 / 未确认"指标**。

⇒ 多卡之后：患者只给其中一张挂号 ⇒ **只有那张进准确率**，其余不进分母、也不会被算成流失（没有那个指标）。**本票要做的只是把它写死并钉住**，不是改口径：

- 加一条断言/注释钉住"同一会话多条记录时，未挂号的那几条不进准确率分母"。
- **一个边角要顺手核对**：侧栏条目与会话详情里的"已挂号 / 挂到哪个科"目前取的是**最新一条记录**（`loadLatestRecords`）。若患者**挂的不是最新那张**（先出的卡没挂、后出的卡挂了、又问了第三张），侧栏的"已挂号"就会指错。规则定死：**"是否已挂号 / 挂到哪个科"以会话为口径、取"已挂号的那条记录"**，不是"最新那条"。实现时逐处核对（`toItem` / `SessionDetailVO` / 侧栏卡片）。

### 不受影响的（已核过，别顺手改）

- **盲区榜 / 根因分布 / 回流**：仍按 `guide_record` 逐条进、逐条挂 ✔ 不变。
- **侧栏与归档**：仍按会话铺开 ✔；条目"结论=最新一张"的口径不变（只有"已挂号"那个字段按上面那条规则取）。
- **`resolveParts` 的丢弃规则**：不变（非首轮一律丢弃，有日志）。
- **工单 01 的判定收口**：不变（`firstTurn` 仍只算一处）。

## Comments

**为什么这次不能只改前端**：`continuable()` 是后端状态机的判据，前端无从替代——前端能做的只是"不要再拿它猜"（工单 01 已经做了）。这条口径改的是**领域模型的边界**，所以它必须动后端，也必须同步 `CONTEXT.md`。

**为什么它比看上去大**：'一次会话 = 一次就诊"这条模型撑着侧栏按会话铺开、归档、准确率分母、回放取证四处。改边界 ⇒ 这四处都要过一遍；本票把查到的四处**逐条列在影响面**里，就是为了不让它们在下游变成惊喜。

**建议的实施顺序**：先落工单 04（纯收尾，不依赖本票），再落本票——本票改完，04 的门禁分支只需把"结论后回等待态"那段删掉即完成对接。
