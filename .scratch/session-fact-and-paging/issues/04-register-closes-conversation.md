# 04: 挂号成功 = 这次就诊收尾——跳回对话页，这段转只读，想继续就开新会话

**What to build:**

`confirmRegister` **成功回调里成对做两件事**，然后跳回对话页：

1. `chat.reset()` —— 它不再是"当前会话"（`sessionId` 清空、消息流清空）；
2. 把**刚结束的这条会话**按"只读回放"打开（复用既有的 `replay` 态：底部换成只读条、结论卡不渲染「去挂号」按钮）。

配套：挂号页在加载时按 `recordId` 查一次挂号状态，**已挂过号就直接渲染成功态**（而不是可点的「确认挂号」）。

**为什么这么做（用户 2026-10-14 定案）**：挂号成功后回到对话页，旧对话还挂在那儿、旧 `sessionId` 还在（Pinia 跨路由不丢），患者在同一页继续说话，后端才按状态机悄悄开一个新会话——**患者看到的是"同一条对话"，系统做的是"另一次就诊"**。用户原话：「挂号完后这轮对话直接结束开启新的对话页面，而不是依靠在旧的对话页面，这样才符合逻辑」。

**为什么必须在挂号成功那一刻做（而不是"回到对话页时判"）**：

1. **这是唯一的确定信号**：后端就在这一刻把会话置 `closed`（`CONTEXT.md` 的领域规则：「会话已出导诊结论或状态为 closed 后的下一句输入 = 新会话」）。
2. **只有一个落点**：`chat` store 是跨路由持久的，页面级状态（门禁/声明）随 `Chat.vue` 重新挂载天然归零 ⇒ 不需要跨组件传标记、不需要路由参数。
3. **不依赖"下一句输入"**：患者挂号后不返回也成立，下次进来就是新咨询。

**已定的规则**（逐条来自 2026-10-14 的四轮对齐）：

1. **成功后立刻跳回对话页**：不再停在挂号页等点击；"挂到哪个科室 + 位置"**跟着结论卡显示**（回放态那张卡本来就有就诊信息行，后端 `actualDept` / `actualDeptLocation` 已具备）——不为它新造一屏。
2. **只读 = 复用回放态**，零新部件：底部 `.p-chat__lock`（只读条 + 「开始新的咨询」）、结论卡的「去挂号」按钮 `v-if="!replay"` **本就不渲染**。不新增状态、不新增组件。
3. **只读态是内存态**（用户 Q3 定）：刷新页面回到普通空状态——那确实是新的一次就诊；刚才那段在左侧记录里可回放，不丢。
4. **只读条文案**：`本次挂号已结束 · 记录在左侧，随时可回看`；按钮沿用 `开始新的咨询`。**光清屏不解释**，患者会以为刚才的结论丢了。
5. **只清成功这条路径**：挂号失败（已挂过号 / 科室停用 / 网络）一律不清，那段对话与声明都还在，可继续用。
6. **挂号页后退**（用户 Q4 选 a）：加载时按 `recordId` 查挂号状态；已挂过 ⇒ 直接显示成功态（科室名 + 位置 + `register_success`），**"确认挂号"按钮不出现**。
7. **不动后端状态机**：本票只新增一个**只读查询**（按 `recordId` 拿挂号状态），会话 `closed` 语义一个字不动。会话边界本身的改动见工单 05。

**要落的点**

- `SimRegister.vue`：成功回调里 `chat.reset()` + 记住 `sessionId`（`chat.sessionId` 此刻还在 store 里，挂号页直接读得到）→ 把"要回放的会话"交给对话页（**走 store 的内存态，不走 URL query**——走 query 会让刷新也恢复只读态，与规则 3 冲突）；成功页按钮文案 →「开始新的咨询」。
- `Chat.vue`：挂载时若 store 里有"待回放的已结束会话"，就按既有回放流程打开它（`replay` 态）。
- 只读条文案：`历史记录 · 只读` → 本次专用句（规则 4）。**注意**：回放**历史**会话时仍用原句——两种进入方式要能区分，别把历史回放也说成"本次挂号已结束"。
- 后端：`RecordService` 加"按 recordId 查挂号状态"的只读方法 + 一个 `GET` 接口（`chat` 模块，返回 `booked` / `actualDept` / `actualDeptLocation`，字段已在 `RecordDTO` 里）；前端 `api/chat.js` 加对应调用。
- `.claude/rules/前端设计方案.md` §4.2 补两条：成功即跳回对话页并转只读；后退进挂号页显示成功态、不显示可点的确认按钮。
