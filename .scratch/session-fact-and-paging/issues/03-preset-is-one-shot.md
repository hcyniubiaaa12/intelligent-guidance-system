# 03: 快捷词的预选是「一次性」的——用完必须清，否则它会跟着之后每一次开图

**What to build:** `Chat.vue` 里 `mapPreset`（快捷词带来的预选）在覆盖层关闭时清空。判据一句话：**预选只服务"点了快捷词之后紧接着打开的那一次图"**，用过即失效。

**怎么发现的（门禁探针实测，2026-10-14）**：工单 01 修好之后，出结论 → 第 2 次就诊 → 从 composer 的小按钮手动开图 → 只点了「皮肤」，而请求体里的声明却是 `parts: ["腰","皮肤"]`、句子是「腰、皮肤不舒服」。原因：`onQuickPick` 把 `mapPreset` 设成 `{region:'waist', word:'腰'}` 之后**没有任何地方清它**，而 `BodyMapOverlay` 每次打开都无条件应用 `props.preset`（`state.picked = [preset.word]`）——于是第 1 次就诊用过的快捷词，在第 2 次就诊里被"补选"进了声明。

**为什么以前没人发现**：这条路径上的声明**本来就是被丢掉的**（工单 01 修的那个 bug）。声明丢着的时候，"预选残留"顶多让图上多亮一块；声明真能带出去之后，它就变成**喂给模型的错误位置事实**（患者以为只说了一处，模型看到两处）。

**已定的规则**：

1. **清空点是"覆盖层关闭"**（不是"提交"）：患者点了快捷词又取消（关掉浮层）时，那个预选同样不该留到下一次——否则"取消过"的意图会在几分钟后自己生效。
2. **放在 `Chat.vue` 里清**（`watch(mapOpen, open => !open && (mapPreset = null))`）：`mapPreset` 是本页的状态（谁的状态谁清），覆盖层只负责"照 preset 预选一次"，不该反向清父组件的状态。
3. **不改覆盖层**：它"每次打开都应用 preset"的行为本身没错（父组件给了就照做），错的是父组件把一次性的东西放成了常驻。

**验收**

- [x] 覆盖层关闭（提交或取消）后 `mapPreset` 为 `null`
- [x] 探针复跑：第 1 次就诊用快捷词「腰背酸痛」→ 第 2 次就诊手动开图只点「皮肤」⇒ 声明必须是 `["皮肤"]`（不再是 `["腰","皮肤"]`）
- [x] `npm run check` 通过、build 通过

**Blocked by:** 无（但与工单 01 是同一片区的状态问题：**都是"前端把一次性的东西留成了常驻"**）

**Status:** resolved

## Comments

**这不是工单 01 引入的**：`mapPreset` 从快捷词落地那天起就没清过。工单 01 只是把这条路径上的声明从"丢掉"改成"送达"，于是残留预选第一次变成了**会影响结论的输入**。记在这里是为了避免回看时误判成工单 01 的回归。

**顺带确认一件容易误判的事**（探针原本写了一条错断言，已改正）：第 2 次就诊的首条请求**仍然带着旧会话 id**，这是对的 —— "是不是新会话"由后端状态机定（`continuable()`：出结论或挂号成功后不可续聊），前端保留旧 id 只是因为它还显示着上一段对话。别把这条当成 bug 去"修"。
