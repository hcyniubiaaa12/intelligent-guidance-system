**对照实验（关键证据）**：用 `git archive fb56ef5` 把 2026-11-14 基线（无判重段的提示词 + 82 条）导出到临时目录，同机同 Key 跑两次：**F1 = 0.844 / 0.803（均值 0.824）**，背景 0.800 / 0.720，手术 0.889 / 0.400，偏好 0.455 / 0.571，空期望 16/16。

**判定**：当前提示词均值约 0.78 vs 基线约 0.82，**是回归**。根因不是工单猜的「旧清单把输入撑长」（82 条样本的 `{remembered}` 就是「（无）」三个字），而是系统提示词新增的约 11 行判重规则让 value 更容易带补充信息（背景/手术的 FP 从 9–12 升到 17，如「2型糖尿病（约五年）」「哮喘（换季易发作）」「胆囊切除术（微创）」）；规则 2「update 时 value 取信息量更大的那个」很可能外溢到 `new`。偏好反而上升，符合预期。另外这次实测还发现：**门禁本身贴噪声边缘**——旧提示词今天两次就差了 4 个点（0.844 / 0.803），单次 0.805 分不清「没回归」和「回归」。

**建议（不在本工单范围）**：提示词侧把规则 2 限定为「仅 action=update 时」，并重申 `action=new` 时 value 仍取最短可独立表达的事实、不附带括号补语/病程/诱因；改完后至少跑 2 次取均值再判门禁。落库与校验代码不需要动。

团队决定不做「把已知降级推给后续工单」这一步，授权在本工单内改 `prompts.yml` 的 `memory-extract.system`。只改了两处、语义未动：

1. 规则 2 加作用域：`2. update 时 value 取…` → `2. **仅当 action=update 时**，value 取…`；
2. 规则 2 之后补两句：`action=new 或 skip 时，value 仍按你平时的抽取口径写——**最短能独立说清这件事的表述**，不要为了显得完整而加括号补语、病程年限、诱因或用药（那些属于当次对话的细节，不是长期事实本身）。`

`MemoryPromptsProtocolTest` 的断言（`信息量更大` / `拿不准就 new` / `action=new` / `target=null` / `永远不是同一件事`）**一条都不需要改，测试直接通过**。`memory-merge` 与 user 模板未动。

**样本侧的两处修正**（属评估口径，不是放宽门禁）：

- D08 原句「先告诉我该去哪个科」与旧值「先说结论」是否同一件事有歧义；改成「还是先说结论，然后再讲原因」后，update / target=3 不再靠猜。
