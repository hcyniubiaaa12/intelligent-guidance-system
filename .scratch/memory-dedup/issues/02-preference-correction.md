# 02: 偏好改口生效（第一根 tracer bullet）

**What to build:**

患者改口之后，偏好以新说法为准，而不是两条并存互相打架。

完成后：患者先说「我希望你讲慢一点」，系统记住；过一会儿再说「你讲话不要太慢了」，系统把旧那条**原地改掉**（不是删旧插新），值变成新说法、原话变成新那句。开一个新会话提问题，助手的语速按新说法走，而不是还慢吞吞的。

这一刀切穿提示词 → 解析 → 校验 → 落库分派 → 注入五层，是第一个能给患者演示完整效果的切片。

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 偏好校验放宽：取消「值必须逐字出现在原话里」，改为「原话必须整体出现在本轮对话原文里」——偏好允许改写表述，但依据不能是编的
- [ ] 稳定背景与档案候选的严格判定（否定句 / 禁止推断 / 当前主诉 / 档案事实兜底）**原样不动**，只有偏好这一条放宽
- [ ] 落库层按 action 分派：`new` 走既有插入；`update` 原地更新旧行（id 不变，改值 / 原话 / 置信度 / 观察时间）；`skip` 零写入
- [ ] `skip` 不写审计——值没变却刷新观察时间，会让这条无理由地跳到「我记住的」列表最前面
- [ ] `update` 的审计记为 `update`（old→new），能看出这是一次改口，而不是两笔互不相干的删除与新增
- [ ] 取旧记忆的时机在「患者更正收回」之后，避免把刚被置失效的记忆当成判重候选
- [ ] 判重整体异常时降级为 `new` 落库，不丢本批
- [ ] 满额合并保留为兜底，并在 `update` 时让原话直接取新原话（修掉「改写后挂上旧原话」的缺陷）
- [ ] 患者端界面不变，不新增「已更新」标记
- [ ] 测试：校验层（改写放行 / 原话不在对话原文则丢 / 背景改写仍被挡）；编排层（三条路径、`update` 原地改且审计正确、`skip` 零写入零审计、判重异常按 `new`）
- [ ] 真机验证：新账号复现改口链路，换会话提问，助手语速确实改变；「我记住的」只剩一条
