# 01: 抽取协议扩展（预factor，行为不变）

**What to build:**

让抽取管线具备「看见已有记忆」的能力，但**先不改变患者看到的任何行为**——这是「把改动变容易，再做那个容易的改动」。

完成后：抽取入口可以收到一份「已记住的记忆」清单，模型输出里每条多出 `action`（`new`/`update`/`skip`）与 `target`（旧清单序号）；解析层把这两个字段读出来，遇到缺失、非法值或 `target` 越界时一律降级为 `new`。落库层**仍然不认 action**，照旧全插，所以对患者来说这一刀是空操作——但它把协议、解析、降级规则先钉死，让下一个切片的 diff 只剩「校验 + 分派」两件事。

同时顺手修一个既有缺陷：偏好满额时的合并提示词目前只把旧偏好的**值**送进去，却要求模型输出 key，模型只能自己编。改成送「键：值」。

**Blocked by:** None（可立即开工）

**Status:** ready-for-agent

- [ ] 抽取入口接受「已有记忆」入参；保留只收对话文本的重载，语义等价于旧清单为空（金标集与既有单测据此沿用，不必全改）
- [ ] `memory-extract` 提示词的 user 模板增加「已记住的记忆」段，按序号编号、分 `[偏好]` / `[背景]` 标注，无条目时写「（无）」
- [ ] `memory-extract` 提示词的输出协议增加 `action` 与 `target` 两个字段，并写死四条判重口径：同一件事才 `update`；`update` 时取信息量更大的值；相反说法以新说法为准；**拿不准就 `new`**
- [ ] 偏好与稳定背景两个草稿类型各增加 `action` / `target` 字段
- [ ] 解析层降级规则：`action` 缺失或不在三值之内、`target` 越界或缺失 → 一律按 `new`
- [ ] 合并提示词改造为接收「键：值」而非只有值；合并结果的 key 不再由模型凭空编造
- [ ] 落库层**保持不变**（这是本切片的验收前提：插入路径无从感知 action）
- [ ] 测试：解析层覆盖三种 action、`target` 越界、`action` 非法、旧清单确实进了 user 消息；合并提示词的占位符内容断言更新
- [ ] 既有 154 个用例全绿（不得因协议扩展而需要大面积改测试）
