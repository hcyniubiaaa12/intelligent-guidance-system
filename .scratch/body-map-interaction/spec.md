## Problem Statement

人体图本身画对了——正反两面、区域形状、选中填色都没问题。**问题全部出在"图与词之间怎么交代"这件事上**，而且每一处都会让患者怀疑自己点错了：

1. **点一处、亮两处，而且图上说的名字和系统记下的名字不一样。** 点"右大腿"，右小腿跟着一起亮；悬停气泡写着「右大腿」，落进已选栏的却是「腿」。患者看到的是"我点的是大腿，它记的是腿，还顺带亮了我的小腿"。
2. **点完图之后几乎没有反馈。** 只有一次 0.2 秒的背景脉冲，患者不知道"接下来该看哪儿"。窄屏更糟：细分词那一栏在图**下方**，点完常常根本不在视野里。
3. **悬停提示正好压在人体上。** 提示气泡画在图内部、固定在所点区域上方 22 个单位处，于是悬停"腹部"时气泡盖住的是"胸部"。实测在桌面渲染尺寸下，一个三字标签的气泡宽约等于**图宽的 38%**——因为小尺寸下文字被反向放大了 1.5–1.7 倍。它挡住的正是患者要指的地方。
4. **点一下图，整张图会缩小约 11.6%，而且此后一直变小。** 实测桌面下人体图渲染高 396.39 → 350.39（−46px），宽度不变；等比缩放系数从 0.652 掉到 0.576。根因不在图里：点选后页脚多出一行「已选」胶囊，页脚高 105 → 151，逐级把图区挤矮。窄屏不复发（图高写死），所以这个现象**只在桌面上、只在第一次点选时**出现——恰好是患者最没底的那一下。

合起来是同一件事：**患者在图上做的动作，和他看到的、系统记下的，对不上。** 图上不报出来他就没法确认自己点对了；报出来的又挡住了他要指的地方；点完还不知道下一步在哪。

---

## Solution

让"图上的字"就是"点一下会落下的词"，把提示移出图外，让图不再因为点选而变形，并在点完之后把视线引到该去的地方。

具体形态：

1. **图上的字与落词对齐。** 整条下肢在图上就叫「腿」、足部叫「脚」、髋部叫「髋」。图上的名字、已选栏的文字、读屏念出来的词，三处完全一致。为什么只能是「腿」而不是「大腿」：术语白名单里没有"大腿/小腿"，图上就不该承诺一个落不出来的名字。
2. **提示文字移到图外。** 悬停/聚焦某一块时，名称显示在**图上方固定的那一行**（原本写"点一下不舒服的位置"的位置），SVG 内部不再画任何文字气泡。零遮挡、零尺寸推算。
3. **图不再被页脚挤压。** 人体图的高度只由浮层/视口高度决定，与页脚内容无关——把窄屏那套已验证的写法上移到桌面。同时把「已选」胶囊行收编进侧栏，页脚回归恒定高度。
4. **点击反馈只用不改变几何的手段。** 删掉"正在编辑"描边环的缩放动效；高亮一律靠颜色、描边粗细与色条。
5. **点完把视线引过去。** 侧栏「具体位置」标题直接显示该区域**实际落下的词**（"已记录：腿 · 可改成下肢"），细分词里当前生效的那一颗加标记；窄屏下自动把该段滚进视野。

患者拿到的是：点一下就知道自己选了什么、还能改成什么，且图不会骗他。系统拿到的是：与今天完全相同的提交物（`{ locations, sentence }`），**后端一行不改**。

## User Stories

### 图上的字就是会落下的词

1. 作为患者，我希望点哪一块、图上就写"系统会记下哪个词"，而不是一个查不到的名字，这样我才能确认自己没点错。
2. 作为患者，我希望整条腿不管点在大腿还是小腿，图上写的都是「腿」——因为系统记下的就是「腿」，不要让我以为它记住了"大腿"。
3. 作为患者，我希望已选栏里的字和图上写的字**完全一样**，不要一个说「右大腿」、一个说「腿」。
4. 作为患者，我希望读屏念出来的也是同一个词，这样用读屏的人不会拿到一份和界面不一致的信息。
5. 作为患者，我希望点一下就能选中，不要为了选中一个位置"先点开、再点一次"。
6. 作为患者，我希望点一下之后立刻看清"系统替我记下了什么词"，并且知道这个词是可以改的（「腿」能改成「下肢」）。
7. 作为患者，我希望再点一下同一块就能取消，不用去找别的按钮。
8. 作为患者，我希望选中的那一块看得出来被选中了，以便确认我点对了地方。
9. 作为患者，我希望"另一侧"这种状态在选中侧之后不产生我读不懂的视觉（本次不新增状态，见 Out of Scope）。

### 悬停与提示：提示不许挡人体

10. 作为患者，我希望鼠标移到某一块上时，这块的名称出现在**图外固定的位置**，而不是一个压在人身上的气泡。
11. 作为患者，我希望提示文字永远不会盖住我正在看的部位——我悬停"腹部"时不要让我看不见"胸部"。
12. 作为患者，我希望提示文字的大小稳定，不要因为浮层变小就被放得很大、把图占掉一大半。
13. 作为患者，我希望没在悬停时，那一行写的是引导语（"点一下不舒服的位置"），而不是一片空白。
14. 作为键盘用户，我希望用 Tab 聚焦到某一块时，名称出现在同一个位置。
15. 作为读屏用户，我希望聚焦某一块时**不会额外被播报一遍**名称——区域本身已经在播报它了。
16. 作为触屏用户，我希望按住某一块时能看到它的名称，松开就回到引导语。

### 点选之后的引导

17. 作为患者，我希望点完一块之后，界面明确告诉我"现在该看哪儿"。
18. 作为患者，我希望点完能立刻看到这一块下面有哪些更具体的说法，不用自己去别处找。
19. 作为患者，我希望窄屏上点完图之后，界面**自动把细分词那一栏带进视野**，而不是让我自己往下滚才发现有选项。
20. 作为患者，我希望侧栏标题就写着"已记录：腿"，而不是一个和已选栏对不上的区域名（"下肢"）。
21. 作为患者，我希望"当前生效的那颗细分词"在那一排里看得出来是哪一颗。
22. 作为患者，我希望点选后的高亮足够明显，让我不会以为"点了没反应"。

### 图不被挤压

23. 作为患者，我希望点选前后**人体图的大小完全不变**——点一下图就缩一圈会让我以为自己操作错了。
24. 作为患者，我希望第一次点选时图也不要突然缩小（这个现象只在第一次出现、之后不再变，反而更让我怀疑）。
25. 作为患者，我希望选中态的变化是"颜色和描边"，不是"缩放、位移"这类会让我以为图在动的东西。
26. 作为患者，我希望在窄屏上点选时图也不会跳动。
27. 作为患者，我希望浮层高度不够时是"图区自己滚动"，而不是"把图压小"。

### 已选与页脚

28. 作为患者，我希望随时看到"我选了哪些"，并且能一条条删掉。
29. 作为患者，我希望"全部清空"就在那一行已选旁边。
30. 作为患者，我希望页脚只承载"我的描述会变成什么"和两个出口，结构稳定、不忽高忽低。

### 窄屏

31. 作为患者，我希望能切换正面/背面，并且切换后我已经选过的东西还在。
32. 作为患者，我希望窄屏与桌面是**同一套语义**，只是排布不同——不要在窄屏上换一套说法。

### 维护者

33. 作为开发者，我希望"图上这块地方叫什么"和"点一下会落下哪个词"由**同一处**定义，不要两处各写一遍。
34. 作为开发者，我希望有人往区域表里加了一个图上没出现过的名字时，自检会红，而不是等患者点了才发现图上有个查不到的词。
35. 作为开发者，我希望**约束的锚点在「句子」而不在「图」**——真正要守的是"拼出的句子必须含术语词"（信息充足性门槛的要求），这样"图这块地方叫什么"就不会被误读成也要走术语表。
36. 作为开发者，我希望本次改动**完全不碰后端**，管理端的词表行为与今天一致。

## Implementation Decisions

### 职责边界（本次最先要钉住的一条）

- **命名是前端资产；受约束的是「句子」。** 区域在图上与侧栏显示的名字（腿、脚、髋、胸口……）**纯展示**，从不进入提交物。约束不落在"图上写什么"上，而落在**拼出的句子**：句子必须含术语词，否则过不了信息充足性门槛。可选词确实**取自**后端词表（`GET /api/chat/parts`）——但那是**数据来源**，不是对图上写法的约束。
- **据此把 `CONTEXT.md` 硬约束① 的锚点从「图」移到「句子」**：以图为锚的表述（"图上只出现术语表里已有的词"）退掉，改为"拼出的句子必须含术语词"。这是一处文档改动，与代码改动同批（见票 02）。
- **依据（两条代码事实）**：拼句（`sentence`）与结构化声明（`declarationLocations`）**只**消费可选词，从不碰命名——命名从来没有、也不应该有过进入句子的路径；区域表也从不把命名纳入任何校验。（原先有一道 `assertVocabulary` 顺带比过词表，该函数已删，见票 02。）
- `CONTEXT.md` 的「术语白名单」词条已经自承它承担"三类读者""同一个字段承担了两个领域的职责"。本 spec 的处理是**把命名从白名单里摘出来**，而不是给术语表加字段。

### 图上命名与落词同源

- 每个区域增加一个**命名**字段，取值一律是该区域的**首选落词**：头、胸口、腹部、背、腰、颈、髋、肩、上肢、手、腿、膝、脚。
- **"首选落词 + 词表过滤后的回落"这条规则从覆盖层上移到位置声明纯函数模块**，由图上命名与覆盖层共用。理由是本仓库已记录的坑："同一份事实只允许一处拼装"。
- **命名不随实时词表漂移。** 管理员停用「腿」时，图上仍写「腿」、落词回落到该区域剩余的「下肢」。这是接受的取舍——**命名稳定优先**；反过来的做法会让一次运营动作直接改写患者看到的解剖命名。
- 在**常驻断言脚本**（在 `frontend/` 下跑 `npm run check`，脚本是 `frontend/scripts/check-body-map.mjs`）里追加一条：**每个区域的命名必须是它自己可选词集合里的一员**（写法是"存在即校验"——命名字段落地那天它自动生效，不必回头改脚本）。它**不**参与术语表比对（那正是本次要废除的职责错配）。

### 人体图的交互面

- **删除画在 SVG 内部的文字气泡**，以及为它推算尺寸的那套"反向放大文字"逻辑——它把气泡放大到图宽的 38%，是遮挡的直接来源。
- 悬停/聚焦/按触时改为向父组件暴露"当前指向的区域"，由覆盖层在**图外的固定位置**渲染名称。取值链沿用原有优先级：按触 → 悬停 → 聚焦；无指向时回落显示引导语。
- 那个名称槽**不加 `aria-live`**：区域按钮本身已经播报了区域名，加上会变成重复播报。
- **删除"正在编辑"描边环上的几何动效**（缩放动画）以及为它存在的那套"强制重挂载、重放动画"机制。描边环本身**保留**，只保留描边颜色与投影。
- **图下缘的左右方位标注留在 SVG 内**不动：它贴着图的最下边缘、与脚部图形不重叠，不构成遮挡。因此文字尺寸自适应逻辑**保留**。

### 覆盖层

- **图高与页脚解耦（核心修复）。** 人体图的高度只由浮层/视口高度决定（定高 + 固定宽高比），**不再占用 flex 剩余空间**；窄屏那套已被验证不会复发的写法上移到桌面。页脚放不下时由**图区自身滚动**，而不是挤压图。
- **页脚回归恒定高度。** 把「已选」胶囊行与「全部清空」从页脚**移入侧栏**（面板里本来就有"已选"的语义），页脚只保留描述预览与两个出口。这样点选前后页脚高度一致，"图缩一下"的根因被从源头移除。
- **落词显式化。** 侧栏「具体位置」的标题显示**该区域实际落下的词**，文案形如「已记录：腿 · 可改成下肢」；细分词里**当前生效的那一颗**加标记。
- **点选后引视线。** 点选后侧栏对应段做一次更强的非几何高亮（比现有 0.2 秒背景脉冲更明显）；窄屏下把该段滚入视口。
- 所有高亮、脉冲、过渡**一律只用颜色/色条/描边**，不用 transform。

### 不改的东西

- 后端、管理端、术语表、部位声明的判据与提交契约**零改动**。
- 膝**保持独立区域**。原则：图上的区域是"落词的落点"，不是解剖学的完备划分——"选腿不含膝"是接受的，因为膝盖疼是会走独立科室的主诉。
- **不拆分图上的区域**：图上不区分大腿/小腿，是因为术语白名单里没有这两个词；在图上拆开只会制造新的"写着一个词、记着另一个词"。

### 提交与状态

- 提交物形状不变：`{ locations, sentence }`。本次只改"图上写什么、提示在哪、点完怎么引导"，不改"提交什么"。

## Testing Decisions

**好测试的判据**：只断言**外部可观察的行为**——不断言 CSS 类名、不断言私有方法被调用、不断言中间数据结构。对本次而言，"外部可观察"有两层含义：对纯函数是"给定选择状态，拼出的命名/落词是什么"；对界面是"**给定这次点击，渲染出来的尺寸是什么**"。

### 缝一（复用既有做法）· 位置声明纯函数

- **测什么**：区域→落词的映射；**图上命名与落词的对应关系**（每个区域的命名必须是它自己落词集合的一员）；首选落词的选择、以及该词被停用后的回落；拼句与方位前缀；全身词不加前缀；"说不上来"不进句子；结构化位置反查回区域。
- **先例**：本仓库历史上的做法是**临时 node 脚本跑断言、验完即删、不入库**（`evidenceReplay` 那套，当年跑了 17 组断言）——**本次不再照抄这个做法**：断言固定成常驻脚本（`npm run check`），因为"验完即删"意味着每次从零重推、成果不积累。由票 01 把它接进硬闸。
- **为什么这是最高缝**：它是唯一一个能用纯逻辑表达"图上写什么、落什么"的地方——覆盖层的排布与几何无法用纯函数表达，但**命名与落词的对应关系可以**，而本次四条问题里有两条（命名不一致、一处亮两处）正是这条对应关系。

### 缝二（人工 · 几何不变式）· 真机探针

- **测什么**：
  1. 点选前后人体图的渲染尺寸**宽与高必须完全相等**（当前桌面会矮 46px）；
  2. "正在编辑"环的动画名为 `none`、包围盒全程不变；
  3. SVG 内**不再存在**气泡节点；悬停某一块时图外那一行显示该区域的落词。
- **先例**：本次 grill 期间已用真实 Chrome + Playwright 实测过一轮，手法可复用——启动开发服务器 → 打开独立预览入口（免登录）→ 取 `getBoundingClientRect` 基线 → 点击一块 → 三个时刻复测 → **逐子元素比对高度变化**定位挤压链。桌面与窄屏各跑一次。
- **为什么必须做这一缝**：本次的缺陷**全部是布局与几何的连锁反应**——纯函数断言看不见它，而目视会漏掉"只缩 46px"这种量级。逐子元素比对是唯一能证明"根因已断"的手段。

### 缝三（人工）· 视觉走查

- **测什么**：悬停提示是否真的不遮挡、点完是否一眼知道看哪、窄屏自动滚动是否到位、"已选"移入侧栏后是否仍然随时可见、触控目标 ≥44px、响应式在 375–430px 不破。

### 不做的事

- **不为静态视觉引入快照测试**：收益低于维护成本。
- **不加"图上命名 vs 术语表"的越界校验**：那正是本次要废除的职责错配。

## Out of Scope

- **`is-soft` 状态没有图例说明**（选了某一侧之后，另一侧变成虚线的那个状态，图例里没有它）。
- **桌面双图并排下，"正在编辑"只在当前面那张图上显示**，另一面看着像丢了。
- **把膝并入「腿」的落词**，或把图上区域按词粒度拆开。
