# 13: 人体图与术语表解耦——字和词都由前端自持

**What to build:** 人体图**不再调后端的部位词接口**。图上写的字、图上可选的词，都由人体图自己持有（`bodyMap.js` 的 `REGIONS` / `PARTS`）——它跟「术语白名单」一点关系都没有。

起因（用户指正）：文档里一直挂着"图上可选的词取自术语白名单（`GET /api/chat/parts`）"这条关系，于是一整张图看起来都靠术语表撑着。工单 02 当时只把**命名**从白名单里摘出来（图上的字是前端资产），**取词这条路没动**——本票把它补上。

**为什么摘得掉**：那 29 个词在前端本来就有一份（`PARTS`），后端那条接口做的事只是"按管理端启停过滤一遍"。摘掉之后：

- 覆盖层的**"加载中 / 取不到 / 全被停用"三态、骨架屏、"暂时没有可选部位"死路、重试按钮**全部消失——没有网络就没有这些状态。
- `HumanBodyFigure` 的 `readonly` 与 `.p-body.is-loading` 只服务加载态 ⇒ 一并删除。
- `src/api/chat.js` 的 `listBodyParts` 零消费者 ⇒ 删。

**明确放弃的能力**（写出来，回看时别当它是漏做）：**管理端在术语白名单里停用某个部位词，不再影响患者端的人体图**。换来的是人体图自给自足。

**保留的唯一约束**——注意这是**对句子的要求**，不是"取词关系"：拼出的句子必须含医学术语才能过信息充足性门槛 ⇒ `PARTS` 这 29 词得与判定认得的部位术语是同一批。所以 `npm run check` 加了一条：**每个区域的每个词都必须在 `PARTS` 里**（两处都在 `bodyMap.js`，必须一致）。
