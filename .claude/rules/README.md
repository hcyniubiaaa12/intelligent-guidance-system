# .claude/rules 索引 —— 改哪一块，去读哪一份

> 本文件只是**路由**，不是规范。三份规范按需去读：改哪一块，读哪一份。

| 要改的东西 | 读它 | 里面有什么 |
|---|---|---|
| `entity` / `mapper` / `enums` / 建表与迁移 SQL | `数据库设计.md` | 各链路表结构（§1–§7）、枚举编码规范（§0）、逻辑删除与唯一键的坑（§0.1——不读会崩应用启动） |
| 患者端视觉与布局：`frontend/src/views/patient/`、`components/patient/`、`styles/patient.css`、`utils/` | `前端设计方案-患者端.md` | 方向 04「导诊伙伴」（手写 CSS、无组件库）：令牌 §2、关键部件 §3、页面骨架 §4、质量底线 §5 |
| 管理端视觉与布局：`frontend/src/views/admin/` | `前端设计方案-管理端.md` | 方案 B3「冷靛控制台」（Element Plus）：令牌 §2、布局部件 §3 |

两条读法：

- **两份前端方案只管视觉与布局**。功能、交互、数据流改动去看 `CONTEXT.md` 与《总体架构与链路设计.md》（总册；四条链路各在 `docs/architecture/` 的一册里）。
- **引用必须带文件名**：两份前端方案各有 §1/§2/§3，**同号不同义**——只写「§3.8」是歧义的。

新增规范文档时，把它登记到上表并写明触发条件（「要改 X → 读它」）。
