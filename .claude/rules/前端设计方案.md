# 前端设计方案 —— 患者端「导诊伙伴」（方向 04）+ 管理端「冷靛控制台」（方案 B3）

> 患者端（**手写CSS、无组件库**；管理端才用 Element Plus）已定稿为方向 04「导诊伙伴」，遵循第 1–5 章。**管理端本轮不动**，遵循文末章节。
> 视觉基准是 `前端方案/重设计-四方向草案/04-导诊伙伴-亲和陪伴.html`（三屏）——⚠️ **点时间产物、落地后不维护**，它记录的是"方向怎么选出来的"，不是可同步的源头。**冲突时以本文档为准。**
> 旧方案「临床纸感（A2）」的令牌与部件语言随本次改写作废，**不留两套并存**。

## 1. 设计定位

患者端是**导诊伙伴**的气质，不是纸质分诊单：把系统当成**一个陪你走完流程的人**。语气从"系统"改成"人"——不写"导诊完成"，写"下一步我陪您去挂号"。

唯一的记忆点是**推荐卡 = 一次郑重其事的交代**：科室名给结论、杏色读数块给把握程度、三条并列候选给范围、脚注给依据、**三步陪伴带**给出去处。其余一切保持安静。

三条视觉身份（识别度全在这里，实现时不许各自漂移）：

1. **暖沙三档明度** `--bg`→`--stage`→`--rail`，靠明度差分开区块，**不画边线**。
2. **柔和青绿是唯一主色**；**杏色只用于"读数与推荐"**（置信度、推荐标记、健康档案行），不出现第三个彩色。
3. **圆角 + 柔阴影 + 无衬线**（与旧方案的直角 + 细线 + 衬线相反）。凡想加回直角、加回复选框描边、改用衬线的，都是没跟上这次换皮。

### 2.4 间距节奏（基础单位 4px）

**允许的档位只有这十一个**：`4 / 8 / 11 / 12 / 16 / 20 / 22 / 28 / 32 / 48 / 50`(px)。写了别的值就是没跟上节奏——交付前用脚本把 `padding / gap / margin*` 数一遍。

- 组件内边距：常规 **16px**；小件 **12px 16px**；大卡 **20px 22px**；药丸小标 **4px 8px**
- 列表内元素纵向间距 **11px**；天分组内条目紧排
- 消息轮之间 **20px**；区块（消息流/步进条/输入区）之间 **28px**
- 舞台左右留白：桌面 **50px**，手机 **20px**；居中列的**文字**左右留白 **32px**

### 2.5 阴影与动效

投影统一走**暖色** `rgba(70,50,34,α)`，不用冷灰黑。

| 令牌 | 值 | 用在哪 |
|---|---|---|
| --sh-rest | `0 3px 12px rgba(70,50,34,.06)` | 静置：卡片 / 输入区 |
| --sh-raised | `0 1px 5px rgba(70,50,34,.07)` | 抬起 / 选中：侧栏条目 |
| --sh-primary | `0 4px 14px rgba(31,138,112,.24)` | 主按钮、输入区聚焦 |
| --sh-overlay | `0 16px 44px rgba(70,50,34,.14)` | 浮层（必须明显重于静置件） |

过渡：`0.18s ease`；`prefers-reduced-motion: reduce` 下关闭全部过渡与动画。

## 3. 关键部件规范

> 部件只在这里定义一次；§4 只讲排布与页面特有行为。
>
> **两类落点，别混**：**共享件**（被两处以上用）→ 类名与样式都写在 `patient.css`；**组件私有件** → 写在组件自己的 `<style scoped>` 里，样式随组件走。
> 组件在 `frontend/src/components/patient/`：`SideRail`（左栏）/ `EmptyState`（空状态）/ `ConclusionCard`（结论卡）/ `HealthProfileOverlay`（健康档案）/ `PatientSelect`（自绘下拉）/ `CopyButton`（复制按钮）。
> **拆分判据是「状态归谁」，不是「模板有几百行」**：会话列表归 `SideRail`、档案表单归 `HealthProfileOverlay`、结论的纯派生归 `utils/conclusion.js`、剪贴板兜底归 `utils/clipboard.js`；页面只留跨块的主线与 SSE 编排。纯函数与常量一律进 `utils/`（零依赖、能单独验）。

### 3.1 消息气泡与消息流

- **助手消息 = 直排文字不带底色**：左侧 30px 圆头像（`--leaf-soft` 底 + `--leaf-deep` 图标）+ 标签「陪 诊 助 手」（10.5px `--leaf-deep` 600）+ 正文（14.5px / 行高 2.0）。
- **用户消息 = `--leaf` 实心气泡**：白字、右下角小圆角、最大宽 64%、靠右。
- **追问（SSE `question`）**：形状同普通回复，**加左侧 3px `--leaf-soft` 竖线 + 16px 缩进**。这条竖线在本语言里表示"追问 / 引用"。
- **资料回答（SSE `info`）**：形状同普通回复，**只有标签不同**（「陪 诊 助 手 · 资 料」），**不套竖线**。**标签必须有**——不给标签，一段没有科室推荐的医学信息会被读成分诊结论。回放里按 `role=info` 还原，否则同一条消息实时看是「· 资料」、翻历史变成普通回复。
- **处置提示（SSE `notice`）**：**独立一泡** + `--alert` 色左侧 3px 描边 + `--surface` 底。收到时另起一泡、后续 `delta` 落到**新**气泡——提示与结论粘成一段就再也拆不开了。
- **错误（SSE `error`）**：`--alert` 描边块，文案说清原因与下一步，不道歉、不模糊。
- **流式**：`delta` 逐字填充**同一个**文本节点，不重建节点。
- **时间分隔**：消息流顶部一条居中 `--ink-3` 10.5px 时间。
- **一键复制**：四个消费点（用户气泡 / 助手回复 / 追问 / 资料回答）各挂一个，**桌面 hover 才浮现**、触屏常显；结论卡是"交代"，「复 制 结 论」**常显**（拼纯文本：科室＋置信度＋Top3＋说明＋依据＋免责）。成功变对勾 +「已 复 制」，1.5s 复位；`navigator.clipboard` 失败降级 `execCommand`。
- **每轮对话结束自动刷新左侧列表**（新会话 / 提问数 / 挂号状态都靠它），正在对话的那条高亮。

### 3.2 推荐卡（签名元素，链路 A 结论 + `result` 渲染）

结构自上而下：eyebrow「给 您 的 分 诊 结 论」→ 科室名（26px）+ **杏色读数块**→ **Top3 并列候选条** → 结论说明 → **判断依据脚注** → **健康档案行（有档案才渲染）** → **三步陪伴带** → 主按钮「我陪您 · 去模拟挂号」。

- **eyebrow**：`--leaf-soft` 药丸底 + `--leaf-deep` 10px 大字距 600。
- **杏色读数块**（替代旧的"印章"）：`--apricot-soft` 底 + `--r-sm`，数字 **19px** `--apricot-deep`。**读数只在杏色里出现**——这是杏色的专属用途。当前模板**只有数字**，所以共享样式按"只有数字"渲染。
- **Top3 并列候选条**：每行 = 序号圆点（`--rail` 底，Top1 用 `--leaf` 实心白字）+ 科室名（112px，超出省略）+ 轨道条（9px）+ 百分比。**Top1** 条用 `--leaf` 实心、科室名转 `--ink` 加粗、百分比转 `--leaf-deep` 加粗；**备选** 条用 `--leaf-line`、文字 `--ink-2`。
  - **顺序由前端再兜一次底**（`rankedTop3()`）：结论主体钉第 1 位，其余按 `pct` 降序、`null` 垫底。后端 rag 层已归一化，这里是防御性渲染——`rec_top3` 是只写快照，2026-10-02 之前落库的那批顺序确实是乱的，回放时仍要显示正确。**纯展示层重排，不改数据。**
- **判断依据脚注**：1px `--line` 上边框 + 「这 么 判 断 的 依 据」标签。每条引用 = 注号（`--r-xs` 药丸底 + `--leaf-deep`）+ 标题（一行加粗）+ 证据原文（截断 400 字，左侧 2px `--leaf-soft` 细线缩进，与追问同一套"引用"语言）。**只列模型真正引用的注**，但正文里每个注号都必须能在依据里查到。
- **健康档案行**（`.p-card__profile`）：**有档案才渲染**，位置在依据脚注之后、陪伴带之前。`--apricot-soft` 底 + 杏色文字，形如 `已参考您的健康档案：男、45-59岁、2型糖尿病、二甲双胍`。**必须与「判 断 依 据」并列但分开**——脚注区是医学证据（带注号、可溯源），这一行是患者自述背景（不带注号）；混在一处「判断依据」的口径就破了。数据来自**后端读档**（`result.profileText`），**不是模型输出**。
- **置信度口径**：以**后端下发为准**（`lowConfidence` + 阈值来自 `sys_config`），前端不写死阈值。`confidence` 为 `null` 时读数与 Top3 一律显示「—」（**不显示 0%**）并按低置信度处理；3 轮追问超限出低置信度结论时读数转 `--alert` 并追加"建议进一步咨询医生"。
- 卡片本体：`--surface` 底 + 1px `--line` + `--r-lg` + 静置阴影 + 20/22px 内边距。

### 3.3 三步陪伴带（签名部件）

结论卡里、主按钮上方的 `--leaf-soft` 底 + `--r-md` 带：抬头「接下来我陪您走这三步」（12.5px `--leaf-deep` 600）→ 一行三节点（12px 圆点 + 10.5px 标签）由连接线串起：`① 拿到结论 / ② 去挂号 / ③ 确认完成`。当前节点 `--leaf` 实心圆点 + `--leaf-glow` 光晕 + 标签转 `--leaf-deep` 600。

- **它是"邀请"，不是第二根进度条**：只在结论卡里出现**一次**，不跟页面走、不带百分比、不随滚动常驻。**全局的位置指示只有 §3.4 的步进条**——两者若在真机上读起来重复，先削陪伴带，不许反过来加厚。
- **只在实时对话渲染**（`!isReplay`）：回放是历史记录，"接下来我陪您走这三步"在那时是句假话。

### 3.4 步进条（全局位置指示）

输入区上方、`--surface` 底 + 1px `--line` 上边框：「① 导诊结论 → ② 模拟挂号 → ③ 确认完成」，10.5px + 圆圈序号，连接线 1px `--line`。当前步骤 `--leaf-deep` 600；进入挂号页后当前态后移，成功页三步全亮。**空对话时不显示**。三步与链路 C 埋点触点一一对应（`result_view` / `sim_register` / `register_success`）。

### 3.5 输入区（书写卡）

一整块"书写区"：`--surface` 底 + 1px `--line` + `--r-md` + 静置阴影，里面**上写字、下排一行**——左边「分诊建议，不能替代医生诊断」（10.5px `--ink-3`），右边一个 44px 方形 `--leaf` 发送按钮（白色向上箭头图标，非文字）。**按钮取 44px 而不是草稿的 34px**：§5 的"触控目标 ≥44px"是硬底线，视觉差一点点、够不着才是真问题。

- **聚焦时整块变 `--leaf` 描边**并转青绿阴影（`focus-within`），**不画内层输入框的边**。
- 输入框随内容长高，**120px 封顶后自己滚**。
- **chip 只填不发**：点一下填进输入框并聚焦，患者还能补一句"还伴着恶心"，也不至于误触烧掉一次模型调用；已有内容用「，」追加。
- **免责那句常驻在输入区里**（左下方小字）——医疗产品该一直看得见。
- placeholder 用 `--ink-3`、说人话：实时「还有什么想补充的，慢慢说…」、空状态「说吧，我在听…」。

### 3.6 空状态（导诊卡，不是一句客套话）

一屏**邀请式的接诊卡**，与输入区一起在舞台里垂直居中。**两个形态**（部位声明必填，工单 05）：
`awaiting`（等待声明）/ `locked`（已声明——选了部位与点了「说不清在哪儿」**都算**，区别只写在回执文案里）。

1. 问候行：44px `--leaf` 圆角方块（助手头像）+ 26px「您好，我是您的导诊助手」+ 副标题「先在人体图上点一下哪里不舒服，我帮您判断该去哪个科；细节我们后面慢慢说。」
2. 「说 清 这 三 件 事 就 够 了」+ **三个部件卡**「① 部位 / ② 时间 / ③ 感觉」（`--surface` + `--line` + `--r-sm`）。**两个形态里都常驻**——它是"要说清什么"的说明。① 带**「必填」徽标**（`--leaf` 实心胶囊）+ `--leaf-soft` 底 + `--leaf` 描边；②③ 带**「随后问」**角标（描边胶囊）。①的值：等待态「在图上选，或说"说不清"」、锁定态「左腹部 ✓」。
3. **等待态专属——大按钮**「在人体图上选部位 / 第一步 · 大约 10 秒」：这一屏唯一的实心主色块（`--leaf` + `--r-md` + `--sh-primary`，内嵌 38px 半透明白图标格 + 右端箭头）。它是必填的第一步入口。
4. 一条示例句（`--surface` 底 + 左侧 4px `--leaf-soft` 竖线，与追问同一套语言）。
5. **等待态专属——快捷词**：「常 见 主 诉 · 点 了 直 接 在 图 上 选 中」+ 5 个 chip（肚子疼 → 腹部 / 头疼头晕 → 头 / 心慌胸闷 → 胸口 / 腰背酸痛 → 腰 / 皮肤起疹 → 皮肤，箭头指向预选词）：点了**直接打开人体图并预选**对应区域——让必填变成省事，不是拦路。**「发热咳嗽」刻意不在列**：它对应不了任何体表区域，留着等于给必填开后门（这类主诉走「说不清在哪儿」出口）。词表在 `utils/bodyMap.js` 的 `QUICK_PICKS`，每个词都必须在部位词表内。
6. **锁定态专属——回执**：`--leaf-soft` 底横条「位置已锁定：左腹部 —— 接着说一句就行，剩下来的我来问。」；走了出口则是「没选位置，直接描述也行 —— 我会边听边判断该往哪个科靠。」（**连"没选"也写成完成态**——出口是完成声明的一种方式，不是失败）。下方虚线下划线的「位置选错了？重新选」→ 清空声明回等待态。
7. **空对话时输入框与接诊卡一起居中**（本页唯一"整块垂直居中"的状态）：在对话主体上用上下 `auto` 外边距——**空间不够时退化成 0**，不会把顶部裁掉。发出第一条后立刻回到常规排布。空对话时把输入框孤零零钉在屏幕底部、跟欢迎语隔几百像素，说不出哪里别扭但就是别扭。
8. **配套的门禁在 composer**（§3.6 与它是一体的）：等待态 composer 加 `is-waiting` 变体——`--rail` 底、输入框 readonly（placeholder「先在上面选好位置，就能开始说了…」）、发送禁用；**不是"能打字但发不出去"**（那会让人输完一整段才发现发不了）。锁定态解除。composer 里的「人体图选部位」小按钮（`--line-2` 描边 + 44px 触控）**等待态也保持可用**——结论卡出现后空状态已不在，禁掉它声明就没了入口。

### 3.7 左侧栏（会话目录）

`--rail` 底（桌面常驻 228px / 手机收成覆盖层），自上而下：

1. **标识行**：26px `--leaf` 圆角方块（内含三条由粗到细、由长到短的横线——画的就是推荐卡那组并列候选条，与产品最强的记忆点同源；SVG 内联）+ 「智能导诊」+ 副标题「您的导诊助手」+ **收起按钮**（仅桌面）。
2. **「＋ 开始新的咨询」**：`--leaf` 实心 + `--r-sm` + 抬升阴影，hover 转 `--leaf-deep`。**位置在标识行之下、抬头之上，不放底部**（会话一多侧栏就长，底部的按钮够不到）。加号用**半角 `+`**（全角「＋」在该字号下偏大偏靠上）。
3. **抬头 + 两个 tab**：`「我 的 就 诊 · N 次」` + `全部对话 / 挂号历史`（药丸 tab，选中 `--surface` 底 + `--leaf-deep` 600）。**次数是列表的量词不是数据**：跟在标签后面同一个 10.5px 标签里、数字用 `--leaf-deep` 600，**不要另起 19px 大数字**（会和 12.5px 的会话条目抢层级，把"我一共来过几次"抬成第二条主信息）。切 tab 时数字跟着切口径。
4. **按天分组的会话条目**：天头 `.p-day`（`--ink-3` 10px 大字距）+ 条目（主诉首句超出省略 + 「N 问」+ 时间）。**选中行 = 白卡片压上去**（`--surface` 实底 + 抬升阴影 + 主诉转 `--leaf-deep` 600）——层次靠明度差，**不是靠加边框**。某天超 10 次折成最新 2 条。
5. **底部用户区**：一张 `--surface` 圆角卡（`--r-sm`），三件事排成**两行**——圆形头像（昵称首字，`--apricot-soft` 底 + `--apricot-deep` 字，28px）；右列上下两行：**昵称**（12.5px 600、`--ink-2`，是"看挂号历史"的入口）+ **「健 康 档 案」**（10px `--ink-3`，副标式的第二入口）；最右端**退出**（10px `--ink-3`，hover 转 `--alert`）。
   - **静息态一律不画下划线**（四条带虚线的文字并排会把底卡变成一堵字墙），可点性靠 `cursor` + hover 变色给。
   - **昵称用 `--ink-2` 不用 `--ink`**：它是身份标识不是要读的内容——底卡已经靠白底 + 主色头像被凸显了（正文色是 `.p-i__x` 的 `--ink`）。
   - **两行贴着文字高度排**（`min-height:0` + `line-height:1.3`），**触屏才补到 44px**——§5 的"竖着叠的次要入口"豁免。**把两行撑开的是行高不是 gap**：1.3 下半行距各约 2px，跟全局 1.85 走就成"两行之间隔一条带"。底卡实测 **212×57**（草图那张约 51px）。
6. **可收成精简轨**：收起按钮在标识行右端，收起后 228px→**123px** 的横向一条：左是**标识**（它本身就是展开入口）、一道分隔线、再是展开图标与 ＋ 图标；轨贴左上角。**三大件都不许丢功能**（标识可展开、展开图标可展开、**＋ 仍要能开新咨询**）。状态存 localStorage，宽度 `0.2s` 过渡。
   - **收起宽度写定值 123px，不用 `fit-content`**：`fit-content` 不参与 `width` 插值，过渡会退化成瞬时跳变。定值算得出来：24 + 26 + 4 + 1 + 4 + 30 + 4 + 30 = 123。配 `min-width: fit-content` 兜底。
   - **手机端的会话目录是浮层语言的唯一例外**：它不套 `.p-overlay`——那不是"浮层内容"，而是同一块侧栏在窄屏下的形态（底色仍 `--rail`、内容一字未变），只在外面加一层 `--mask`。**除它之外，任何浮层都必须用 `.p-overlay*`。**

### 3.8 浮层语言（抽屉 / 覆盖层，全端统一一套）

患者端**只有一种浮层语言**，健康档案抽屉与之后的人体图覆盖层都复用它，**不新造第二种**。

- **部件落点**（共享件，在 `patient.css`）：`.p-overlay`（遮罩）/ `.p-overlay__box`（面板）/ `.p-overlay--drawer`（贴边满高变体）/ `.p-overlay--wide`（宽表单变体 560px，健康档案用它）/ `.p-overlay--xl`（超宽 760px，左右分栏）/ `.p-overlay--tall`（`height: calc(100vh - 40px)`，图要占到视口多数高度）/ `.p-overlay__head` / `__title` / `__sub` / `__close` / `__body` / `__foot`。
- **进出节奏也收在这一组里**：面板自带「淡入 + 8px 上浮」（纯 CSS 动画，任何调用方白拿）；遮罩的**淡出**只能靠调用方的过渡组件（CSS `animation` 只管挂载、管不到卸载），所以 `.p-fade-enter-active / -leave-active / -enter-from / -leave-to` 四个类也放在 `patient.css`——页面只写 `<Transition name="p-fade">`，**不自己定义时长与缓动**。
- 结构：全屏遮罩 + 居中/侧滑的 `--surface` 面板（`--r-lg` + `--sh-overlay` + 1px `--line-2`），右上角一个「关 闭」文本按钮。遮罩用**暖色** `rgba(46,38,32,.42)`。
- 浮层是**页面内浮层、不 teleport**，因此可以安稳吃 `.patient-root` 上的令牌（EP 那边必须挂 `:root` 是因为弹层 teleport 到了 body）。
- **人体图覆盖层**（`BodyMapOverlay.vue`）：变体是 `--xl` + `--tall`（左右分栏要宽、图要高）。左图右选栏：图上是正反两面**同一轮廓、只换躯干那块**（正面胸腹 / 背面背腰），免得患者在两张图之间找不到"我的头"在哪儿；选中态**填实 + 深描边两条一起变**（只变色在浅底图上读不出来）。图上"形"是组件资产、"词"是后端的（`GET /api/chat/parts`），**管理员停用一个词这里立刻就不给了**；反过来新增部位词图上不会出现新区域——刻意取舍。窄屏（`@container` 按**浮层自身宽度**判，不按视口）改成上下且**整列一个滚动容器**、两块各自按内容取高。
- **健康档案抽屉**：入口在**侧栏底部用户区**，副标题写明"选填 · 帮分诊结合您的既往情况，随时可改"。表单三块：**性别 / 年龄段 = 自绘下拉**（§3.9，选项由读回体 `options` 下发，**前端不写死**）；**既往病史 / 长期用药 / 过敏史 = 多选标签 + 「其他」自由文本**（标签来自 `GET /api/profile/tags`，**只列启用项**）。**剩余额度实时显示**，上限由读回体 `limits` 下发——**到额度就写不进，不许静默裁剪**；后端二次校验兜底（**前端硬限只是提示，不构成约束**）。

### 3.9 表单控件：自绘下拉（`PatientSelect.vue`）

**不用原生 `<select>`**：原生控件外观由浏览器决定（Windows 灰凹面、macOS 圆角胶囊），与本方案的控件语言对不上，**同一套截图换台机器就变了**。

- **部件落点**（共享件，在 `patient.css`）：`.p-sel`（定位容器，**默认 `flex:1` 填满所在行**）/ `.p-sel__btn` / `.p-sel__panel` / `.p-sel__panel--up` / `.p-sel__opt` / `.p-sel__tick`（勾的固定位）/ `.p-sel__optx` / `.p-sel__none`；进出节奏用 `<Transition name="p-sel-rise">`。
- 触发按钮：`--surface` + 1px `--line` + `--r-sm` + 13.5px，右侧 11px 箭头（展开 `rotate(180deg)`）。hover 描边转 `--line-2`；**展开态是 `--leaf` 描边 + 一圈 4px `--leaf-glow`**（不是加粗边框，那会让控件突然变大）。无选中值时文字取 `--ink-3`。
- 选项面板：`--surface` + 1px `--line-2` + `--r-sm` + `--sh-overlay`，内边距 4px。**高亮（键盘正在走的那条）与选中（当前值）是两回事**：高亮 `--leaf-soft` 底，选中 `--leaf-deep` 600 字 + 一枚勾（勾占 16px 固定位，勾与不勾的行文字才对得齐）。选项 `min-height:44px`——**选项也是控件**。文案 `nowrap`。
- **面板高度与朝向由组件实测后写行内 `max-height` / 加 `--up`**，不写死在 CSS 里：它可能被祖先的滚动容器裁掉（档案浮层的表单区是 `overflow-y:auto`），所以量的是"到**最近那个会裁溢出的祖先**的可用空间"，装不下就**向上翻**；**不给高度下限**（为了凑一个下限而超出可用空间，正是"只露出一条、其余点不到"的成因）。
- **交互按 WAI-ARIA combobox + listbox**：焦点**始终留在触发按钮上**，面板里用 `aria-activedescendant` 指向当前项（不把焦点搬进 listbox）——Tab 的走向不会被面板劫持，`Esc` 能就地收起。`Enter`/`Space` 开合合一，`↑`/`↓` 移动高亮并循环，点面板外面收起（绑 `pointerdown` 而非 `click`，后者晚一帧会先触发外面的跳转）。选项由调用方下发，组件内**不写死任何词条**。

## 4. 页面骨架

### 4.1 对话页（主战场）

**桌面布局是 DS 式**：整页全宽、**侧栏贴窗口最左**，对话内容在舞台中央收 **1000px** 单列；**侧栏与对话区之间不画任何边线**（靠 `--rail` / `--stage` 的明度差，加线会把一整块暖沙隔成两间病房）。

- **顶栏整条不渲染**（`.p-chat__topbar` 仅 `<768px` 出现）：标题归侧栏标识行、用户区归侧栏底部，对话区顶上一条横线都不留。手机端仍保留顶栏（左「会话」、中标题、右昵称与退出）。
- **滚动条落在窗口最右缘，不在"对话框"里**：滚动容器 `.p-chat__thread` 是**整幅宽**，正文靠内边距 `max(32px, calc((100% - 1000px)/2))` 收成 1000px 居中。**`.p-chat__main` 的直接子元素必须在这条规则里列全**——容器一全宽，漏掉的那个（当时是只读条 `.p-chat__lock`）就自己铺满整幅、与相邻区块错位。滚动条**定宽 12px 并淡化**（`::-webkit-scrollbar`，thumb 用 `border:3px solid transparent` + `background-clip:content-box` 只画中间 6px），定宽是为了让右侧悬浮面板的把手能**精确**停在它左边；**不能同时写 `scrollbar-width`**——Chromium 一旦认了那个标准属性，这套伪元素整个失效。
- **「＋ 开始新的咨询」**：撤回放 + 清对话态（下一条消息即新会话）+ 光标落进输入框。

**三态**：实时对话 / 只读回放 / 空状态（§3.6）。

- **实时**：消息流按 §3.1，结论卡按 §3.2。
- **点会话 = 只读回放**：按原顺序铺开那一次会话，**卡片不带挂号按钮**（已挂号的在卡底补一行「就 诊　科室 · 位置」），输入区换成「历 史 记 录 · 只 读」+「开始新的咨询」。**一次会话 = 一次就诊，翻旧账不能往里写字**。
- **会话归档**：收纳不是删除——归档的会话挪到末尾「已 归 档 · N 次」折叠区，仍能点开只读回放、随时「取 回」。三条约定：
  - **入口是行内 hover 动作**（「归 档」/「取 回」小字，桌面 hover 浮现、触屏常显），与复制按钮同一套语言；动作是**兄弟 button 绝对定位**（`.p-i` 本身是 button，里面不能再放 button）；hover 时把行右侧的时间淡掉。
  - **主区与收纳区由后端分好**（`days` 只含未归档、`archivedDays` 单独一份且同样按天分组）：前端过滤会让每个天头计数重算；两个 tab 共用同一口径。
  - 在归档会话里又发消息 → 后端**自动取回**（"看一眼"不会，说话才算）。
- **问题导航**（本页签名次部件，悬浮面板）：**一行 = 这条会话里患者的一个问题**（不是会话之间的索引——会话之间靠左栏切）。
  - 收起时右缘只有一根 2px `--leaf-soft` 细把手（**热区是整条右缘，视觉只有那 2px**）；鼠标挨到就滑出 220px `--surface` 面板，抬头「用 户 问 题」+「N / 总数」，每条 = **问题正文首句（超出省略）＋右缘一根小横杠**，当前那条转 `--leaf`、横杠加长加粗。**自上而下 = 问题 1 → 最新一问**。实时对话时不显示。
  - **面板脱离布局流**（`absolute` 贴右缘）：进出回放时正文列一动不动。**面板自己滚**：`max-height: min(56vh,318px)`，放不下时内部滚 + 上下 10px 渐隐（滚动条不画）；**滚轮先滚面板、到头再转给正文**，是否溢出用 `ResizeObserver` 判。
  - **点条目**：正文滚到那一问并居中，**问题行左侧亮一条 2px `--leaf` 竖线**；`prefers-reduced-motion` 下滚动改瞬时。**触屏没有 hover**：点把手切换面板，手机端把手热区加宽到 34px、面板收窄到 186px。

### 4.2 模拟挂号页（链路 C 三触点）

- 与推荐卡同款部件语言：`--surface` 卡片 + `--line` 描边 + `--r-sm` 圆角。
- **推荐科室按推荐次序提到列表最前**：结论卡跳转用 `rec` query 带上 Top3 的科室 id（逗号分隔、按推荐次序），页面据此重排——**推荐科室标「我 们 推 荐」（top1，`--apricot-soft` 底 + 杏色 600 + 3px `--apricot` 左侧竖条）/「备选 N」（top2/top3，`--rail` 底 + `--ink-2`）**，其余保持后端原序。**主色描边专门留给「选中态」**——推荐与选中同时出现时要分得清"系统推的"和"我选的"。top1 的权威仍是 `deptId`，整串 `rec` 只用于排序。
- 选中态：`--leaf` 描边 + `--leaf-soft` 底 + 圆形勾选标记（`--leaf` 实心 + 白勾）。
- 位置信息跟在科室名下面（`.p-dept__loc`，11.5px `--ink-2`）：**每个科室自带自己的诊室位置**——号源一类的信息不在这一页的数据里，别在稿子上画了就当它存在。
- 选定科室 → 确认按钮 `--leaf` 实心 + 抬升阴影，文案全程「确认挂号」；成功页显示 `register_success`，步进条三步全亮。

### 4.3 登录 / 注册页

- 骨架：暖沙底上**单列居中卡**（`--surface` + `--r-lg` + 静置阴影），**无侧栏、无顶栏**。
- 顶部：26px `--leaf` 圆角方块标识 + 「智能导诊」+ 一句招呼（沿用 §3.6 的问候语气）。
- 表单：每项 = label（10.5px `--ink-2` 大字距）+ 输入框（`--surface` + `--line` + `--r-sm`；focus 转 `--leaf` 描边 + `--leaf-soft` 光晕）。错误态用 `--alert` 描边 + 一行说明，**不弹窗**。
- 主按钮 `--leaf` 实心圆角，与患者端主按钮同一档；登录 / 注册切换用文本链接（`--leaf-deep` + hover 下划线）。
- ⚠️ **本页没有独立参考稿屏**（草案 04 只出了三屏），骨架按本文档令牌推导，**落地时以真机为准**——若与既定令牌冲突，回来改本文档，不许就地造新值。

### 4.4 埋点触点

`result_view` / `sim_register` / `register_success` 三处延续本方案，**不出现第二种视觉语言**。

## 5. 质量底线

- **响应式**：375–430px 宽度内布局不破；触控目标 **≥ 44px**。
  - **44px 作用于"手指够得着的地方"**：手机端的一切控件与所有主操作（按钮 / 条目 / chip / 输入框）。
  - **已登记的两类豁免**（豁免要留痕，不许静默破例）：① **≥768px 才出现的桌面专用图标按钮**（如精简轨那两个 30px 图标）；② **竖着叠的次要入口**（侧栏底卡的昵称与「健 康 档 案」，各撑 44px 底卡就是 116px）。做法同源：**按输入方式分档**（`@media (hover:none)` 才补 44px）。凡加入豁免的类，必须在 §3 对应部件写明理由 + 在 `scripts/_skin_check.py` 的 `TOUCH_EXEMPT` 登记。
- **同名类不许两处实现**：共享件的外观只在 `patient.css` 定义一次，页面里**不允许**再写一条 `.p-xxx { background/border/border-radius/box-shadow/color/font-* }`。**例外是"上下文覆盖"**：带祖先状态的选择器（如 `.is-empty .p-composer`）——它描述"这个部件在这一处本来就该变样"，不是把共享件重抄一遍。
- **桌面端适配（≥768px）**：患者端保持手机版式不重排。**布局写在各页自己的样式里，共享件不带页面布局**：
  - **对话页**：整页全宽不居中——侧栏贴最左、对话内容收 **1000px**（§4.1）
  - **挂号页**：`1000px` 单列 + 左右 1px `--line` 细线 + 文字区块内边距 32px
  - **登录 / 注册页**：一张居中窄卡（`max-width: 380px`），**不收 1000px**——表单撑到 1000px 就没法看
  - 手机端全屏布局不变，一套 CSS 媒体查询实现，不做桌面专用页面
  - **为什么都不再是 720**：720px 在 1440／1920 屏上两侧各空 360／600px，像一张纸条贴在墙中央。加宽的边界由内边距守住——卡宽了，一行不跟着排长。
  - **纸面边界挂在最外层的容器上，不挂各区块**：区块在空状态下会收缩，边界挂在它身上就会断成两截。
- **键盘可达**：`:focus-visible` 用 `--leaf` 2px 描边；`prefers-reduced-motion` 下关闭全部动效与过渡。
- **文案**：动词开头、一句话说清、不道歉；用**第一人称**（"我陪您""说吧，我在听"），空状态是行动邀请而不是一句客套话。
- **本轮范围**：**管理端不动**（见文末章节）；患者端的功能、交互、数据流（SSE 八事件、三态、归档、只读回放）一律不改，只换视觉与布局骨架。

# 管理端设计方案 —— 「冷靛控制台」（方案 B3）

> 已定稿（B3，2026-09-19 Element Plus 接入后配色定案）。管理端（Element Plus · PC）全部页面遵循本章节。
> 参考稿：`管理端方案/管理B3-冷靛控制台.html`（看板与配色基准）
> B3 要点：主色向靛收敛（--blue #4468B8）；侧栏三级靛阶（底 --blue-side / 选中 --blue-deep / 主色 --blue）；补齐 EP 状态梯度令牌；coral/moss/err 与患者端同明度域，维持不动。

## 1. 设计定位

管理端是"运营控制台"的气质：信息密度高、数据波动一眼可见、异常状态醒目。核心任务是扫一眼找到待处理的事（审核队列）并看清数据趋势，不做纸质单据风格。

## 3. 布局部件规范

### 3.1 顶栏

- 白底 + 底部 1px 实线；左侧页面标题 + 细字距副标题（区间/口径说明）
- 右侧操作区：主操作按钮（实心 blue）+ 区间切换按钮（描边）；用户信息与退出登录统一在侧栏底部（见 3.2），顶栏不重复放置
- **区间切换只在"区间"有意义的页面出现**（2026-09-26 定）：它原先写死在顶栏、每个管理端页面都挂着，而这些页面上它没有任何作用——点下去毫无反应，却像是能改变数据口径，比假数据更误导。现在只在数据看板渲染（近 7 天 / 近 30 天），状态放**路由 query**（`?days=30`），刷新区间不丢、链接可分享

### 3.2 侧栏

- 蓝色实底（--blue-side），选中项深蓝底（--blue-deep）+ 白字；待办数用 coral 药丸徽标（margin-left:auto）
- hover 项半透明白底过渡
- **可折叠**：品牌区右侧挂 26px 圆形折叠按钮（白底描边、悬出侧栏边缘），在 212px / 60px 间切换（0.18s ease）；折叠态导航显示两字缩写居中 + title 提示完整名称，徽标与品牌文字隐藏
- **底部用户区**：圆形头像（昵称首字，半透明白底）+ 昵称 + 上箭头；点击展开 EP 下拉菜单「退出登录」，退出前 confirm 说清后果（返回登录页），确认后清 Redis 登录态、跳登录页并 toast

### 3.3 KPI 指标卡（看板）

- 四列网格；每卡 = 环形指标（SVG stroke-dasharray，56px）+ 右侧标签/数值/同比
- 正向数据环形与涨跌用 blue，警示指标用 coral（.warn）
- 同比行：↑ 蓝色 / ↓ coral / 持平 ink-2
- **环形弧长必须有含义**（2026-09-20 定）：比率类 = 比率本身；计数类 = 占同类总量的比例（如待审核/全部任务、盲区榜/全部记录）。禁止"数字越大环越满"这种没有口径的画法
- **无样本时数值与环内文字都显示「—」，不显示 0%**：0% 会被读成"全错"，与"还没有数据"是两件事；附注位改用文字说明（如"暂无已确认挂号的记录"）
- 环比只有在两期都有样本时才算：上期为空要说"不可比"，不伪造成一个涨跌数字；文案带样本量（如"↑ 2.1pp 环比 · 样本 42 条"）

### 3.4 图表面板

- 双列网格（1.6fr 1fr）+ 全宽表格区；面板 = 白底 8px 圆角 + 标题栏（1px 底线 + 右侧 hint）
- 柱状趋势：纯 CSS flex 柱（蓝=命中、coral=未命中堆叠），hover 柱透明度变化 + 标签加粗
- **柱高按窗口内最大值归一化、并留 20% 余量**（2026-09-20 定）：真实日量可能远超 100 条，把原始条数直接当百分比会溢出容器；20% 余量留给下方星期标签
- **缺数据的日期要补 0**：按日期轴对齐，不能让柱子错位
- 分布条：名称 + 圆角轨道条 + 右对齐百分比，hover 条微粗
- **无数据不画空图**：图表与分布条在无数据时换成 `.a-empty` 空态文案，并说清"为什么没有"（如"近 7 天还没有已确认挂号的记录""暂无归因数据（审核页标注根因后自动汇总）"）

### 3.5 数据表格

- 表头 11px 灰字浅底（wash）+ 1px 底线；行 hover 浅底色（wash）；行间 1px 线；EP 表格同此（--el-table-header-bg-color: var(--wash)）
- 状态用药丸 tag（wash 底蓝字 / coral 警示 / moss 成功）
- **只读展示表（如看板「最近导诊记录」）用本方案 `.a-table` 手写 + EP 分页**；带筛选/排序/多列操作的业务表（用户管理）直接用 EP 表格
- **分页：管理端每一个列表查询都必须能选每页条数**（2026-09-30 定）——统一 `layout` 走 `frontend/src/utils/pager.js` 的 `PAGE_LAYOUT`（`total, sizes, prev, pager, next`）；总数已写在面板标题栏 hint 里的页面用 `PAGE_LAYOUT_NO_TOTAL`（不重复显示 total）；`page-sizes` 取 `PAGE_SIZES`（10/20/50/100，与后端 `MAX_PAGE_SIZE=100` 对齐）。切条数的动作走 `applySizeChange(page, size, reload)`：**先把 `current` 置 1 再请求**，否则 el-pagination 的"当前页超出总页数就夹到最后一页"兜底会再发一次 `current-change`，两个请求并发、后到的赢，看到的页码可能不是第 1 页
- 科室蓝本那份列表做**前端分页**：它同时要供上传表单与筛选下拉使用，后端 `GET /kb/depts` 因此返回全量（科室本来就少）
- **空表不渲染表头**，整块换成 `.a-empty` 空态文案
- 操作列：实心（主操作）+ 描边（次要）+ 危险红字（删除），hover 均有过渡
- 点击行可展开子行（浅底）放扩展内容：审核表单（主科室选择、交叉科室多选、回流预览、确认入库/驳回/忽略）+ 每条代表样本各自的根因归因芯片；「审核过的桶」区（状态机里的**终态** approved/rejected/dismissed）提供「修正重审」入口
- **分区标题用人话，不直接甩状态名**（2026-10-07 定）：那一栏在状态机里叫「终态」，但它含 `dismissed`（"忽略"= 没审就关闭），标题叫「已审核」语义对不上、叫「已终态」又是内部术语 ⇒ 用「审核过的桶」。**词表里的术语不必原样出现在 UI 上，但内部注释/文档要能对回词表**
- **多种状态混在一张表里时给多选筛选**：终态表（已审核 / 已驳回 / 已忽略）配 `el-select multiple`，选中变化即重拉。**空选 = 不过滤**（前端就别发空参数）；筛完没有结果时，空态文案要跟"没有任何数据"区分开
  - **选项少于五六个就别开 `collapse-tags`**（2026-10-07 真机反馈后定的）：它只显示第一个标签 + `+N`，容器一窄那个 `+N` 就被裁掉，**看着就像"只能单选"**——用户据此以为多选没生效。宁可真占宽度
  - 筛选框左侧**不要并排长文案**（如"共 N 个 · 修正重审回到待审"）：它会把筛选框挤到刚好放不下标签的宽度
- 筛选值的选项与表格里的状态标签**共用一份定义**：同一个 code → label 只写一处，否则筛选框和表格迟早对不上

### 3.6 tab 切换

- 面板顶部 tab 行：底边 2px 透明，选中变 blue + 加粗；hover 变 blue

### 3.7 敏感词与违规处置（用户管理页两个 tab）

**敏感词库 tab**

- 顶部「处置规则」面板：统计窗口 / 禁止词警告阈值 / 禁止词禁言阈值 / 观察词警告阈值 / 禁言时长（数值输入 + 范围与默认值提示）+「保存规则」。与词表**同页**——"哪些词算违规"和"触发多少次会怎样"是一件事的两半；规则拉取失败只降级成提示条，不阻断词库维护
- 词表列：词 / 类型 tag（禁止词 coral 警示、观察词 wash 蓝字）/ 累计命中 / 状态 / 操作
- 操作：编辑（描边）、停用（描边）、转禁止词（实心 blue，观察词行）、删除（危险红字，confirm 走逻辑删除）
- 顶部操作：单条添加（实心）、批量导入（描边，上传 txt）、导出备份（描边）

**账号管理 tab**

- 表格上方一句口径提示：窗口长度与三个阈值**从配置读**，不写死数字——写死就意味着改了阈值页面开始撒谎
- 列：用户名 / 昵称 / 角色 / 状态 / **近 N 分钟触发**（禁止 x · 观察 y 两枚 tag，为 0 用 info 弱化）/ **处置**（禁言中用 danger tag 显示"禁言至 HH:mm"；否则"已警告 n 次" warning tag；都没有显示「—」）/ 注册时间 / 操作
- 操作：明细（弹窗：窗口内按词聚合的命中 —— 词/类型/词次/最近命中；+ 处置记录 —— 级别/触发类型/命中÷阈值/窗口/时间）｜解除禁言（仅禁言中的行显示）｜封禁/解封
- **窗口口径与后端同源**：页面上的"近 N 分钟"取自同一份配置，不会出现"页面按 30 分钟统计、后端按 60 分钟判定"

### 3.8 交互规范

- 全部交互 0.18s ease 过渡；`prefers-reduced-motion` 下全部关闭。**例外——多选 chip 的选中态不加过渡**（2026-10-07 补，起因：审核页根因 chip）：`transition: all .18s` 把"点没点上"变成一段 180ms 的渐变，管理员以为没选中、再点一次反而取消了。**选中是状态，不是动画**；`Review.vue` 内已对 `.a-chip` 关闭过渡（其余页面暂沿用全局过渡）
- 操作反馈统一用底部居中 toast（墨色底白字，2.2s 自动消失）
- 破坏性操作先 confirm，文案说清后果与执行顺序
- 进度条统一 5px 圆角轨道：进行中 blue / 异常 coral / 完成 moss
- **进度条不许撒谎**（2026-09-26 定，用于知识库入库进度）：只显示**真实知道的量**，不把两段耗时差着数量级的阶段拼成一根 0–100% 的条——那样必须拍一个分段比例，而它在任何一份文档上都不会对，症状就是"卡在 60% 不动"，人读成"卡死了"。知识库解析的显示按阶段走：「解析中 37%」（外部服务给的真百分比）→「正在切分」→「写入 38 / 42」（自己的计数）→「已完成」。**不显示任何推算出来的总进度**。
  > 为什么这条重要到要写进规范：进度条几分钟不动，管理员会以为没点上、再点一次——那正是「同一文档同时跑两次入库」的触发条件（白付一次解析费）。**显示真实量是在压制一个真实会发生的误操作。**
  > 同理，解析阶段不可能知道会切出多少片（那是切分的结果），所以「15 / 38 · 解析中」这种显示是编的。**2026-09-26 起知识库页已按本条接通真实接口**（那条假数据连同整页假数据一起清掉了），页面实现见 `KbManage.vue`：`progressOf()` 一个函数决定文案与进度条，`ratio` 为 `null` 就不画条——**不画比画错强**。
- 侧栏页面切换、tab 切换不刷新整页
- **多选 chip 的选中态要显式声明 `:hover`**（2026-10-07 补）：`.a-chip:hover` 的特异性（0,2,0）高于 `.a-chip--on`（0,1,0），点中后鼠标仍停在按钮上时会把白字压成蓝字——**蓝底蓝字什么都看不见**，且因为选中态是实心底色，比没选中时更刺眼。写法：`.a-chip--on:hover { color: #fff; }`。凡是「hover 改文字色」+「选中改底色」的组合都要补这一条

### 3.9 表单控件（EP 输入框 / 按钮）

- 高度统一 32px：按钮（默认与 small）均 32px，与输入框等高，同一行内不出现高低差；link 型按钮随文字高度，不受此限
- 圆角：按钮 5px、输入框直角 0；按钮文字 12.5px
- 输入框状态只变色不变粗：默认 line 1px 描边 / hover blue-side / focus blue，不加外圈光晕
- placeholder 与禁用态：文字 --dis-text，禁用底 --dis-bg
- EP 组件内部原生元素（input 等）不叠 `:focus-visible` outline——wrapper 描边即焦点指示，避免双框
- **不用原生 `<select>`**（2026-10-07 补）：原生控件的长相由浏览器决定、与本方案无关，在一屏 EP 组件里格外扎眼。统一用 EP `el-select` + `el-option`（停用项照旧在 `label` 后面拼「（已停用）」）。**宽度写在组件上**——EP 不吃 `max-width`
- **flex 列容器的直接子元素默认 `stretch`**（2026-10-07 补）：`.rev` 这类 `display:flex; flex-direction:column` 里，一个单独出现的 `<button>` 会被拉成整行宽。**不该占满一行的直接子元素要显式 `align-self: flex-start`**
- **表单状态按对象缓存，别只存在一个变量里**（2026-10-07 补）：审核页的合成文本是**可手改**的（管理员入库前定稿），预览生成后如果"收起再展开就没了"，等于逼人重写一遍——那是不可接受的数据丢失。做法：`per-bucket` 缓存，收起与切桶时存、回来时还原（**还原后不要再用后端建议值覆盖**），桶 approve / 驳回 / 忽略后清除该桶缓存

### 3.10 上传（`el-upload` 拖拽区，2026-09-26 定）

管理端上传文件一律用 EP 的 `el-upload`（`drag` + `:auto-upload="false"`），**不要手写 `<input type="file">`**——裸 input 的长相由浏览器决定，与本方案无关，在一屏 EP 组件里格外扎眼。

- 拖拽区：1px dashed `--line` 描边 + 8px 圆角（卡片语言）+ 白底，hover 与拖入态描边转 `--blue`、底色转 `--wash`；上传图标 `--dis-text` 40px
- 已选文件行：**32px 高、直角**（与输入框/按钮同一行高语言），字号 12.5px
- 格式与上限写进 `#tip`（11px `--ink-2`），不在别处再抄一遍
- **没选文件时主按钮禁用**（判定权仍在后端，前端只做即时提示）
- `:limit="1"` 时再选文件要**替换**而不是拒绝（`on-exceed` 里 clearFiles + handleStart）——选错文件的第一反应是重选，不是先删；开窗前记得 `clearFiles()`，上次选的不能留下
- ⚠️ **样式覆盖不能挂 `.admin-root` 前缀**：el-dialog 会 teleport 到 body，那条规则够不着，要挂 `:root` 或用组件自身的类（见 `element-override.css` 的 `.a-upload`）

### 3.11 证据回放（审核队列 · 代表样本，2026-10-07 定）

**背景**：证据快照过去是 `<pre>` 直接摊 JSON。单条样本约 5KB（`retrieved` 5 条 × 400 字 + `prompt_snippet` ≤2000 + `model_output_raw` ≤2000），一个桶 5 条近 25KB——审不动。

**分区（自上而下，折叠项默认收起）**：**结论行置顶**（verdict 药丸 + 科室 + 置信度 + 引用注号，先知道答了什么再看依据）→ 错位提示（仅异常时）→ 系统召回清单 → 当时的健康档案（压成一行）→ 折叠区（检索用串 / 模型原始输出 / 原始快照）。组件 `views/admin/EvidenceReplay.vue`（词表正名是「证据链回放」），纯函数 `utils/evidenceReplay.js`。

- **不做柱带/条带图**（2026-10-07 真机反馈后删）：「谁被引用」每行的 `已引用` 标已经在说，柱带是同一信息的第二次编码，徒增一层视觉噪音。**一条信息只用一种编码**，除非两种编码服务不同读者
- **点哪条召回就在哪条下面展开正文**（每条独立开合，互不影响）——不把正文挪到整个列表底下，那会让人对不上"这是哪条的内容"；展开的正文与条目共用一条左侧竖线，视觉上是一组
- **`model_cited` 的序号 ↔ `retrieved[].rank` 是展示的连接键**。**缺注号的条目绝不合成序号**（合成出来的号会连错条目）、**也不重排**（后端就是按 rank 1..N 顺序写的）；只要有一条缺注号，整份快照**不做引用比对**（错位提示不出）——连接键不可靠时，宁可不报也不报错
- **错位提示是启发式，文案一律写「值得看一眼」，绝不写「错误」**：模型没引相关度最高的那条未必是问题（本仓库实测过该现象偶发且不复现，假说是小库期噪声）。只报两种情况——一条都没引用（info）、相关度最高的那条没被引用（warn）；**不写第三条「引用的都是靠后的条目」**，注1 被引用时它不可能成立、注1 没被引用时前一条先命中，属死分支。**也不解释成因**——成因未知，写了就是编
- **不复现 `prompt_snippet`**：它是 `retrieved` 的派生视图（同一次循环、每条取前 200 字拼起来），两个都摊等于同一份内容看两遍。要看它就展开「原始快照」
- **召回正文只有 400 字缩写**（快照口径 `CITE_CONTENT_MAX`）：**不能承诺看全文**。分两处写明——清单标题常驻「（正文为 400 字缩写，点条目展开）」，展开某条时给一句「要全文得拿 `chunk_id` 回知识库页查」并**把 `chunk_id` 实际显示出来**（提示里提到的东西，界面上必须找得到，否则这句话没法执行）
- **解析失败降级为原文**：老记录、坏 JSON、空串一律原样展示并标明「不是可解析的证据结构」，不猜结构、不补默认值——审出来的依据不能是编的
- JSON 里的 `null` 一律当「没有」（`toNumber` 统一处理）：直接 `Number(null)` 会得到 `0`，屏幕上就出现「相关度 0.00」这种看着像真数据的假数据
- 部件不另造：`verdict` 用既有的药丸 tag `.a-tag`（admin.css，10px 圆角），不写一个直角方框
- 字阶仍守管理端的 11 / 13 / 13.5，不新造字号

### 3.12 代表样本卡（审核队列，2026-10-07 定）

桶详情里的「代表样本 · 最近 5 条」。**每条样本默认只占一行**，证据、根因、原始数据收在展开里。

- **一行里放什么**：主诉 + **异常标记**（只在有引用错位时出现的 `引用错位` pill）+ 结论摘要（科室 · 置信度 · 引用了哪几条注）+ `证据 ▸`。**不摊开证据**——一屏塞不下 5 份证据 + 桶级回流表单，这是这一页最挤的根源
- **不标「正常」**（2026-10-07 补）：这些记录进桶本身就因为「系统错了」，给它贴一个「正常」标签自相矛盾；而**「没标」本身就是「无异常」**。凡是有默认/正常态标签的地方，先问一句「这个标签说的是好事还是『没坏事』」——后者不该有标签
- **有错位提示的样本排最前**（`Array.prototype.sort` 稳定，同组内保持原顺序）：归因先看异常。**异常要一眼可见、正常要安静**
- 折叠头是**整行可点**的按钮（复位 padding/border/background），不是只让标题可点
- 摘要里的结论与错位判定，**复用 `utils/evidenceReplay.js` 的 `parseEvidence` / `evidenceHint`**，与展开后的证据卡同一套口径——同一判定不许出现两份实现
- 「保存本条根因」按钮跟着根因标签一起收进展开区：它是根因操作，与根因标签同域
- 换桶 / 收起时清空展开状态：留下的 `recordId` 属于上一个桶，留着只是噪音
