# 前端设计方案 —— 患者端「临床纸感」（方案 A）+ 管理端「冷靛控制台」（方案 B）

> 已定稿（方案 A2）。患者端（Vant · 手机）全部页面遵循本方案；管理端遵循文末「管理端 · 冷靛控制台」章节。
> 参考稿：`前端方案/方案A2-临床纸感增强.html`

## 1. 设计定位

患者端是"分诊台纸质单据"的气质：冷静、可信、能说清依据。页面唯一的记忆点是**推荐卡 = 单据**——置信度像印章、判断依据做成脚注。其余一切保持安静。

## 2. 设计令牌

### 2.1 色板（只用这些值）

| 令牌 | 值 | 用途 |
|------|-----|------|
| --paper | #F7F9F8 | 页面底色（冷纸白） |
| --card | #FFFFFF | 卡片底色 |
| --ink | #1C2B28 | 主文字 |
| --ink-2 | #5A6B67 | 次要文字、标签 |
| --line | #DDE5E2 | 分隔线、边框 |
| --teal | #0E7C66 | 主色：用户气泡、主按钮、强调 |
| --teal-deep | #0A5C4C | 主按钮 hover |
| --moss | #4A7C59 | 助手标签、成功态 |
--teal-soft | #CDE3DD | 置信度备选条、浅强调底 |
| --side | #E9EFEC | 会话侧栏底色：比 paper 暗两档，与对话区靠明度差分开 |

> `--side` 只出现在对话页左栏。侧栏内的分隔线不要用 `--line`——它比 `--side` 还亮，画上去等于不存在；侧栏内部一律用 `rgba(28,43,40,.07~.16)`。

主按钮必须实心 teal；备选/次要信息用 line 描边空心；错误提示用 #A94438（同明度域，不引入新色系）。

### 2.2 字体

- 显示/正文：`Noto Serif SC`（衬线，宋体家族兜底）——患者端全局衬线，是气质的来源
- 界面标签（eyebrow、按钮、脚注标签）：`PingFang SC / Microsoft YaHei` 无衬线 + 大字距（letter-spacing .1em–.22em）
- 字阶：结论科室名 24px / 正文 14px / 注释 12.5px / 标签 10.5–11px

### 2.3 形状与间距

- 圆角只用于气泡：用户气泡 `14px 14px 3px 14px`，AI 气泡直排文字无底色；卡片、按钮一律直角（0 圆角）
- 会话区垂直节奏 18px；卡片内边距 16px；脚注区上边框 1px dashed
- 顶栏 = 病历抬头式：标题左、细字距副标题右，底部 1px 实线
- **对话页的顶栏整条不渲染**（2026-09-20 三版定，`.p-chat__topbar` 仅 <768px 出现）：标题归左侧栏抬头、用户区归左侧栏底部，对话区顶上一条横线都不留。手机端没有侧栏可挂，仍保留顶栏（左「会话」、中标题、右昵称与退出）
- 其余页面（如模拟挂号）顶栏照旧；挂号页的顶栏没有 `p-chat__topbar` 类，不受对话页那条规则影响
- 顶栏右侧操作区（`.p-topbar__ops`）：昵称 + 「退 出」文本按钮（`.p-topbar__logout`，line 描边空心，hover 变 #A94438），10.5px 无衬线大字距，触控目标足够点击
- **昵称本身是入口**（顶栏 `.p-topbar__nick` / 侧栏底部 `.p-chat__unick`）：无衬线 10.5px + 大字距 + 下划线虚线，hover 变 teal；点它切到「挂号历史」并打开左侧栏（手机端；桌面侧栏本就常驻）——不是按钮样式，保持抬头式的安静

## 3. 关键部件规范

### 3.1 推荐卡（签名元素，链路 A 结论 + result 事件渲染）

结构自上而下：eyebrow「分 诊 结 论」→ 科室名（大衬线）+ 置信度（teal，右侧）→ 置信度条列表（Top3）→ 结论说明 → 脚注区（1px dashed 上边框 + 「判 断 依 据」标签 + 注1/注2 溯源引用）→ 主按钮「下一步 · 模拟挂号」。

**置信度条列表**（Top3 科室横向概率条，替代原备选科室块）：
- Top1：实心 teal 条 + 科室名加粗 + 百分比 teal 加粗；备选：浅青 #CDE3DD 条 + ink-2 小字
- 条高 5px、直角 0 圆角（保持单据感）；科室名列宽 92px，超出省略
- 数据对应 result 事件的 Top3 推荐科室与置信度，与顶部大科室名的置信度一致

**步进流程条**（推荐卡下方、输入框上方，纸色条 + 1px 上边框）：
- 「① 导诊结论 → ② 模拟挂号 → ③ 确认完成」，细无衬线 11px + 圆圈序号，连接线 1px 实线
- 当前步骤 teal 加粗；进入挂号页后当前态后移，成功页三步全部 done（teal）
- 三步与链路 C 埋点触点一一对应：result_view / sim_register / register_success

- 溯源引用必须显示（chunk 标题），注号对应证据快照的 retrieved 顺序
- **每条引用 = 注号 + 标题 + 证据原文（截断 400 字）**（2026-09-26 改）：标题一行加粗，原文另起一段、左侧 2px `--teal-soft` 细线缩进（与追问气泡同一套语言——它是"引用"，得跟结论正文区分开）。**只列模型真正引用的注**，但正文里出现的每个注号都必须能在依据里查到（见《总体架构与链路设计.md》链路 A 对齐点）。起因：一份期刊 PDF 被切成 8 片、标题全一样，卡片上是一串重复的「一、…的内容」，看着像"标题码"而不像出处
- 置信度由**后端下发为准**（lowConfidence 标志 + 阈值来自 sys_config），前端不写死阈值；模型未给出合法置信度时（confidence 为 null）：头部与 Top3 条一律显示「—」（不显示 0%），并按低置信度样式处理
- 3 轮追问超限出低置信度结论时：置信度文字用 #A94438 并追加"建议进一步咨询医生"

### 3.2 对话页

- **左侧会话栏**（桌面常驻 248px / 手机收成覆盖层，2026-09-20 加；底色 `--side`）：最上头**标识行**（`.p-chat__hd`：logo ＋「智能导诊」＋ 收起按钮，一行）→ 「+ 新 的 咨 询」→ 抬头「我 的 就 诊」+ 次数 + 两个 tab（`全部对话` / `挂号历史`，同一份数据换口径过滤）→ 按天分组的会话条目 → 底部用户区（昵称 + 退出）。条目三个部件：天头 `.p-day`（半透明白）、会话行 `.p-i`（主诉首句超出省略 + 「N 问」+ 时间）、折叠条 `.p-fold`（**某天超过 10 次折成最新 2 条**，「展 开 该 天 全 部 N 次」⇄「收 起 该 天」）
- **侧栏标识**（2026-09-20 三版）：方框里三条由粗到细、由长到短的横线——画的就是推荐卡上那组置信度条，与产品最强的记忆点同源。展开态 20px teal，收起态 18px。SVG 内联，无图片资源
- **选中行 = 白卡片压在侧栏底上**：`.p-i.on` 用 `--card` 实白，天头用半透明白——「压上去」的层次靠这层明度关系才出来，不是靠加边框
- **侧栏可收成精简轨**（2026-09-20 三版，学 DS 网页版）：收起按钮在**侧栏标识行右端**（`.p-chat__foldbtn`，方框带左栏线图标，仅桌面渲染）。收起后侧栏 248px→**127px** 的横向一条：左是**标识**（`.p-chat__railbrand`，它本身就是展开入口），一道分隔线，再是展开图标与 ＋ 图标；轨贴左上角。两态下新会话都可用（展开点大按钮、收起点 ＋ 图标）；状态存 localStorage；宽度 0.2s 过渡
  - **收起宽度写定值 127px，不用 `fit-content`**（2026-09-20 三版踩到）：`fit-content` 不参与 `width` 插值，`transition: width .2s` 会退化成瞬时跳变——实测采样只有 `[248, 127]` 两帧。改定值后实测 13 帧平滑过渡。配 `min-width: fit-content` 兜底（图标增减时轨不挤坏）
  - 收起态**三大件都不许丢功能**：标识可展开、展开图标可展开、**＋ 仍要能开新咨询**——否则收起后患者得先展开侧栏才够得到新建
- **点会话 = 只读回放**：对话区按原顺序铺开那一次会话（用户气泡 / 追问 / 结论卡），**卡片不带挂号按钮**（已挂号的在卡底补一行「就 诊　科室 · 位置」），输入区换成「历 史 记 录 · 只 读」+「开始新的咨询」。**一次会话 = 一次就诊，翻旧账不能往里写字**——想接着问就是新会话
- **回放时右缘出现「问题导航」**（本页的签名部件，2026-09-20 四版改成悬浮面板）：**一行 = 这条会话里患者的一个问题**（不是会话之间的索引——会话之间靠左栏切）。收起时右缘只有一根 2px `--teal-soft` 细把手（**热区是整条右缘，视觉只有那 2px**——细线好点不中，热区必须放大，但视觉不许变粗）；鼠标挨到就滑出面板：220px 白卡片，抬头「用 户 问 题」+「N / 总数」，下面是条目——每条 = **问题正文首句（超出省略）＋ 右缘一根小横杠**，**当前那条文字与横杠变 teal、横杠加长加粗**。**自上而下 = 问题 1 → 最新一问**，与正文同向（正文也是从上往下读，别把最新那条放到最上面）。实时对话时不显示——一次实时对话只有一个问题，做索引是空的
- **面板脱离布局流**（`position:absolute` 贴右缘）：进出回放时中间的正文列一动不动。早先做成 flex 里的一列，书签一出现正文就横移 15px，读一半的内容会跳一下
- **面板自己滚**：`max-height: min(56vh, 318px)`，放不下时内部滚 + 上下 10px 渐隐（滚动条不画）；**滚轮落在面板上先滚面板，滚到头（或本来就放得下）再转给正文**。是否溢出用 `ResizeObserver` 判，不用一次性计算
- **点条目**：正文滚到那一问并居中，**问题行左侧亮一条 2px teal 竖线**；`prefers-reduced-motion` 下滚动改瞬时
- **浮层是全方案唯一允许加阴影的地方**：纸面部件一律直角、细线、无阴影，但这一块是**浮在纸上**的，没阴影就和正文糊在一起
- **触屏没有 hover**：点右缘把手切换面板（`matchMedia('(hover:none)')` 判定）；手机端把手热区加宽到 34px、面板收窄到 186px，免得盖掉半屏正文
- **滚动条落在窗口最右缘，不在「对话框」里**（2026-09-20 四版）：滚动容器 `.p-chat__thread` 是**整幅宽**的，正文靠内边距 `max(32px, calc((100% - 1000px) / 2))` 收成 1000px 居中。早先容器自己就是 1000px 宽，滚动条便缩在对话框的右边缘上，和右侧浮层打架。**`.p-chat__main` 的直接子元素必须在这条规则里列全**——容器一全宽，漏掉的那个（当时是只读条 `.p-chat__lock`）就自己铺满整幅、与相邻区块错位
- **滚动条定宽 12px 并淡化**（`::-webkit-scrollbar`，thumb 用 `border:3px solid transparent` + `background-clip:content-box` 在 12px 轨道里只画中间 6px）：定宽是为了让把手能**精确**停在它左边（宽度不定就只能靠猜），把手 `right: 12px` 正好让开。**不能同时写 `scrollbar-width`**——Chromium 一旦认了那个标准属性，这套伪元素整个失效
- **「＋ 新的咨询」**：撤回放 + 清对话态（下一条消息即新会话）+ 光标落进输入框
- **每轮对话结束自动刷新左侧列表**（新会话 / 提问数 / 挂号状态都靠它），正在对话的那条高亮
- **输入区是一整块「书写区」**（2026-09-20 改，学 DeepSeek 网页版那块输入卡片）：一张 card 底、1px line 描边的矩形，里面**上写字、下排一行**——左边一句「分诊建议，不能替代医生诊断」，右边一个 32px 方形发送按钮（teal 实心，白色向上箭头图标，非文字）；聚焦时**整块**变 teal 描边（`focus-within`），不画内层输入框的边。输入框随内容长高（120px 封顶后自己滚）。**不圆角、不加阴影**——学的是排布，不是皮肤
- AI 回复不带气泡底色（直排文字 + 「分 诊 助 理」moss 小标签），用户消息实心 teal 气泡
- 追问消息与普通回复同款，不加特殊样式；SSE delta 流式渲染逐字填充同一文本节点
- 处置提示（敏感词累计触发的**警告与禁言话术**，SSE `notice`）：**独立一泡** + err 色左侧 3px 描边 + card 底——不能与诊断正文混为一谈。收到 `notice` 时前端另起一泡，并把后续 `delta` 落到**新**气泡（消息提示与结论粘成一段话就再也拆不开了）
- SSE 四态 error：错误以 line 描边块呈现，文案说清原因与下一步（"网络中断，点击重试"），不道歉不模糊
- **空状态 = 接诊单**（不是一句客套话，2026-09-20 定）：eyebrow「分 诊 台」→ 24px 大衬线「说说哪里不舒服」→「说清三件事，分诊会更准」→ 三个**待填单据槽**「部位 / 多久了 / 什么感觉」（虚线底边，**不是按钮**——别让人以为要点）→ 一条示例（teal-soft 左竖线，与追问气泡同一套语言）→ eyebrow「常 见 主 诉」+ 6 个 chip（发热咳嗽 / 肚子疼 / 头疼头晕 / 皮肤起疹 / 心慌胸闷 / 腰背酸痛）
- **空对话时输入框跟着欢迎语一起居中**（2026-09-20 定，学 DeepSeek／豆包）：接诊单 + 输入区当成一整块，在顶栏以下的空白里垂直居中（`.p-chat__main.is-empty` 上用上下 `auto` 外边距——空间不够时它退化成 0，不会把顶部裁掉），同时**不显示步进流程条**（还没有任何步骤）；发出第一条后立刻回到常规排布：输入框贴底、流程条出现。空对话时把输入框孤零零钉在屏幕底部，跟上面的欢迎语隔着几百像素，说不出哪里别扭但就是别扭
- **「+ 新 的 咨 询」在左侧栏标识行之下、抬头之上**，不放底部：会话一多侧栏就长了，底部的按钮够不到（学 DeepSeek 的「开启新对话」）。加号用**半角 `+`**——全角「＋」在该字号下偏大偏靠上，与后面那串大字距的字不齐
- **chip 只填不发**：点一下把主诉填进输入框并聚焦，**不直接发送**——患者还能补一句"还伴着恶心"，也不至于误触烧掉一次模型调用；已有内容则用「，」追加
- **免责那句常驻在输入区里**（左下方、细无衬线小字）——医疗产品该一直看得见，顺带把原来空状态那行独立的免责收掉了
- **一键复制**（2026-09-20 二版，学 DS 消息操作）：用户气泡 / AI 回复 / 追问下方各挂一个 `.p-act__btn`（复制图标 + 文字），**桌面 hover 才浮现**（保持纸面安静）、触屏常显（`@media (hover:none)`）；结论卡是单据，「复 制 结 论」常显（拼纯文本：科室＋置信度＋Top3＋说明＋依据＋免责）。复制成功变对勾 +「已 复 制」，1.5s 复位；`navigator.clipboard` 失败降级 `execCommand`
- **桌面布局是 DS 式**（2026-09-20 二版改，三版补底色）：整页全宽、**侧栏贴浏览器窗口最左**，对话内容在舞台中央收 1000px 单列；**侧栏与对话区之间不画任何边线**——两块纸靠明度差分开（侧栏 `--side` / 对话区 `--paper`），虚线＋竖线夹缝只会把一张纸隔成两间病房。空状态下输入区悬在纸中间时，它的 `border-bottom` 仍要关掉（那条边是给"贴底输入区"收纸口用的）

### 3.3 模拟挂号页（链路 C 三触点）

- 与推荐卡同款单据风格；推荐科室在科室列表中 teal 实心高亮，其余空心
- 选定科室 → 确认按钮实心 teal，按钮文案全程用「确认挂号」；成功页显示 register_success 状态

### 3.4 埋点触点

result_view（推荐卡渲染完成）/ sim_register（选定科室）/ register_success（确认成功）三页面的风格延续本方案，不出现第二种视觉语言。

## 4. 质量底线

- 响应式：375–430px 宽度内布局不破；触控目标 ≥ 44px
- 桌面端适配（≥768px）：患者端保持手机版式不重排，收成一列居中的「病历单」并加左右 1px 细线，文字区块内边距放宽到 32px。**各页宽度**：对话页**整页全宽不居中**——侧栏贴窗口最左，对话内容在舞台中央收 1000px 单列（§3.2，2026-09-20 二版改）；其余页（挂号页等）**1000px** 单列；手机端（<768px）全屏布局不变，一套 CSS 媒体查询实现，不做桌面专用页面
  - **为什么都不再是 720**（2026-09-20 改）：720px 在 1440／1920 屏上两侧各空 360／600px，像一张纸条贴在墙中央。加宽的边界由内边距守住——纸宽了，一行不跟着排长
  - **纸面边界挂在最外层的容器上，不挂各区块**：区块在空状态下会收缩，边界挂在它身上就会断成两截（一张纸缺了半截边，说不出哪里不对但处处别扭）
- 键盘可达：`:focus-visible` 用 teal 2px 描边；`prefers-reduced-motion` 下关闭全部动效
- 文案：动词开头、一句话说清、不道歉；空状态是行动邀请（"说说哪里不舒服，我来帮您分诊"）

# 管理端设计方案 —— 「冷靛控制台」（方案 B3）

> 已定稿（B3，2026-09-19 Element Plus 接入后配色定案）。管理端（Element Plus · PC）全部页面遵循本章节。
> 参考稿：`管理端方案/管理B3-冷靛控制台.html`（看板与配色基准）
> B3 要点：主色向靛收敛（--blue #4468B8）；侧栏三级靛阶（底 --blue-side / 选中 --blue-deep / 主色 --blue）；补齐 EP 状态梯度令牌；coral/moss/err 与患者端同明度域，维持不动。

## 1. 设计定位

管理端是"运营控制台"的气质：信息密度高、数据波动一眼可见、异常状态醒目。核心任务是扫一眼找到待处理的事（审核队列）并看清数据趋势，不做纸质单据风格。

### 2.2 字体与形状

- 全局无衬线 `PingFang SC / Microsoft YaHei`
- 字阶：KPI 数值 15px 加粗 / 面板标题 13.5px / 正文 13px / 标签提示 11px
- 圆角：卡片 8px、按钮 5px、tag 10px（药丸形）；与患者端直角风格区分，无衬线体
- 布局：左侧 212px 蓝色侧栏（可折叠至 60px；brand + nav + 底部用户区）+ 右侧主区（顶栏 + content 24px 28px 内边距，纵向 18px 间距）
- **Element Plus 接入（2026-09-19 定案，B3 色板）**：main.js 全量注册 + `element-override.css` 把 EP 变量映射到本方案色板（primary=blue、success=moss、warning=coral、danger=err、disabled/mask/placeholder 取 --dis-*/--mask、直角 0 圆角、字体 sans）——新页面优先用 EP 组件（表格/分页/下拉/弹窗/消息），不要手写重复部件；EP 弹层 teleport 到 body，主题覆盖必须挂 `:root`（挂 .admin-root 弹层吃不到）

## 3. 布局部件规范

### 3.1 顶栏

- 白底 + 底部 1px 实线；左侧页面标题 + 细字距副标题（区间/口径说明）
- 右侧操作区：主操作按钮（实心 blue）+ 区间切换按钮（描边）；用户信息与退出登录统一在侧栏底部（见 3.2），顶栏不重复放置
- **区间切换只在"区间"有意义的页面出现**（2026-09-26 定）：它原先写死在顶栏、每个管理端页面都挂着，而这些页面上它没有任何作用——点下去毫无反应，却像是能改变数据口径，比假数据更误导。现在只在数据看板渲染（近 7 天 / 近 30 天），状态放**路由 query**（`?days=30`），刷新区间不丢、链接可分享

### 3.2 侧栏

- 蓝色实底（--blue-side），选中项深蓝底（--blue-deep）+ 白字；待办数用 coral 药丸徽标（margin-left:auto）
- hover 项半透明白底过渡
- **可折叠**：品牌区右侧挂 26px 圆形折叠按钮（白底描边、悬出侧栏边缘），在 212px / 60px 间切换（0.18s ease）；折叠态导航显示两字缩写居中 + title 提示完整名称，徽标与品牌文字隐藏
- **底部用户区**：圆形头像（昵称首字，半透明白底）+ 昵称 + 上箭头；点击展开 EP 下拉菜单「退出登录」，退出前 confirm 说清后果（返回登录页），确认后清 Redis 登录态、跳登录页并 toast

### 3.3 KPI 指标卡（看板）

- 四列网格；每卡 = 环形指标（SVG stroke-dasharray，56px）+ 右侧标签/数值/同比
- 正向数据环形与涨跌用 blue，警示指标用 coral（.warn）
- 同比行：↑ 蓝色 / ↓ coral / 持平 ink-2
- **环形弧长必须有含义**（2026-09-20 定）：比率类 = 比率本身；计数类 = 占同类总量的比例（如待审核/全部任务、盲区榜/全部记录）。禁止"数字越大环越满"这种没有口径的画法
- **无样本时数值与环内文字都显示「—」，不显示 0%**：0% 会被读成"全错"，与"还没有数据"是两件事；附注位改用文字说明（如"暂无已确认挂号的记录"）
- 环比只有在两期都有样本时才算：上期为空要说"不可比"，不伪造成一个涨跌数字；文案带样本量（如"↑ 2.1pp 环比 · 样本 42 条"）

### 3.4 图表面板

- 双列网格（1.6fr 1fr）+ 全宽表格区；面板 = 白底 8px 圆角 + 标题栏（1px 底线 + 右侧 hint）
- 柱状趋势：纯 CSS flex 柱（蓝=命中、coral=未命中堆叠），hover 柱透明度变化 + 标签加粗
- **柱高按窗口内最大值归一化、并留 20% 余量**（2026-09-20 定）：真实日量可能远超 100 条，把原始条数直接当百分比会溢出容器；20% 余量留给下方星期标签
- **缺数据的日期要补 0**：按日期轴对齐，不能让柱子错位
- 分布条：名称 + 圆角轨道条 + 右对齐百分比，hover 条微粗
- **无数据不画空图**：图表与分布条在无数据时换成 `.a-empty` 空态文案，并说清"为什么没有"（如"近 7 天还没有已确认挂号的记录""暂无归因数据（审核页标注根因后自动汇总）"）

### 3.5 数据表格

- 表头 11px 灰字浅底（wash）+ 1px 底线；行 hover 浅底色（wash）；行间 1px 线；EP 表格同此（--el-table-header-bg-color: var(--wash)）
- 状态用药丸 tag（wash 底蓝字 / coral 警示 / moss 成功）
- **只读展示表（如看板「最近导诊记录」）用本方案 `.a-table` 手写 + EP 分页**（`el-pagination`，layout 只留 prev/pager/next）；总数写在面板标题栏 hint 里（「共 N 条」），不在分页器上重复显示 total。带筛选/排序/多列操作的业务表（用户管理）直接用 EP 表格
- **空表不渲染表头**，整块换成 `.a-empty` 空态文案
- 操作列：实心（主操作）+ 描边（次要）+ 危险红字（删除），hover 均有过渡
- 点击行可展开子行（浅底）放扩展内容：审核表单（主科室选择、交叉科室多选、回流预览、确认入库/驳回/忽略）+ 根因归因芯片（桶级套用、逐条可改）；已终态桶提供「修正重审」入口

### 3.6 tab 切换

- 面板顶部 tab 行：底边 2px 透明，选中变 blue + 加粗；hover 变 blue

### 3.7 敏感词与违规处置（用户管理页两个 tab）

**敏感词库 tab**

- 顶部「处置规则」面板：统计窗口 / 禁止词警告阈值 / 禁止词禁言阈值 / 观察词警告阈值 / 禁言时长（数值输入 + 范围与默认值提示）+「保存规则」。与词表**同页**——"哪些词算违规"和"触发多少次会怎样"是一件事的两半；规则拉取失败只降级成提示条，不阻断词库维护
- 词表列：词 / 类型 tag（禁止词 coral 警示、观察词 wash 蓝字）/ 累计命中 / 状态 / 操作
- 操作：编辑（描边）、停用（描边）、转禁止词（实心 blue，观察词行）、删除（危险红字，confirm 走逻辑删除）
- 顶部操作：单条添加（实心）、批量导入（描边，上传 txt）、导出备份（描边）

**账号管理 tab**

- 表格上方一句口径提示：窗口长度与三个阈值**从配置读**，不写死数字——写死就意味着改了阈值页面开始撒谎
- 列：用户名 / 昵称 / 角色 / 状态 / **近 N 分钟触发**（禁止 x · 观察 y 两枚 tag，为 0 用 info 弱化）/ **处置**（禁言中用 danger tag 显示"禁言至 HH:mm"；否则"已警告 n 次" warning tag；都没有显示「—」）/ 注册时间 / 操作
- 操作：明细（弹窗：窗口内按词聚合的命中 —— 词/类型/词次/最近命中；+ 处置记录 —— 级别/触发类型/命中÷阈值/窗口/时间）｜解除禁言（仅禁言中的行显示）｜封禁/解封
- **窗口口径与后端同源**：页面上的"近 N 分钟"取自同一份配置，不会出现"页面按 30 分钟统计、后端按 60 分钟判定"

### 3.8 交互规范

- 全部交互 0.18s ease 过渡；`prefers-reduced-motion` 下全部关闭
- 操作反馈统一用底部居中 toast（墨色底白字，2.2s 自动消失）
- 破坏性操作先 confirm，文案说清后果与执行顺序
- 进度条统一 5px 圆角轨道：进行中 blue / 异常 coral / 完成 moss
- **进度条不许撒谎**（2026-09-26 定，用于知识库入库进度）：只显示**真实知道的量**，不把两段耗时差着数量级的阶段拼成一根 0–100% 的条——那样必须拍一个分段比例，而它在任何一份文档上都不会对，症状就是"卡在 60% 不动"，人读成"卡死了"。知识库解析的显示按阶段走：「解析中 37%」（外部服务给的真百分比）→「正在切分」→「写入 38 / 42」（自己的计数）→「已完成」。**不显示任何推算出来的总进度**。
  > 为什么这条重要到要写进规范：进度条几分钟不动，管理员会以为没点上、再点一次——那正是「同一文档同时跑两次入库」的触发条件（白付一次解析费）。**显示真实量是在压制一个真实会发生的误操作。**
  > 同理，解析阶段不可能知道会切出多少片（那是切分的结果），所以「15 / 38 · 解析中」这种显示是编的。**2026-09-26 起知识库页已按本条接通真实接口**（那条假数据连同整页假数据一起清掉了），页面实现见 `KbManage.vue`：`progressOf()` 一个函数决定文案与进度条，`ratio` 为 `null` 就不画条——**不画比画错强**。
- 侧栏页面切换、tab 切换不刷新整页

### 3.9 表单控件（EP 输入框 / 按钮）

- 高度统一 32px：按钮（默认与 small）均 32px，与输入框等高，同一行内不出现高低差；link 型按钮随文字高度，不受此限
- 圆角：按钮 5px、输入框直角 0；按钮文字 12.5px
- 输入框状态只变色不变粗：默认 line 1px 描边 / hover blue-side / focus blue，不加外圈光晕
- placeholder 与禁用态：文字 --dis-text，禁用底 --dis-bg
- EP 组件内部原生元素（input 等）不叠 `:focus-visible` outline——wrapper 描边即焦点指示，避免双框

### 3.10 上传（`el-upload` 拖拽区，2026-09-26 定）

管理端上传文件一律用 EP 的 `el-upload`（`drag` + `:auto-upload="false"`），**不要手写 `<input type="file">`**——裸 input 的长相由浏览器决定，与本方案无关，在一屏 EP 组件里格外扎眼。

- 拖拽区：1px dashed `--line` 描边 + 8px 圆角（卡片语言）+ 白底，hover 与拖入态描边转 `--blue`、底色转 `--wash`；上传图标 `--dis-text` 40px
- 已选文件行：**32px 高、直角**（与输入框/按钮同一行高语言），字号 12.5px
- 格式与上限写进 `#tip`（11px `--ink-2`），不在别处再抄一遍
- **没选文件时主按钮禁用**（判定权仍在后端，前端只做即时提示）
- `:limit="1"` 时再选文件要**替换**而不是拒绝（`on-exceed` 里 clearFiles + handleStart）——选错文件的第一反应是重选，不是先删；开窗前记得 `clearFiles()`，上次选的不能留下
- ⚠️ **样式覆盖不能挂 `.admin-root` 前缀**：el-dialog 会 teleport 到 body，那条规则够不着，要挂 `:root` 或用组件自身的类（见 `element-override.css` 的 `.a-upload`）
