### 口径说明

- **g3 的档案值「过敏」是探针构造值**：种子语料的咳嗽鉴别正文里出现「过敏因素」，词面规则据此命中；
  真实患者填「青霉素」时，只有召回正文真的提到青霉素才会报硬警报。这个值只用于验证规则链路，不代表产品文案。
- **g2 的 `memory: null` 是正常的**：本轮背景未命中，快照仍写节点（显式 null），回放侧按可选节点解析；
  g4 证明了有命中时节点写的是 `{text,hits,query,threshold}` 结构。
- 非结论轮（追问/资料回答）不下发结构化警报，这一点由单元测试覆盖，真机探针只验结论轮。

## 4. 本地知识库数据说明（影响 g1/g4）

探针第一次跑 g 时后端日志报「候选科室 0 个（无切片剔除 13）」。核对发现本机 MySQL 的
`kb_doc` / `kb_chunk` 全部是 `deleted=1`（此前被清理过），而 pgvector `kb_chunk_vec` 仍保留 12 条
切片正文副本。为让结论轮跑通，按以下方式**只恢复演示语料、不改历史记录**：

1. 从 `kb_chunk_vec` 读出 12 条切片的 `chunk_id/doc_id/title/content`；
2. 映射到当前 7 个科室（心血管/呼吸/消化/骨科/神经/耳鼻喉/皮肤）的现存 `dept_id`；
3. 以原 `chunk_id/doc_id` 补写 `kb_chunk` / `kb_doc`（`deleted=0`，`chunk_type=text`）。

没有改科室行、没有改任何 `guide_record`、没有删除数据。这是本地环境的数据修复，不属于产品代码变更。

## 5. 复现步骤

```bash
# 1) 存量库迁移（只需一次；可重复执行）
mysql -uroot -p --default-character-set=utf8mb4 < scripts/sql/memory_migration.sql
PGVECTOR_URL=jdbc:postgresql://<host>:5432/guide_vec PGVECTOR_USER=postgres \
  PGVECTOR_PASSWORD=<pwd> java -cp <postgresql-jdbc.jar> scripts/sql/PgExec.java \
  scripts/sql/pgvector_memory_migration.sql

# 2) 启动后端与前端
cd backend && mvn -o -B -DskipTests install
mvn -o -pl admin spring-boot:run
cd frontend && npx vite --port 5173

# 3) 跑探针（MYSQL_PWD 只用于直查证据快照）
cd frontend && MYSQL_PWD=<pwd> node e2e_memory_probe.cjs
```

失败时脚本会把截图写到 `frontend/e2e-shots/<步骤>.png`，完整逐条结果写到
`frontend/e2e-shots/probe-result.json`，并按步骤名打印可复现步骤。
