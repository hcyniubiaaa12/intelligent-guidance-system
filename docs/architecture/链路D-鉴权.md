# 链路 D：鉴权链路

> 本文是《总体架构与链路设计.md》（仓库根，**总册**）的分册之一。全局约定——分层视图与设计原则、模块职责边界与依赖方向、部署形态、已定参数汇总——都在总册；动本册前先读总册 §1 / §3 / §5。

### 链路 D：鉴权链路

```
患者/管理员 → 登录(POST /api/auth/login) → JWT 签发(含角色)
    → 前端存储(Axios 拦截器携带 Authorization)
    → JwtAuthFilter 校验 → SecurityContext 注入
    → 接口鉴权：/api/admin/** 仅 ROLE_ADMIN；/api/chat/**、/api/guide/** 仅登录
```

**对齐点**：`/api/auth/register` 默认患者角色，注册成功即登录（后端直接签发 token）；管理员账号由初始化脚本/管理端人工创建；未登录/登录过期返回 401（前端清登录态跳登录），无权限访问受限接口返回 403（不跳转，仅提示）；前端 HTTP 层统一解包 Result——业务码 2000 同样按未登录兜底跳登录（**公开路由且确实是游客才不跳；持有 token 却在公开路由上被 401 = 登录过期，照常清态跳登录**，见下节「游客访问」），`code!==200` 统一 reject 携带 message 供页面展示。

**登录时只校验封禁，不看禁言**：`status=banned` → 拒绝登录；`mute_until` 未到期仍可登录（能看历史、能重新描述症状被驳回），限制只作用在"发言"这一步（入口校验先判禁言，见 `docs/architecture/链路A-导诊对话.md` §6.6）。两者混用会让"禁言"变成"封号"，且封禁语义被稀释（管理端分不清谁封的）。

### 游客访问：前端放开，后端不放宽

**边界**：未登录可访问**对话页**（`/`，路由 `meta.public`），导诊与就诊记录仍要求登录。

- 游客能看见并操作的是**纯前端、零请求**的那一屏：接诊卡、人体图选部位、快捷词、输入框。他能在输入框里写字、能选部位，**按发送那一刻**才被告知需要登录。
- **`/register`（模拟挂号）、`/admin/**` 仍然要求登录**：前者缺 `recordId` 时只能渲染错误态，放开没有意义；后者鉴权完全不变。`/preview`（人体图部件预览页）维持原有的 `public`。

**后端鉴权规则未放宽——一条都没有。** `permitAll` 仍然是 `/api/auth/login`、`/api/auth/register`、`/error` 与 dispatcher 规则；`/api/chat/**`、`/api/records/**`、`/api/profile/**`、`/api/track/**` 继续 `authenticated()`，游客调用一律 401 + 业务码 2000。游客路径靠**前端不发请求 + 不渲染依赖登录的块**实现：`SideRail` 在游客态直接返回、不调会话列表接口。就诊记录是个人数据，为一个前端展示态去动服务端鉴权就是把安全边界让给 UI。

> **「没有记录」与「取不到」是两个状态**：游客态的左栏写「登录后查看就诊记录」，不是「还没有就诊记录」——后者等于替他说"你从没来过"。同一条判据也决定了"请求压根不发"，而不是"发了被 401 兜回来"。

**401 口径只有一处：`frontend/src/utils/authRedirect.js` 的 `onUnauthorized()`。** `api/http.js`（JSON 接口）与 `utils/sse.js`（对话流）都调它，**各自不留本地副本**——两份副本曾经判据不同（`sse.js` 那份不看 `meta.public`），后果是公开路由上游客一发消息就被强制踹去登录页。判据是**「公开路由 **且** 确实是游客（`isGuest`）」**：

- 公开路由 + 游客 ⇒ **不跳转、不碰 store**（游客其实走不到这里——发送闸就把他拦下了，这条是兜底）；错误照旧 reject / 走 `onError`，**任何错误都不许被吞掉**；
- 其余情形（持有 token 却在公开路由上被 401 = **登录过期**；或不在公开路由上）⇒ 清 user store 与 chat store，跳 `/login?redirect=<当前 fullPath>`（已停在 `/login` 时不重复 push）。

> **判据不是「当前路由是否 public」一条**——只看路由会把登录过期一并放过：`/` 是公开路由，过期用户在那儿发消息被 401 后既不清 token 也不跳登录页，界面维持着"已登录"的假象、每次操作都失败、且没有出路。游客与过期的分界是**手里有没有 token**，不是路由。

**这两条路径的可观察行为不同，且必须不同**：

| 场景 | 能否走到 401 | 结果 |
|---|---|---|
| 游客（无 token） | 走不到——发送在 `Chat.vue` 的 `send()` 入口就被拦住，请求根本不发 | 就地提示 + 焦点交给「去登录」，**URL 不变** |
| 登录过期（token 失效/改坏） | 能——请求真的发出去了，后端回 401 | 清态并跳 `/login?redirect=…` |

游客态若也跳登录，等于把我们自己请进来的人再踹出去。

**唯一的例外：登出接口自己处置 401。** `POST /api/auth/logout` 不在后端 `permitAll` 里，token 已失效时它**必然**返回 401——而那正是最该清干净的情况。若让拦截器照常接管，人会因为"登出"这个动作被踹去登录页，与「退出登录后留在游客态」直接打架。做法是请求带 `skipAuthRedirect: true`（`api/auth.js` 的 `logout()`），拦截器据此跳过 401 处置，由 `Chat.vue` 的 `onLogout()` 在 `finally` 里照常清态。

> **不能改成"先切本地态再调接口"**：那样请求不再带 `Authorization`，后端按 tokenId 删 Redis 登录态那一步就真删不掉了——表面上退出了，服务端那份登录态却还活着，直到自然过期。这个改动踩过，别再踩回去。
