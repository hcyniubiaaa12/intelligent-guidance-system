# 链路 D：鉴权链路

> 本文是《总体架构与链路设计.md》（仓库根，**总册**）的分册之一。全局约定——分层视图与设计原则、模块职责边界与依赖方向、部署形态、已定参数汇总——都在总册；动本册前先读总册 §1 / §3 / §5。

### 链路 D：鉴权链路

```
患者/管理员 → 登录(POST /api/auth/login) → JWT 签发(含角色)
    → 前端存储(Axios 拦截器携带 Authorization)
    → JwtAuthFilter 校验 → SecurityContext 注入
    → 接口鉴权：/api/admin/** 仅 ROLE_ADMIN；/api/chat/**、/api/guide/** 仅登录
```

**对齐点**：`/api/auth/register` 默认患者角色，注册成功即登录（后端直接签发 token）；管理员账号由初始化脚本/管理端人工创建；未登录/登录过期返回 401（前端清登录态跳登录），无权限访问受限接口返回 403（不跳转，仅提示）；前端 HTTP 层统一解包 Result——业务码 2000 同样按未登录兜底跳登录，`code!==200` 统一 reject 携带 message 供页面展示。

**登录时只校验封禁，不看禁言**：`status=banned` → 拒绝登录；`mute_until` 未到期仍可登录（能看历史、能重新描述症状被驳回），限制只作用在"发言"这一步（入口校验先判禁言，见 `docs/architecture/链路A-导诊对话.md` §6.6）。两者混用会让"禁言"变成"封号"，且封禁语义被稀释（管理端分不清谁封的）。
