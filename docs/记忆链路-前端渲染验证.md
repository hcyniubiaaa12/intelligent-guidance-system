### 1.3 真实记录样本（全库既有的证据快照，可直接对照）

> 取自另一条测试记录（`guide_record.evidence`），用来确认「告警长什么样、快照结构是什么」。
> 它同时命中了一条**硬警报**和一条**相关提醒**——两者可以并存（上限 3 条，谁先来谁占名额）。

```json
"alerts": [
  {"text": "与您的过敏史「过敏」相关：知识片段提到过敏，请务必向医生说明过敏史。",
   "level": "hard", "anchor": "field:allergy", "source": "rule", "memoryId": null},
  {"text": "与您提到的「2型糖尿病」相关",
   "level": "advisory", "anchor": "memory:2121559347775066114",
   "source": "memory", "memoryId": "2121559347775066114"}
]
```

```json
"memory": {
  "hits": [{"id":"2121559347775066114","key":"慢病","type":"background_health",
            "score":0.708,"value":"2型糖尿病"}],
  "text": "\n\n【长期记忆】\n- 患者长期背景：2型糖尿病\n- 患者偏好：讲慢一点",
  "query": "我有2型糖尿病，最近咳嗽两周了，夜里干咳，嗓子痒，想看看该去哪个科",
  "threshold": 0.7
}
```

**这张快照同时证明了三件事**：① 背景确实被召回并注入（`hits` 非空、`text` 里有「患者长期背景」）；
② 偏好是**全量注入**（`text` 里有「患者偏好：讲慢一点」）；③ 告警的两种级别与锚点格式。
`anchor` 的 `memory:<id>` 指回具体记忆条目，`field:allergy` 指回档案字段——前端不重新计算，只渲染。

## 3. 用例

### T1 · 「我记住的」列表渲染

**操作**：点左栏底部用户卡的「健 康 档 案」→ 点左栏书签「它记住的」。

**期望**：
- 分组标题「偏好」「长期背景」，配额分别显示 `3 / 5`、`4 / 10`；
- 7 条记忆全部出现，**一条两行**：第一行「键 值 ⋯⋯ 观察时间」，第二行原话出处；
- 偏好三条按观察时间倒序：`讲话快一点` → `讲简短一点` → `讲话快点`；
- 鼠标移到某一条上，「修改 / 删除」浮现、右端时间淡出（触屏常显）；
- **这一页没有保存按钮**——记忆的改/删是即时生效的；保存条只属于「我填写的」那一页。

**断言位置**：`frontend/src/components/patient/MemorySection.vue`（`.p-mem__item` / `.p-mem__row` / `.p-mem__quote` / `.p-mem__acts` / `.p-hp__bt` / `.p-mem__quota`）。

### T2 · 偏好真的进了提示词

**操作**：新开一次咨询，随便问一句（先看日志，不必等出结论）。

**期望**：后端日志出现

```
进入检索：…｜记忆偏好 3 条（背景召回 开）…
```

> 这说明三条偏好被**全量注入**。回答应该「短、快」——但这是主观感受，**以此条日志为判定依据**。
> 依据：`MemoryInjectionService.loadPreferences` 只取 `status=active`；关闭自动记忆时这里会变成 `记忆偏好 0 条`。

### T3 · 稳定背景召回 → 相关提醒（advisory）

**操作**：新开咨询，发送：

```
我有糖尿病，最近总是头晕、手脚发麻，已经一周了
```

**期望**：
1. 出结论卡（推荐科室，通常是神经内科）；
2. 卡片**顶部**出现一条浅青底提醒（不是危险色）：

```
与您提到的「糖尿病」相关
```

3. 去重按**文案**：同一条背景被两条片段命中只出一条；但如果召回同时命中「糖尿病」和「2型糖尿病」两条背景，
   **会各出一条**（值不同、文案就不同），最多占满 3 个名额。看到两条同义提醒是当前口径，不是重复渲染。

**断言**：
- DOM：`.p-card__alerts` 下有 `.p-card__alert--advisory`；
- 颜色：主色（`--leaf` 系），**不是** `--alert` 红；
- 数据库：本轮 `guide_record.evidence` 的 `memory.hits` 非空。

> **为什么必须带「糖尿病」三个字**：背景召回有**词面第二路**（完整子串 / 足够长的公共子串），
> 这是当前最稳的命中方式。只说「头晕」不保证召回。

### T4 · 档案硬警报（hard）

**操作**：新开咨询，发送：

```
我身上起了疹子，很痒，已经三天了
```

**期望**：卡片顶部出现**危险色**提醒，文案形如

```
与您的过敏史「皮肤过敏」相关：知识片段提到……，请务必向医生说明过敏史。
```

> 方括号里取**命中片段里出现的那个档案值**：命中「皮肤」时显示「皮肤过敏」，命中「荨麻疹」时显示「荨麻疹」。
> 词面子串匹配（值 ≥2 字），所以看到「皮肤过敏」或「皮肤」都算正常。

**断言**：
- DOM：`.p-card__alert--hard`；
- 颜色：`--alert` 红字 + `--alert-soft` 底；
- 数据库：`evidence.alerts[].source = "rule"`。

> **名额规则**：硬警报**先占**（上限 3 条），占满时相关提醒整体丢弃。
> 所以 T3 与 T4 要分开跑；同一条消息既命中过敏又召回背景时，可能只看到硬警报。
> 若这条消息没触发硬警报，换「我最近老是咳嗽，有痰，一周了」——种子语料的咳嗽鉴别正文里含「过敏因素」。

### T5 · 结论卡的「已参考您的健康档案」行

**期望**：结论卡在「判断依据」之后、陪伴带之前，出现一行杏色背景的文字：

```
已参考您的健康档案：男、2005 年出生、过敏：皮肤过敏、荨麻疹
```

**断言**：`.p-card__profile`；数据来自后端 `result.profileText`，**不是模型输出**。

### T6 · 关闭自动记忆（验证「只停记忆、不停档案」）

**操作**：「我记住的」标题右侧的「自动记忆」开关关掉 → 重新发 T3 的消息。

**期望**：
- 卡片顶部**没有** `advisory` 提醒；
- **硬警报仍在**（T4 的消息仍会出 `hard`）；
- **档案行仍在**（`已参考您的健康档案：…`）；
- 「我记住的」每条后面多一句「已暂停 · 不再影响回答」，顶部出现暂停说明。

**断言**：`.p-mem__paused`、`.p-mem__item` 上的暂停标记；后端日志 `记忆偏好 0 条`。

### T7 · 证据快照（只写不读，回放读它）

**操作**：跑完 T3 / T4 后查最近一条导诊记录。

```sql
USE guide;
SELECT id, rec_dept_id, confidence, low_confidence,
       JSON_EXTRACT(evidence, '$.memory')  AS memory_node,
       JSON_EXTRACT(evidence, '$.alerts')  AS alerts_node
  FROM guide_record
 WHERE session_id IN (SELECT id FROM chat_session WHERE user_id='2121568874666844161')
 ORDER BY created_at DESC LIMIT 3;
```

**期望**：
- `memory_node` 是 `{text, hits[], query, threshold}`；本轮无命中时为 `null`（**节点在、值为 null**）；
- `alerts_node` 是数组；无警报时是 `[]`（「没有发生」与「发生了但为空」是两件事）。

## 5. 排错

| 现象 | 先看哪里 |
|---|---|
| 卡顶什么告警都没有 | 后端日志「结论警报：规则 x 条、记忆提醒 y 条…合并下发 z 条」——看是不是被名额占满或根本没命中 |
| 有提醒但指不回记忆 | 日志「背景提醒缺少记忆 id 或内容，已丢弃」——`memoryId` 为空，提醒必须能指回条目 |
| 背景没召回 | 消息里是否含背景值（词面第二路）；再看 `记忆召回` 相关日志与 `memory.background.recall.threshold` |
| 偏好没生效 | 查 `user_memory` 是否 `status=active`；再看日志 `记忆偏好 N 条` |
| 「我记住的」是空的 | 浮层左栏的三枚书签：我填写的 / 它记住的 / 待确认；先确认是不是还停在第一页（「它记住的」有数量徽标时点进去看） |
